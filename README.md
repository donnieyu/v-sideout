# SIDEOUT / 사이드아웃

뉴배동·히어로즈 예시 모임의 주간 신청·후보 접수·수동 팀 편성 시제품. 실제 계정 운영 전, 샘플 모임에서 핵심 흐름을 검토하는 1차 구현이다.

## 현재 구현

- 회원 화면: 운동 목록·달력, 참석·불참, 상한 도달/마감 이후 후보, 공개된 팀·명단, 본인 신청 기록.
- 운영진 화면: 회차·모집 설정, 시간순 신청 명단, 수동 팀 배정과 포지션, 서버 저장, 공개본 관리.
- 신입·임시 게스트는 별도 ‘함께 참여하는 인원’. 마스터·회장만 선택적 팀 배정 및 전체 회원 대리 추가.
- 공지·이벤트·이야기 게시글, 고정, 댓글.
- 서버 저장: D1에 샘플 모임 상태와 revision을 저장하며 낙관적 잠금으로 동시 덮어쓰기를 막는다.

## 현재 경계

오른쪽 상단 역할 전환은 샘플 데이터를 확인하기 위한 개발 도구다. 이 값을 실제 인증이나 권한 증명으로 사용하면 안 된다. 사이트는 소유자 전용 비공개로 배포하며 실제 개인정보를 넣지 않는다. 회원용 응답은 운영 정보가 제거된 별도 projection이다.

계정 생성·로그인·운영진 지정·여러 모임 등록은 후속 단계. 그때 실제 인증된 계정에서 모임별 권한을 결정하고, 관계형 테이블로 회원·접수·편성·공개 이력을 분리한다. 현재 단일 샘플 workspace 저장 구조를 실제 다중 모임 구현으로 간주하지 않는다.

빠른 무작위 배치, 객관적 평가/비교 투표, 출석 통계는 미구현이다. 교대 순서 관리는 범위 밖이며 현장에서 결정한다. 날짜·장소·회원은 모두 샘플이다.

## 실행·검증

- `npm run dev`: 개발 화면. 사용 가능한 포트가 출력된다.
- `npx tsc --noEmit`: 타입 확인.
- `node tests/domain.mjs`: 신청/후보/권한/공개/게스트/편성의 도메인 검사.
- `npm run build`: Worker 빌드.
- D1 migration은 `drizzle/`에 있다. 로컬 적용은 초기 한 번만 실행한다.

관련 계획과 화면 설계는 상위 `docs/PRODUCT_PLAN.md`, `docs/SCREEN_DESIGN.md`를 참고한다.

## 화면 개편

접이식 사이드바·공통 프로필 수정, 두 모임 타일·마감 D-day, 0~18명 바, 마스터의 모임별 다음 회차 생성, 세로 코트의 드래그/검색 배치를 제공한다. `app/team-board.tsx`가 코트 편성 화면이다. 두 샘플 모임은 서로 다른 D1 workspace 행을 사용하고 계정 프로필은 별도 공통 행에 저장한다.

기존 데이터는 `upgradeWorkspace`로 비파괴 변환한다. 스키마 SQL은 변경하지 않으며, 기존 신청·명단·공개 이력은 유지한다. 운영 설정의 기존 폼은 유지했다. 도메인 검사는 25개다.
