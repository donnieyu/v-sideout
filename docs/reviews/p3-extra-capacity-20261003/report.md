# 추가 선수 자리 수 조정 — 구현 및 검증

2026-10-03 · promotion-p1 · 로컬 구현. 커밋·원격 배포 없음.

## 적용 규칙

- 팀당 기본 코트는 6자리다.
- 기본 추가 자리 수는 팀마다 `max(0, ceil(신청자 수 / 팀 수) - 6)`개다.
- 18명/3팀은 추가 타일 없이 `＋ 추가 선수 자리` 버튼만 보인다.
- 19~21명/3팀은 팀마다 1개, 22~24명/3팀은 팀마다 2개다.
- 24명/4팀은 기본 추가 자리가 없고, 25~28명/4팀은 팀마다 1개다.
- 미배정 인원 대신 전체 신청자 수를 사용한다. 대기자·미신청 회원은 기본 자리 수를 늘리지 않는다.
- 첫 추가 자리는 라이트 2이고, 이후는 포지션 제한 없는 추가 자리다.
- 신청 인원·팀 수 변경 시 배정된 자리와 수동 추가한 자리는 보존한다. 불필요해진 자동 빈 자리만 정리한다.
- 저장 시 수동 빈 자리는 정리하고, 신청 인원 수용에 필요한 기본 자리는 다시 유지한다. 기존 저장 API에는 배정 선수만 전달한다.
- 필요한 최소 추가 자리보다 더 많이 존재하는 빈 자리만 삭제할 수 있다. 선수 배정 해제와 자리 삭제는 구분한다.
- 미리보기·연속 배정·다음 빈 자리 탐색·자동배치는 같은 실제 자리 목록을 사용한다.

## 변경 파일

- `web/components/sideout/allocation/position-board-model.ts`: 필요 용량 계산, 수동/자동 자리 구분, 정리·삭제 조건.
- `web/components/sideout/allocation/allocation-ab-model.ts`: 상태 정규화와 일반 추가 자리 자동배치.
- `web/components/sideout/allocation/session-allocation.tsx`: 신청자 수 기반 초기화 및 변경 반영, 미리보기.
- `web/components/sideout/allocation/continuous-allocation.tsx`: 팀마다 다른 추가 자리 구성 및 동일 삭제 조건.
- `web/components/sideout/allocation/session-allocation.css`: 추가 자리 없는 팀의 버튼 여백 축소.
- `web/lib/sideout/allocation-adapter.ts`: 기존 저장 배정의 추가 자리 보존.

- SIDEOUT 테스트 214개, 회원 UI 테스트 4개: 총 218개 통과.
- TypeScript 검사·프로덕션 빌드·git diff --check 통과.

- 실제 로컬 API + Chrome 390×844에서 별도 검증 일정으로 확인:
  1. 18명/3팀: 추가 타일·추가 인원 제목 없음.
  2. B팀 수동 추가 → 해당 배정 자리 이동 → 미리보기 → 빈 자리 삭제.
  3. 18명 자동배치·저장 후 상세 화면과 저장 원본의 선수/자리/포지션 일치.
  4. 28명/3팀: 12개 추가 자리, 4팀 전환 후 4개 추가 자리.
  5. 28명/4팀 자동배치·저장 후 상세 화면 28명 및 팀 원본 일치.
  6. 공개 후 초안 변경 시 운영진 상세는 최신 저장본, 공개본은 이전 공개 원본 유지.
