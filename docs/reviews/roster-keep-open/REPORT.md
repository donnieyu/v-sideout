# 명단 모달 연속 취소 수정

2026-10-06 · 실제 앱 promotion-p1

원인: 참가 취소 성공 시 `roster:` 복원 캐시를 삭제했다. 브라우저 confirm 이후 focus로 인증을 재확인하여 컴포넌트가 재생성되면, 요청 완료 당시의 열린 모달 상태가 사라져 닫힌 상태로 돌아갔다. 기존 단독 컴포넌트 테스트는 이 타이밍을 다루지 않았다.

수정: 참가 추가/취소 성공 후 열려 있는 모달의 복원 상태를 유지한다. 명단 갱신 알림으로 서버의 새 명단과 revision을 조회한다. 명시적으로 닫을 때만 캐시를 즉시 제거하며, 이미 닫은 모달을 지연 응답이 다시 열지 않도록 캐시가 존재할 때만 갱신한다. 확인창, 권한, 공개 후 취소 제한은 변경하지 않았다.

검증:
- 회귀 테스트는 수정 전 실패 / 수정 후 통과.
- 취소 요청 중 인증 재검증에 의한 실제 컴포넌트 재생성과 이후 두 번째 취소를 재현. 연속 쓰기에 revision 2, 3 사용 확인.
- SIDEOUT 전체 258개 통과, 타입 검사/빌드 통과.
- 별도 로컬 시험 일정에서 두 명을 실제 서버 API로 연속 취소. 매번 모달 유지, 최종 신청자 0명, 명시적 닫기 후 인증 갱신에도 재오픈하지 않음 확인.
- 기존 사용자 연습 일정은 전후 데이터 동일. 새 28명 사용자 일정도 변경하지 않음.
- 실제 iPhone 검증은 별도 미실시.
