# P3-3 실제 팀편성 편집 연결 — 2026-10-03

## 결과와 범위
승인 목업 보존본의 연속 배정·코트/행 미리보기·팀/추가 자리 조작을 `/session/:id/teams/edit`에 이식했다. 인증된 마스터와 해당 모임 운영자만 실제 API로 읽고 저장·공개한다. 샘플 회원/역할 스위치와 목업 저장소는 이식하지 않았다. 상세보기의 기존 명단/팀 표는 유지했다. 전체 목업 승격 완료가 아니라 P3-3 편집 연결 단계다.

- 편집 진입은 미리보기. 선택한 자리와 배정 화면을 왕복한다. 이름은 선택, X는 배정 해제. 후보는 신청자 우선, 주/부/다른 포지션으로 나누되 미배정 신청자 전원을 제공한다.
- 실제 주·부 포지션을 기반으로 자동 배치. 기존 배정 유지, 신청자→대기자, 미신청 회원/미등록 포지션/비활성 회원은 자동 배치 제외.
- 저장 후 화면·선택 유지. 재시도는 동일 명령 ID. 실패/충돌은 입력 보존. 공개는 3~4팀, 빈 팀 없음, 모든 신청자 배정 및 확인 필수. 서버도 같은 정책을 검사한다.
- 공개 후 추가 신청·취소 금지와 초안/공개본 분리는 P3-2 정책을 유지한다.
- 같은 계정의 탭 복귀 재인증에는 입력 복원, 다른 계정으로 바뀌면 캐시 폐기.

## 인수와 데이터
사용자가 인증 담당 채팅에 인수 요청을 승인했다. 인증 담당의 `3c2c018` / `docs/reviews/MEMBER_POSITION_PROFILE_P3_HANDOFF_2026-10-03.md`에 있는 명시적 동의에 따라 포지션 조회 계약과 테이블만 인수했다. 원본 스키마 출처는 `deae058`. 가입·승인·발송 모듈 전체를 가져오지 않았다.

P3 소유 새 migration `web/drizzle/0003_milky_night_thrasher.sql`을 생성했고 로컬 합성 D1에 적용했다. 실제 회원 원본/원격 D1 변경은 없다. 프로필 조회는 권한과 기존 후보 필터 이후 회원 ID로 한정한다. 없는 행은 null, S/S도 허용, 잘못된 코드는 503으로 거절한다. 일반 상세/공개 응답에는 개인 선호 포지션을 추가하지 않는다.

추후 인증 브랜치 통합 시 양쪽 0003/0004와 journal/snapshot의 계보 및 중복 CREATE TABLE을 반드시 조정해야 한다. 현재 P3 번호를 원격에 독립 적용하면 안 된다.

## 발견 및 보완
1. 승인 원본 CSS의 370px 최소 폭 때문에 390px에서 C팀이 일부 잘렸다. 334px로 조정해 390px에서 세 팀이 함께 보인다. 320px/4팀에서는 터치 영역을 줄이지 않고 내부 가로 스크롤하며 현재 선택을 자동 노출한다.
2. 자동 배치가 주포지션 대기자를 부포지션 신청자보다 먼저 채웠다. 신청자 우선 테스트 실패를 확인한 뒤 상태 우선 순서로 수정했다.
3. 독립 검토의 P2: 저장 도중 부모 새로고침으로 편집 remount 가능. 저장/조회에 공통 잠금을 두고 새로고침과 편집 동시 실행을 차단했다. 지연 POST 테스트 RED→GREEN.
4. 독립 검토의 P2: 비활성 회원이 차지한 자리가 빈자리처럼 보임. 기존 배정의 신원을 표시용으로 유지하고 비활성 표기/해제를 제공한다. 후보·자동배치에는 제외한다. API/UI 테스트 RED→GREEN.
5. GET 명단 정산 이후 모임 권한·일정 상태 재확인으로 조회 중 변경 경계를 보완했다.

## 검증
- SIDEOUT 198 + 회원 UI 4 = 202개 자동 테스트 통과. 어댑터 round-trip, 승인 범위, 실제 SQLite 저장, 주·부 포지션 조회, 잘못된 프로필, 저장/공개·재시도·계정 복귀·지연 저장·비활성 배정 포함.
- 타입 검사와 production build 실행 기록 별첨. 독립 검토자는 P3-3 새 파일과 의존 경계를 읽고 관련 테스트를 직접 실행했다. 발견 2건을 한 번의 보완 단계에서 수정했으며, 독립 재검토까지 수행한 것으로 주장하지 않는다.
- 실제 로그인 및 로컬 D1 브라우저: 상세→미리보기→수동 배정→저장 후 유지→공개 취소(쓰기 없음)→확인→새로고침 보존. JS 오류 없음. 개인 S/S 프로필은 편집 응답에만 확인.
- 390px: 배치판 clientWidth/scrollWidth 둘 다 340px. 320px: 문서 가로 넘침 없음, 선택된 C팀 내부 스크롤 노출, 선수풀 높이 281px. 1280px: 문서 넘침 없음, 선수풀 386px.
- 실제 iPhone 이번 변경 재검사는 아직 하지 않았다. 브라우저 viewport 검증을 실기기 검증으로 대체해서 기록하지 않는다.
- 디자인 탐지 1회 결과 빈 목록. 이것만으로 접근성 전체 통과를 주장하지 않는다.

## 남은 범위
- 기존 회원의 주·부 포지션 등록/수정 UI와 인증 승인 기능 통합은 별도다. 미등록 회원도 코트 기본 자리·라이트2에 수동 배정 가능하지만 임의 추가 자리는 주포지션 등록이 필요하다.
- 경기 순서 기본 자동 생성은 저장/공개 서버에 연결됨. 별도 경기 순서 수정 페이지, 신입 경기 토글/대진/드래그 저장은 다음 P3-4다.
- 실기기 재확인, 인증 브랜치 통합 migration 정리, 최종 전체 권한/목업 대응 검수 및 배포는 남았다.
