# 팀 순서 변경 검토

팀 순서 변경은 이 작업에서 구현하지 않았다. 현재 실제 앱의 배정표·상세 팀편성은 `LineupRecord.teams` 배열 순서로 그려진다. 저장도 배열 순서를 보존하므로 별도 데이터베이스 필드는 필요 없다. 팀 ID와 선수 배정은 유지하고 배열 순서만 바꾸는 것이 안전하다.

## 비교

| 방식 | 장점 | 약점 |
| --- | --- | --- |
| 배정표의 팀 열을 직접 좌우로 드래그 | 현재 화면에서 결과를 즉시 본다 | 320px에서 제목·수정·삭제가 이미 밀집해 있고, 4팀의 가로 스크롤과 터치 드래그가 충돌한다. 열 전체 미리보기·자동 스크롤도 필요하다. |
| 별도 `팀 순서` 시트에서 세로로 드래그 | 3~4팀 카드에 손잡이·팀명·배정 인원을 충분히 보여줄 수 있다. 가로 스크롤과 충돌하지 않는다 | 순서를 바꾸는 동안 배정표가 가려지고 진입 동작이 하나 추가된다. |
| 화살표로만 순서 변경 | 접근성과 구현이 단순하다 | 직접 조작감이 약하고, 사용자가 요청한 드래그앤드롭을 충족하지 못한다. |

권장안은 배정표 하단 관리 영역에서 여는 **팀 순서 시트**다. 각 팀 카드의 손잡이로 세로 드래그하고, 같은 손잡이에서 키보드 위·아래 화살표로 이동할 수 있게 한다. 이동 중 삽입 위치와 떠 있는 카드를 보여주고, 놓으면 배정표의 열 순서를 즉시 갱신한다. 상단 도구 모음과 좁은 팀 제목 셀에 조작을 더하지 않는다. 기존 경기 순서 편집기의 포인터 캡처·삽입 표시·착지 애니메이션 패턴은 참고할 수 있지만, 그 훅은 세로 경기 목록 전용이라 그대로 재사용하지 않는다.

구현 시에는 팀 ID, 이름, 선수 배정을 그대로 두고 `teams` 배열만 이동해야 한다. 저장·새로고침·공개 상세에서 같은 순서가 보여야 한다. 경기 순서는 팀 ID로 연결된 별도 계획이므로 **팀 열 재배치만으로 경기를 다시 생성하거나 이미 수정한 대진을 바꾸지 않는 것**을 권장한다. 현재 `team-draft.ts`도 ID 집합이 같으면 경기 순서를 보존한다. 반면 `session-allocation.tsx`의 공개 편성과 초안 비교용 `signature`는 팀을 ID로 정렬하여 순서 차이를 무시하므로, 순서 변경을 실제 구현할 때 이 비교와 관련 테스트를 함께 수정해야 한다.
