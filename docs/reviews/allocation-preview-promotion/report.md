# 팀 배정·미리보기 실제 앱 반영 결과

2026-10-06. `feat/promotion-p1` 작업 트리. 4190 임시 UI를 검토한 뒤 실제 앱 4180의 기존 컴포넌트/API에 반영했다. 원격 배포·병합은 수행하지 않았다.

## 반영

1. **후보/추가 자리**: 미배정 신청자 전원, 주→부→다른 포지션 그룹·숫자·일치 텍스트 강조. 세터 예외 그룹 제거. OP2는 라이트 기준, 일반 교대는 추가 후보. 신청자 탭 우선, 전체 상태 검색·참석 확인·교체/해제 계약 유지.
2. **동선**: 공통 상단 저장. 배정 화면 하단 이전/미리보기/다음. 미리보기 하단 배정하기/공개. 선택 팀으로 이동은 유지하고 과거 선택 자리의 파란 강조는 제거.
3. **상태**: 단일 진행/완료 안내. 전원 배정과 공개 가능 조건을 구별한다. 1~2팀·빈팀·미배정·비활성 배정은 공개를 막는다. 공개본과 다른 편성은 ‘미공개 변경 있음’. 서버는 최종 검증 권위를 유지한다.
4. **시각**: 배정 자리 녹색, 기본 빈자리 옅은 황색·점선, 추가 빈자리 중립색·점선. 완료해도 선택적 추가 인원 경로 제공. 버튼은 빈자리를 만들며 생성한 자리를 눌러야 배정으로 이동한다.
5. **자동 배치**: 실행 전 확인/아이콘 유지. 신청자 전원 배정 후에는 기존 편성을 변경하지 않고 안내. 나머지 기존 알고리즘은 유지.
6. **저장/이탈**: 저장 여부는 rosterRevision 대신 실제 저장 팀 존재 여부, 공개 상태는 서버 공개본으로 판단. 저장 후 편집 유지. 허용된 이동에서 편집 캐시 제거; 취소하면 유지. 포지션 안내는 펼쳐보는 도구로 바꿔 작은 화면 공간 확보.

수동 배정과 서버 왕복은 로컬 검증 전용 가상 일정에서 실행했다. 기존 사용자 연습 일정 `session-allocation-practice-20261003`는 검증 전후 DTO가 같음을 확인했다. 실패한 화면 검사 중 생성된 검증 전용 일정도 로컬에 남아 있으며 사용자 일정과 구별되는 이름/안내를 사용한다.

320×667에서 후보 영역이 처음 47px여서 실패했다. 안내를 접고 여백을 줄인 후 **103px**, 390/423×844에서는 **262px**, 1024×844에서는 **342px**. 모든 크기에서 문서 가로 넘침 없고 하단 버튼이 뷰포트 안에 있다. 320px의 팀 배치판은 터치 영역 보존을 위해 가로 스크롤을 사용한다. 주포지션 후보 0명, 검색 빈 결과, 미등록/비활성·이미 배정된 선수 처리, 중복 없는 그룹을 자동 검사했다.

브라우저 첫 로그인 실패는 이전 서버가 새 빌드에서 사라진 정적 자산을 참조한 404였다. DB를 유지한 채 4180 프로세스를 최신 빌드로 재시작하여 해결했다.

## 독립 검토와 판단

실행 스킬의 요구에 따라 별도 `allocation_promotion_review`(gpt-6-astra/high)가 이번 변경 구간만 읽기 전용으로 검토했다. Critical 없음, Important 1개, Minor 없음.

- 발견: `onLeave` 콜백이 없는 일정/즐겨찾기 편집기는 BFCache 복귀 후 이탈 보호가 꺼질 수 있음.
- 보완: 콜백 없는 복원에서 leaving 플래그 초기화. 실패 재현 후 수정했고 전체 225개 테스트 통과. 실제 팀 편집의 네이티브 Back 검증도 통과.
- 판단 유보: 실제 iPhone은 별도 인수. 기존 자동 배치/등록 정책과 이번 전부터 있던 변경 전체는 검토 범위 밖. 원래 범위를 유지하며 전체 제품/브랜치 완료로 확대하지 않는다.

실행 중 판단:
- 기존 변경이 있는 격리 작업 트리를 유지했다. 변경 전 스냅샷으로 구간 diff를 남기고 전체 커밋·삭제는 하지 않았다. 그렇지 않으면 이전 사용자 작업이 섞일 위험이 있다.
- 메타데이터는 계획의 sideout-query.ts가 아닌 실제 편집 GET 담당 sideout-teams.ts에 추가했다. 저장 가능 팀수 최소 1을 근거로 hasSavedDraft를 계산하여 명단 revision을 저장 여부로 오인하지 않는다.
- 앱 링크는 문서 이동이므로 beforeunload/pagehide로 네이티브 뒤로가기를 보호했다. 확인 후 떠난 팀 편집의 BFCache 복귀는 서버에서 재조회한다. 일정/즐겨찾기의 복원은 dirty 보호를 다시 활성화한다.
- 자동 배치 대상과 OP2 계약은 그대로 두었다. 별도 정책 제안을 임의 확정하지 않았다.
