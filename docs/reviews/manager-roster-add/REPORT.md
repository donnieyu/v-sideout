# 운영진 명단 추가 규칙 변경 — 2026-10-06

후속 변경: 같은 날 사용자 보고에 따라 공개 취소 후 운영진 참가 취소도 허용했다. 아래 취소 제한 기록은 당시 상태이며 [후속 보고서](../manager-roster-cancel/REPORT.md)가 우선한다.

## 확정 규칙

- 마스터 또는 해당 모임 운영자는 모집 중(open), 운동 시작 전, 현재 팀편성이 미공개인 일정에 명단 모달로 회원을 추가할 수 있다. 공개 취소 상태도 포함한다.
- 수동 추가는 참석 의사 확인으로 간주하고 마감/정원/소속회원 우선 기간과 무관하게 applied 참석자로 바로 등록한다. 취소 이력이 있는 활성 회원도 다시 추가 가능하다.
- 현재 공개 중, 운동 시작 시각 이후, 준비 중(draft) 일정에서는 추가를 차단한다. 비활성 회원·중복 신청/대기는 후보에서 제외하고 서버에서도 거절한다.
- 일반 회원 본인 신청의 마감/우선기간/정원 대기 규칙 및 최초 공개 후 신청 제한은 유지한다.
- 추가 권한과 참가 취소 권한을 별도로 내려 모달에 적용했다. 이번 요청으로 기존 공개 이력 이후 참가 취소 제한이 풀리지는 않는다.

## 변경

participation.ts의 canManagerAdd를 후보 조회·상세 capability·등록 서버에 공통 적용. 팀배정만의 예외 context를 제거하고 운영진 참석 등록 규칙으로 통합했다. 명단은 canManageRoster로 추가, canCancelRoster로 취소를 분리한다. 후보 조회는 settled snapshot의 모임 권한을 다시 확인한다. 기존 revision/commandId/회원 활성 상태/동시 공개 CAS 보호는 유지한다.

## 검증

- 신규 회귀 7개 실패 확인 후 구현. 기존 대기/FIFO 시험의 source를 일반 회원으로 조정하고 운영진 bypass 시험을 분리했다. 중간 테스트 편집에서 신규 manager 시험도 self로 바뀐 오류를 확인해 바로잡았다.
- 최종 전체 SIDEOUT 301개, 회원 UI 4개 통과. TypeScript 및 production build 통과. tests.txt/member-tests.txt/types.txt/build.txt.
- 운동 시작 -1ms 허용, 시작 시각 및 +1ms 차단을 후보 GET·추가 POST·버튼 capability 모두에서 확인.
- 실제 로컬 브라우저 390px: 마감 후 정원1 일정에서 마스터가 2명 직접 참석 추가, 모달 유지; 일반 회원은 대기; 공개 중 버튼/GET/POST 차단; 공개 취소 후 운영자가 추가하면 명단 및 팀편성 후보에 신청자로 반영. 참가 취소 버튼은 계속 숨김.
- browser.json: 검증 전용 일정 a09b333e-04c5-498b-97a3-29a12c6930bc. 기존 사용자 일정 두 개의 편성 데이터를 검사 전후 대조하여 보존 확인. 런타임 오류 없음.
- 실제 iPhone 조작 검증은 수행하지 않았다. 4180 로컬 서버에 새 빌드 반영. 원격 배포 없음.
