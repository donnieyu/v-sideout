# 팀 보기 변경과 경기 순서 드래그 개선 검토

2026-10-06 · promotion-p1 실제 앱 · 드래그 개선은 제안 단계

## 반영한 변경

- 편집기 행 보기: 세터 → 레프트 1 → 레프트 2 → 센터 1 → 센터 2 → 라이트. 추가 선수는 기존 별도 영역을 유지한다. 화면 순서만 정렬하고 슬롯 ID와 코트 배치는 바꾸지 않았다.
- 일정 상세: 코트 / 행 전환 제공. 기존 행 보기를 기본으로 유지한다. 코트에는 고정 6자리와 배정된 추가 선수를 분리해 표시한다. 선수 이름·소속·본인 표시는 두 보기에서 유지한다.
- 저장본/공개본/과거 기록의 기존 열람 정책은 그대로 사용한다. 토글은 서버 데이터를 바꾸지 않는다.

## 현재 드래그 구현

`web/components/sideout/match-editor.tsx`는 HTML5 draggable이나 외부 라이브러리가 아닌 Pointer Events 구현이다. 손잡이에서 pointer capture를 시작하고 elementFromPoint로 아래 행을 찾는다. 잡은 행에는 푸른 배경, 목표 행에는 상단 3px 선을 표시한다. 손을 놓으면 배열을 바꾼다. 원래 행이 포인터를 따라오거나 주변 행이 이동하는 애니메이션, 드롭 후 정착 효과는 없다.

가장 중요한 문제는 안내선과 실제 삽입 위치다. 목표 행의 윗부분에 선을 표시하지만, 아래 방향으로 이동하면 원본 제거 후 목표 인덱스에 넣어 목표 행의 뒤에 놓이는 것으로 읽힐 수 있다. 시각 효과를 더하기 전에 before/after 경계를 명확히 해야 한다.

현재 제공하는 키보드 위/아래 이동, Escape·pointercancel 취소, 이동 결과 음성 안내, 드래그 중 저장 차단은 유지해야 한다. 가장자리 자동 스크롤은 프레임마다 고정 10px이며 거리 기반 속도 조절은 없다.

## 공식 패턴 비교

Atlassian의 공식 지침은 복잡한 행을 단순한 드래그 미리보기로 만들고, 최종 삽입 위치를 명확한 선으로 표시하도록 설명한다. 한 목록 안 재정렬은 도착 영역 전체 색칠보다 삽입선이 핵심이다. 다른 조작이 있는 행에는 전용 손잡이를 사용한다.
출처: https://atlassian.design/components/pragmatic-drag-and-drop/design-guidelines/

Dnd-kit은 포인터를 따라오는 DragOverlay와 드롭 애니메이션을 제공한다. 현재 React 문서의 기본 드롭 효과는 250ms ease이며 변경하거나 끌 수 있다. 스크롤되는 목록에서는 오버레이가 원래 목록의 배치와 드래그 미리보기를 분리하는 데 유용하다.
출처: https://dndkit.com/react/components/drag-overlay/
출처: https://dndkit.com/legacy/presets/sortable/overview/

이 비교는 공식 설계·구현 자료에 근거한다. Jira·Trello·Notion 앱을 직접 실행해 동작을 측정한 결과는 아니다.

| 방식 | 장점 | 비용·주의점 | 판단 |
|---|---|---|---|
| 기존 Pointer Events 보강 | 현재 터치·저장·권한 흐름 보존, 의존성 추가 없음 | 경계 계산·스크롤·가변 높이 처리를 직접 유지 | 현재 단일 목록에 권장 |
| dnd-kit Sortable + Overlay | 이동·정착 효과와 센서 구성이 체계적 | 기존 이벤트 교체와 접근성·터치 회귀 검증 필요 | 여러 목록 간 이동으로 확장될 때 재검토 |
| 브라우저 네이티브 기반 DnD | 데스크톱 드래그 미리보기 활용 | 플랫폼 제약과 모바일 동작을 다시 검증해야 함 | 현재 모바일 중심 화면을 즉시 대체할 이유는 약함 |

## 권장하는 상호작용

1. 손잡이를 잡으면 행의 간략 카드가 살짝 떠서 손가락을 즉시 따라온다. 일반/신입, 대진 중심으로 표시하고 회전·과도한 확대는 생략한다. 원래 자리는 높이가 유지되는 옅은 자리 표시로 남긴다.
2. 행의 위/아래 절반을 기준으로 삽입 경계를 계산하고, 확정될 위치에 안내선 또는 간격을 보여준다. 자기 자리로 돌아오면 이동하지 않는다.
3. 주변 행 이동은 삽입 경계가 바뀔 때만 짧게 적용한다. 신입 행의 높이가 다르므로 실측 높이를 사용한다. 목표 인덱스 진동을 막을 작은 완충 구간을 둔다.
4. 놓으면 새 위치로 정착하고 도착 행에 짧은 색 피드백을 준다. 제안 시작값은 주변 이동 150~200ms, 정착 160~220ms, 완료 색 500~700ms다. 제품에 맞춰 검증할 수치이며 공식 표준값이 아니다. 포인터 추적에는 지연되는 easing을 쓰지 않는다.
5. 자동 스크롤은 가장자리까지의 거리와 경과 시간에 비례시킨다. 고정 헤더 아래에서도 드롭 위치가 가려지지 않도록 계산한다.
6. 움직임 감소 설정에서는 공간 이동 효과를 줄이고 삽입선·색·결과 안내는 유지한다. 일반 목록 영역은 스크롤에 사용하고 전용 손잡이만 드래그를 시작한다.

권장 구현 순서: 정확한 삽입 경계 → 따라오는 카드/원래 자리 표시 → 드롭 정착 → 주변 행 이동·자동 스크롤 조정. 작은 효과를 여러 개 얹기보다 사용자가 ‘무엇을 잡았고 어디로 옮기는지’를 확실히 알게 하는 것이 우선이다.

## 후속 드래그 검증 기준

- 위/아래·첫/끝·한 칸/여러 칸 이동 시 삽입선과 결과 일치.
- 다른 높이의 일반/신입 행, 긴 대진명, 100경기 제한에서 정상 동작.
- 밖으로 나간 포인터·Escape·pointercancel·캡처 손실의 취소 정책 일관성.
- 드래그 중 저장 차단, 취소 시 순서 복원, 완료 시 변경 상태·경기 시각 갱신.
- 키보드 대체 이동·포커스 유지·음성 안내·움직임 감소 설정 확인.
- iPhone Safari에서 손잡이와 페이지 스크롤 충돌, 하단/상단 자동 스크롤 실기기 확인.
