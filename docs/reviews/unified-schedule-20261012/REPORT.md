# 승인된 공통 일정 정보 · 하단 플로팅 조작 적용

2026-10-12 사용자 “승인할게. 승인된 것들 진행해.”에 따라 promotion-p1에 적용했다. 기존 미커밋 변경을 보존했다. 메인 병합/배포는 수행하지 않았다.

## 적용

- 모바일 편집기: 외곽 바탕 박스 없는 개별 48px 둥근 버튼을 하단에 모았다. 등록은 돌아가기/준비로 저장/모집 시작, 일정·경기 수정은 돌아가기/저장, 팀은 돌아가기/저장/공개, 공개 중에는 돌아가기/공개 취소다. PC는 상단 조작 영역을 사용한다.
- 저장 중 돌아가기는 비활성화하고, 기존 미저장 이탈·확인·공개 권한·충돌 처리를 유지한다. 모달이 열리거나 경기 드래그 중이면 배경 작업 그룹을 숨긴다. 팀 정보 재조회가 필요한 상태는 편집을 잠그고 별도 복귀 경로를 유지한다.
- 등록/수정 모두 동일한 직접 입력 화면을 사용한다. 정보/공지 탭과 변경 펼침을 없앴다. 장소·시간, 신청 정보, 운동 공지는 하나의 카드 안에서 구분한다. 제목은 고정하고 입력 본문 하나를 스크롤한다. 좁은 화면의 시간 입력은 값이 잘리지 않는 레이블/입력 행으로 배치한다.
- 상세 일정 정보도 같은 세 구획의 단일 카드로 표시한다. 전체 수정 버튼 하나, 장소 중복 제거, 긴 공지 펼침 유지. 공개 팀을 보는 일반 회원에게는 장소·시간·공지 중심으로 표시하고 신청 설정은 생략한다.
- 신청 마감은 정확한 한국 날짜/시각과 D-N/오늘 마감/신청 마감 배지로 표시한다. D-N은 한국 달력 날짜 기준이며 공개 일정의 접수 종료가 우선한다. 서버 신청/대기 규칙은 변경하지 않았다.
- 모바일 키보드는 visualViewport 높이가 실제 줄어든 경우에만 감지한다. 키보드 닫기와 저장을 입력 영역 위에 유지한다. 단순 포커스만으로 버튼을 숨기지 않는다.

## 검증

- 테스트 선행: 공통 폼·D-day 실패 확인 후 구현.
- SIDEOUT 387개 / 회원 UI 4개 통과. TypeScript 검사·프로덕션 빌드 통과.
- 이번 공통 UI 파일 lint 오류 0; schedule-editor의 기존 경고 2개 유지. 별도 match-editor 기존 react-hooks/refs 오류 21개는 이번 범위 밖이며 전체 lint 통과를 의미하지 않는다.
- 실제 Chrome에서 320×667 / 390×844 / 1280×900, 등록·일정 수정·팀 수정·공개 팀·경기 수정·상세 총 18개 화면 확인. 가로 넘침 없음. 본문 스크롤 중 제목/하단 조작 위치 유지, 마지막 입력란 가림 없음.
- 미저장 복귀 확인/취소, 공지 직접 진입, 공개 취소 확인창 취소, 공지 펼침, 경기 포인터 드래그/키보드 이동, 오버레이 작업 숨김 확인. 페이지 런타임 오류 0.
- 독립 읽기 전용 리뷰 `/root/floating_ui_review`: 확정 회귀 없음, 키보드 포인터 저장 검증 요구. 실제 Chrome 시뮬레이션에서 포커스 이동으로 저장 클릭이 유실됨을 재현하고, 키보드 표시 중 pointerdown의 자동 포커스 이동을 막아 수정했다. 포인터 down/up 한 번에 모의 저장 1회 통과.
- 기존 일정에 실제 POST 0회. 키보드 저장 검증은 브라우저에서 응답을 가로챈 모의 저장이며 운영/연습 명단을 변경하지 않았다.
