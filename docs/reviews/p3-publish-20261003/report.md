# P3-2 공개 명령 검증 보고

## 구현 범위
- `web/lib/sideout/team-publish.ts`: 3~4개 비어 있지 않은 팀, 신청자 전원 배정, 활성/중복/자리 검증. 1~2팀은 초안 저장만 가능.
- `web/lib/server/sideout-teams.ts`: 기존 POST에 별도 publish 명령. `confirmed: true` 필수. 공개는 배정 대기자 승격·초안·공개 팀·공개 경기·최초공개시각을 동일 revision 커밋으로 변경한다.
- 초안 저장은 공개본을 보존하고 재공개는 최초공개시각을 보존한다. 공개 이후 추가신청/운영진 추가/본인·운영진 취소 금지 유지.
- 6명 미만 팀을 별도로 금지하지 않는다. 사용자 규칙은 신청자 전원 배정이며 빈 팀은 거절한다.

## 검증
- SIDEOUT 183개 + member UI 4개 = 187개 통과. `tests.txt`, `member-tests.txt`.
- 타입 검사 `npx tsc --noEmit` 통과. 초기 테스트 JSON 응답 unknown 타입 오류 수정 후 재검사.
- `npm run build` 통과 (`build.txt`). vinext의 기존 정적 라우트 분류 안내만 출력.
- 신규 도메인 13개 + API 11개: 1/2팀 차단, 3/4팀 공개, 빈 팀·미배정·비활성·중복·잘못된 자리, 공개 확인, 승격, 재공개, 원본 불변.
- 실제 SQLite D1 테스트: 공개와 취소/신규신청/일정수정/회원비활성/행위자 권한 회수 경쟁 →409, 부분 승격/부분 공개 없음.
- LAN HTTP 실제 로그인 + 로컬 Wrangler D1: 합성 일정 2026-12-27 (`29eed784-2e35-4ef6-b613-76cf2a1d9002`), 신청2+대기1 → 공개 후 신청3. 동일 명령 재전송 200/한 번만 반영, 구 revision409, 2팀 공개400/원본불변. 공개 후 운영진 추가/취소400. 후속 초안 제목 변경에도 공개 제목 유지.
- 대기자였던 시험waiter는 공개 후 팀/경기 열람 가능. 시험outsider는 팀/경기를 받지 않음. 두 일반 계정 모두 편집 초안 GET403.
- `browser.json`, `verify-publication.mjs`, `capture-visibility.mjs`, `mobile.json`: 실제 인증 화면 및 390px 열람 차이 확인. 실물 iPhone 검증은 이번 단위에서 수행하지 않았다.
- 첫 브라우저 실행은 팀명 중복 선택자 때문에 캡처 단계에서 중단했다. heading으로 한정 후 재실행 통과. 당시 생성한 12월20일 합성 일정도 로컬에 남겨 두었다.
