# 새 모임 등록의 상세 확인 흐름 — 2026-10-12

## 변경
- /session/new 기본 진입은 입력 폼 대신 모임 기본 장소·입장/시작/종료 시간과 기존 기본 신청 설정을 보여주는 운동 상세 화면이다.
- 기존 준비 일정과 PreparedScheduleView를 공유하여 모집 준비 중/회원 미공개 안내, 일정 정보 카드, 수정, 공통 하단 돌아가기/모집 시작을 통일했다.
- 단순 진입 시 저장 요청 없음. 모집 시작 시에만 신규 일정(phase=open, revision=0)을 생성하고 생성된 상세로 이동한다. 팀편성 공개는 별도이다.
- 수정은 명시적인 edit=1 진입으로 분리한다. 처음 저장 전 복귀는 기본 정보 상세, 처음 저장 후 복귀는 새로 생성된 실제 일정 상세로 연결한다. 주/모임 필터를 보존한다.
- 모임 기본값 계산을 공통 함수로 옮겨 조회/수정 기본값이 어긋나지 않게 했다. 기존 기본 마감/우선 신청/정원 규칙은 변경하지 않았다.
- 등록 불가 권한·지난 일정·잘못된 날짜 차단, 중복 시작 방지, 실패 시 오류 표시와 동일 명령 재시도를 유지한다.

## 검증
- 신규 회귀 테스트를 먼저 실행해 누락 동작 3건 실패 확인. 구현 후 신규 7건 포함 대상 22건 통과.
- 전체 SIDEOUT 41파일/403개 테스트 통과. TypeScript 및 production build 통과.
- 변경 제품 파일 ESLint 오류 없음. schedule-editor의 기존 hook dependency/unused variable 경고 2건 유지.
- Chrome + WebKit의 320/390/1024px: 가로 넘침 없음, 버튼 44px, 읽기 화면으로 최초 진입 확인.
- 두 브라우저에서 수정 → 준비로 저장 → 창 포커스 재검증 → 저장값 유지 → 운동 상세 복귀 → 모집 시작 확인.
- 기본 정보 상세에서 직접 모집 시작 → 신규 상세 진입, 필터 보존 확인.
- 모든 일정 생성/변경은 브라우저에서 가상 응답으로 가로채 검증했다. 실제 사용자 일정/신청자 데이터는 변경하지 않았다.
- 4180 서버에 새 빌드를 반영했다. 실기기 iPhone Safari 직접 검증은 별도이며 WebKit 결과와 동일시하지 않는다.
