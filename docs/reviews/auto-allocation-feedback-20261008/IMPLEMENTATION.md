# 자동 배치 후 미배정 이유 보기 구현·검증

2026-10-08 · `feat/promotion-p1`

팀 삭제가 선택된 다른 팀 자리의 `target`은 남기고 `pendingId`만 지우던 상태 결함을 수정했다. 이제 팀 삭제 후 이전 선택 상태를 모두 정리하며, 수동 배정 → D팀 추가·삭제 → 자동 배치의 회귀 테스트가 통과한다.

기존 주→부→기타 포지션 배정은 유지한다. 자동 배치 실행 결과에서 남은 활성 신청자를 `주포지션 미등록`, `빈자리 부족`, `빈자리가 있는데 미배정`으로 분류한다. 마지막 유형은 정상 이유가 아닌 실행 이상으로 별도 오류를 표시한다. 기존에 배정된 비신청자가 자리를 사용한다면 자리 부족 설명에 인원 수를 덧붙인다. 그룹 합계는 잔여 신청자 수와 일치하도록 한 사람을 한 그룹에만 넣는다.

상태 줄의 `이유 보기`는 자동 배치 후 잔여 신청자가 있을 때만 나온다. 팀·자리·신청자 데이터가 바뀌면 과거 결과는 보이지 않는다. 이유 대화창에는 이름·소속·해결 행동을 표시한다. 포지션 불일치는 잔여 사유로 쓰지 않는다.

검증:

- `npm run test:sideout`: 32개 파일, 342개 테스트 통과.
- `npm run test:member-ui`: 4개 통과.
- `npx tsc --noEmit` 및 `npm run build` 통과.
- 변경 코드·테스트 4개 파일의 대상 `eslint` 통과. 전체 `npm run lint`는 기존 파일에 분산된 오류 52건·경고 52건으로 실패했으며, 이번 변경 파일에서는 오류·경고가 없었다.
- 실제 로컬 18명 시험 화면에서 자동 배치 후 14명 배정·4명 미배정, 이유 보기에서 4명 모두 주포지션 미등록으로 표시됨. 시험 브라우저에서 저장하지 않아 실제 편성은 변경되지 않았다.
- 320px·390px Chrome에서 이유 대화창 좌우가 화면 안에 있고 문서 가로 넘침이 0px임을 측정했다. [320px 화면](screenshots/reason-320.png), [390px 화면](screenshots/reason-390.png).
- 빌드 후 실행 중이던 로컬 4180 Worker가 이전 정적 파일을 참조해 404가 발생하여 새 빌드로 재시작했다. 이후 브라우저 검증을 완료했다.

실기기 터치 확인과 공개 전 사용자 검토는 아직 수행하지 않았다. 이번 변경은 브랜치 작업이며 메인 반영과 별도로 검토할 수 있다.

## 후속 시각 개선

자동 배치 후 미배정자가 남으면 기존 상태 줄을 옅은 황색 주의 상태로 표시한다. `14/18명 배정 · 4명 미배정`처럼 숫자를 한 줄로 줄이고 주의 아이콘과 `이유 보기` 버튼을 함께 둔다. 배정 전의 일반 상태와 전원 배정 후 녹색 완료 상태는 유지한다. 320px·390px 실제 브라우저에서 상태 줄 높이 46px, 버튼 높이 44px, 가로 넘침 0px을 확인했다. [320px 상태](screenshots/warning-status-320.png), [390px 상태](screenshots/warning-status-390.png). `npm run test:sideout` 342개, `npx tsc --noEmit`, 변경 파일 대상 ESLint, `npm run build` 통과.
