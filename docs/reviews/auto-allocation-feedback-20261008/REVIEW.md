# 자동 배치 결과·잔여 사유 개선 검토

상태: 초기 대안 비교 기록. 앱 코드·신청자·저장 편성은 변경하지 않았다.

> 2026-10-08 후속 검토: 아래의 ‘포지션 일치 우선 후 명시적 마무리’ 추천은 철회한다. 사용자의 후속 요구와 실제 알고리즘 재현 결과에 따라, 현재의 **주→부→기타 포지션 자동 배정은 유지**하고 남은 신청자의 원인을 설명하는 방향으로 정리했다. ‘맞는 포지션이 없음’은 현재 알고리즘의 미배정 사유가 아니다. 최신 상황 분류·결함·검증 증거는 [UNASSIGNED_CASES.md](UNASSIGNED_CASES.md)를 따른다. 아래 대안/흐름은 비교 이력이며 구현 지시가 아니다.

## 확인된 원인

사용자가 지정한 2026-10-17 일정 `9b2f9cd1-145c-46d7-afb4-4eb66412b04d`의 로컬 시험 DB를 읽기 전용으로 조회했다. 신청자 18명 중 14명은 프로필이 있고 4명은 주·부 포지션이 미등록이다. 저장 편성은 14명이며 B/C팀의 센터 각 2자리가 비어 있다.

현재 `autoFillBoard`는 신청자→대기자, 각 집단 안에서 주→부→기타 포지션 순으로 배정한다. 주포지션 미등록·비활성 회원은 제외한다. 기본 자리를 모두 채운 뒤 추가 자리를 채우고, 기존 기본 자리 배정은 유지한다. 따라서 센터 지원자 부족만으로 빈 센터 자리를 유지하는 규칙은 아니다.

실제 입력을 빈 3팀에 재실행: 14명 배정(주 9, 부 3, 기타 2), 프로필 미등록 4명 제외. 모두 OH/부 OP인 18명을 합성한 반례: 센터 지원자가 없어도 18명 전원 배정. 저장된 배정 원본은 변경하지 않았다.

## 대안

1. 현행 알고리즘 유지 + 결과 설명: 가장 작은 변경. 다만 다른 포지션 배정은 자동이고 미등록만 제외하는 차이를 알아야 한다.
2. 무조건 전원 배정: 자리만 충분하면 빨리 완료. 세터/센터를 맡을 의사가 확인되지 않은 배정까지 자연스럽게 확정된 듯 보일 수 있다. 참석과 포지션 수행 의사는 별개다.
3. 추천 — 포지션 우선 배정 후 명시적 마무리: 주/부 일치 배정을 우선하고 나머지를 사유별로 보여준다. 운영자가 다른 포지션 또는 미등록 회원의 빈자리 배정을 선택하면 완성한다. 현행의 암묵적 기타 포지션 fallback을 명시적 선택으로 바꾸는 설계다.

## 제안 흐름

- 자동 배치 확인창에 “주·부 포지션을 우선 배치합니다. 맞는 자리가 없거나 포지션 정보가 없으면 확인이 필요합니다.”와 실행 버튼을 표시한다. 필요한 정보는 이 문맥에서만 제공한다.
- 실행 후 전원 일치 배정이면 기존 한 줄 상태를 “신청자 18명 전원 배정 · 공개 가능”으로 갱신한다. 3~4팀/빈 팀 없음 등 실제 공개 조건도 충족해야 한다.
- 잔여가 있으면 결과 다이얼로그: 배정 N명/남음 M명, 포지션 미등록/맞는 빈자리 없음/자리 부족 그룹과 선수명·소속·주부포지션. 빈자리도 팀/포지션별로 표시한다.
- “직접 배정” 또는 “남은 선수 빈자리에 배정”을 선택. 후자는 선수→자리 제안과 미등록/포지션 외 배정 수를 먼저 보여주고 적용한다. 인원이나 자리 부족이 있으면 전원 배정을 약속하는 문구를 쓰지 않는다.
- 결과창을 닫아도 기존 상태 줄의 “4명 남음 · 이유 보기”로 다시 확인한다. 새 상시 안내 박스를 쌓지 않는다. 편성을 수정하면 잔여 상태를 현재 편성에서 다시 계산하여 오래된 사유를 남기지 않는다.
- 자동배치 보고서는 결과 보드와 동일한 계산에서 생성하여 UI 추정과 실제 배정의 불일치를 방지한다. 주/부 조합을 함께 검토해 배정 가능한 최대 인원을 찾고, 그 안에서 주포지션과 기존 기본 배정을 우선한다.

## 상황별 처리

| 상황 | 제안 |
|---|---|
| 18명·프로필/포지션 적합 | 18명 배정·완료 한 줄 |
| 18명·미등록 4명 | 등록된 선수 우선 배정, 미등록 사유/실제 이름 제공, 선택적 빈자리 배정 |
| 특정 포지션 지원자 부족 | 맞는 빈자리 없음으로 표시; 해당 포지션 수행 확인 후 대체 배정 |
| 21~28명·기본 자리 초과 | 기본 자리 우선, 남는 인원 추가 자리; 추가 자리 부족은 줄 추가 제안 |
| 신청자 일부 미배정·대기자 존재 | 신청자 해결을 우선. 신청자가 남아 있는데 대기자로 자리를 소진하지 않도록 함 |
| 미등록 선수를 일반 추가 자리에 배정 | 회차 배정 포지션을 명시적으로 선택할 수 있어야 함. 현재 fromBoard는 개인 주포지션이 없으면 일반 추가 자리 저장을 거부함 |
| 기존 배정/수동 추가자리 존재 | 기존 기본 배정 보존. 추가 자리 선수 이동은 실행 전 설명. 동일 입력 반복 실행 시 중복 배정 없음 |
| 공개 중/비활성 | 자동 배치 불가 및 비활성 신규 배정 금지 유지. 보존 가능한 기존 공개 배정은 유지 |

회차 배정 포지션은 회원 주·부 포지션 원본을 수정하지 않는다. 미신청 회원은 자동 편입하지 않는다. 저장 전 로컬 변경·저장 시 참석 확정·공개 확인/잠금은 기존 규칙을 유지한다.

## 구현 시 검증

현재 10월17일 18명/미등록4명 입력, 센터 지원자0명, 주부 중첩, 세터 부족, 18/21/28명, 수동 추가줄 삭제 후 용량 부족, 대기자와 미배정 신청자 동시 존재, 프로필 미등록의 기본/추가 자리, 기존 배정 유지, 반복 실행, 공개 잠금, 결과 사유와 실제 후보 수 일치. 320/390px에서 결과 dialog 내부 스크롤·이름/소속 줄바꿈·닫기/포커스 복귀를 확인한다.
