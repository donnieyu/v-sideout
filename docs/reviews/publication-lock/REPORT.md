# 공개 취소 후 편집 흐름 검증

## 구현

- 현재 공개 상태(publicationState)와 최초 공개 이력(firstPublishedAt)을 분리. 기존 데이터는 필드가 없어도 published 스냅샷을 공개 중으로 해석.
- 공개 중 save/publish는 서버 거절. 확인된 unpublish만 편집 허용 상태로 전환. 기존 명령 재시도 영수증/리비전/권한 원자적 경계 유지.
- 공개 취소 후에도 최초 공개 이력과 공개본/경기 순서 보존. 신청·참가 취소·자동 대기 승격은 재개하지 않음.
- 공개본과 초안이 다르면 공개 취소 확인창에서 기준 선택. 공개본 선택 시 기존 초안과 경기 순서를 withdrawnDraft에 보존.
- 공개 중은 실제 공개본 조회, 저장 비활성, 배정·교체·해제 및 팀/자리 변경 숨김. 코트/행 및 포지션 조회 유지. 서버 성공 이후 편집 활성화.
- 공개 취소 후 회원 API/화면은 팀·경기 순서를 함께 비노출. 경기 순서 단독 수정 기존 정책 유지, 취소 중에는 비공개 저장. 재공개에 전체 신청자/3~4팀/유효성 검증 재적용.
- 15초 갱신 및 포커스 재검증으로 공개 상태 전환 시 편집 캐시 교체. 오래된 저장 요청은 서버 리비전 검사로 거절.

## 확인 결과

- SIDEOUT 테스트 268개 통과, TypeScript 오류 없음, production build 성공.
- 권한/확인 누락, stale revision, 중복 명령, 동시 일정·명단·운영자 변경, 운동 시작 이후 취소 거절 테스트.
- 별도 브라우저 시험 일정의 실제 API: 공개 중 직접 저장 거절, 공개 유지 선택 무변경, 네트워크 실패 후 잠금 유지, 재시도 공개 취소, 회원 팀/경기 순서 비노출, 참가 제한 유지, 취소 중 경기순서 비공개 저장, 저장 후 편집 유지, 재공개 후 읽기 전용.
- 320/390px 공개 미리보기·포지션 조회 화면 캡처. 해제 버튼과 후보 풀 없음, 가로 넘침 없음. 읽기 전용 타일에 남던 해제 버튼 여백을 제거.
- independent reviewer: 서버 상태/권한/캐시/데이터 보존 코드 검토에서 차단급 발견 없음. 테스트 실행과 E2E는 주 작업에서 수행.
- 원래 사용자 연습 일정 두 개는 API 전후 비교로 보존 확인. 자동화가 변경한 것은 fixture.json의 별도 가상 일정뿐.
- 실제 iPhone 검증은 미수행. 브라우저에서 320/390px 검증.
