# 승인된 SIDEOUT 작업 메인 통합 — 2026-10-07

## 통합 범위

사용자의 “지금까지 승인된 내역들을 메인으로” 요청에 따라 `feat/promotion-p1`의 승인된 실제 앱 변경을 main으로 통합한다. 출발 main은 `d976116`, 기존 promotion HEAD는 `3faaf54`다. 이 기록은 앱 코드 통합과 운영 배포를 구분한다.

- 홈·일정 상세·일정 편집·즐겨찾기와 실제 인증/조회 경로.
- 명단 모달의 복수 참가자 추가, 연속 취소, 공개 취소 후 명단 수정, 참가 취소 시 초안 배정 자동 해제.
- 일반 신청의 마감·상한·소속 우선 대기/FIFO, 운영진의 운동 시작 전 직접 참석 등록, 공개 중 신청/추가/취소 잠금.
- 코트·행 통합 팀편성, 선수 선택/해제/교체 다이얼로그, 이름·소속 표시, 완료 상태와 미신청 목록의 명시적 진입, 검색/복합 필터.
- 기본 자리 우선 자동 배치와 초기화, 모든 팀 공통 추가 선수 줄, 3팀 최소/4팀 최대 UI, 배정된 팀·줄도 확인 후 삭제, 행의 팀 이름 수정.
- 저장 후 편집 유지, 공개 확인·공개 중 읽기 전용·공개 취소 후 재편집, 공개 후 빈자리 숨김.
- 일정 상세의 기존 섹션 순서 유지·공개 팀편성 강조·팀별 구분, 공개 후 팀 영역에 인원/명단 통합, 수정 버튼/폰트 통일, 홈·상세의 시험 문구 제거.
- 팀편성 코트/행 도구와 하단 공개 고정, 콘텐츠 내부 스크롤.
- 경기 순서 자동 생성, 신입 경기 선택/순서 변경, 마우스·터치·키보드 DnD, 저장만으로 같은 팀 ID 구성의 공개 경기 순서 갱신.
- 인수 승인된 포지션 조회 계약과 `member_position_profiles` migration. 프로필 입력이나 별도 인증 기능까지 인수한 것은 아니다.

검토 보고서·회귀 검사·합성 화면 증거도 함께 보존한다. 과거 보고서의 당시 미구현/미통합 표시는 현행 상태를 뜻하지 않는다. 최신 상태는 이 문서와 [이전 대응표](../MOCKUP_PROMOTION_PARITY.md)가 우선한다.

## 병합 전 발견·수정

독립 서버 검토는 권한, 명단/배정/공개 SSOT, revision 및 원자성 경계를 읽기 전용으로 검사했다.

1. 공개본만 있는 기존 roster에서 경기 저장은 성공하나 빈 초안과 3팀 경기 계획이 어긋나 후속 조회가 503이 됨. 공개본을 저장 원본으로 사용하는 경우 초안도 같은 팀 원본으로 생성하여 해결했다. 공개 선수/참가 상태는 보존한다.
2. 최초 공개 전 비활성화된 미배정 신청자가 공개를 막음. 미공개 편성 저장 시 비활성·미배정 신청의 현재 참석을 정리했다. 기존 공개 배정 유지와 해제 후 재배정 금지는 유지한다. 상태 변경 회원은 기존 atomic guard에 포함된다.
3. 새 checkout 시험 seed가 포지션 테이블 migration을 누락. 0003을 포함하고 신규 격리 DB로 8계정과 테이블 생성을 확인했다. 사용 중인 시험 DB는 변경하지 않았다.

두 서버 회귀는 수정 전 각각 503/400 실패를 확인했고 수정 후 통과했다. 독립 재검토 결과 해당 범위에 남은 병합 차단 문제는 발견하지 못했다. 이것은 운영 D1 업그레이드 검증이 아니다.

- 새 빈 격리 경로에서 seed 실행 및 profile schema/8계정 검증. 실제 사용 중인 `.wrangler/sideout-p1` 자료는 보존.
- 최신 320/390px 코트·행 내부 스크롤 및 고정 도구 위치/가로 넘침 검사 통과. [측정](browser.jsonl). 첫 시도는 재빌드 전 서버의 구 청크로 로그인 화면 로딩 실패; 같은 자료 경로로 서버 재시작 후 통과했다.
- 현재 소스/문서의 diff whitespace 검사 통과. 과거 원시 build/test 로그와 patch 파일은 출력 바이트를 보존하여 말미 공백 경고가 남는다. 이번 검증 로그는 ANSI와 말미 공백만 정리했다.
- 기존 전체 lint 부채, 실제 iPhone의 최신 통합 화면 전체 인수, 운영 DB 업그레이드/복구는 이 자동 검증에 포함되지 않는다.
