# 경기 순서 수정 실제 앱 반영

2026-10-06 · promotion-p1 · 실제 앱 4180. 이번 변경은 경기 순서 편집에 한정하며 원격 배포·병합·인증/프로필 원본 수정은 하지 않았다.

## 구현 결과

- 일정 상세의 **경기 순서 수정**으로 별도 자식 화면에 진입. 상단 취소/저장, 저장 후 계속 편집, 미저장 이탈 확인.
- 마스터 또는 해당 모임 운영자만 조회/수정. 운동 시작 전, 저장된 팀편성이 3~4팀인 경우만 가능.
- 3팀: 3경기씩 3라운드, 라운드 사이 신입 한 경기. 4팀: 일반 6경기 한 라운드, 앞뒤 신입 한 경기. 기존 기본안 유지.
- 신입 경기 포함 토글, 2~4팀, 순차 대진 배정 및 직접 선택, 경기 추가/삭제. 일반 대진/경기 수는 보존하고 순서만 이동.
- 손잡이를 터치/마우스로 드래그하거나 위/아래 화살표 키로 이동. 이동 위치 강조, 화면 가장자리 자동 스크롤, pointercancel/Esc 취소. 드래그 중 저장 잠금.
- 경기당 20분으로 시각 재계산. 운동 종료 초과는 경고하며 저장은 허용.
- 실제 session/roster revision과 commandId를 사용해 동시 수정·재시도 검증. 실패 시 입력 유지, 충돌 시 최신 정보 명시적 재조회.

## 공개 기준 — 사용자 확인 반영

같은 팀 구성이라면 저장 즉시 참석 회원의 경기 순서에 반영한다. 여기서 팀 구성은 **팀 ID 집합**이며 경기 상대를 정하는 기준이다. 선수 배정 초안이 바뀌어도 경기 저장으로 그 선수를 공개하지 않는다. 팀 ID가 다른 초안은 경기 순서도 초안으로 저장하고 팀편성 공개 시 함께 반영한다. 기존 열람 권한·참가/취소 정책은 유지한다.

## 독립 검토와 보완

실행 스킬에 따라 별도 Astra/high 검토자가 이번 구간만 읽기 전용으로 검토했다. Critical 없음, Important 1건, Minor 1건을 보고했다.

1. 신입 3~4팀에서 포함 토글 OFF→ON 시 4개 일반팀 앞뒤 신입 대진이 첫 대진으로 중복됨. 회귀 테스트 2개 실패를 확인하고 두 번째 대진을 순환 선택하도록 수정했다.
2. 최초 마우스 드래그에서 Esc 취소가 손잡이에 전달되지 않아 원치 않는 이동이 적용됨. 실제 브라우저에서 실패를 재현했다. 취소했는데 순서가 바뀌는 영향으로 Important로 재분류하고 드래그 시작 시 손잡이 포커스를 명시했다. 수정 후 같은 브라우저 검증에서 순서가 변하지 않는 것을 확인했다 (`escape.json`, `escape-green.txt`).

검토자가 판단을 유보한 기존 dirty 변경 전체·실제 iPhone·운영 배포는 이번 완료 주장에 포함하지 않는다. 모바일 시각은 부모 작업의 캡처 검증으로 별도 확인했다. 보완 후 별도 재리뷰 대신 회귀 검사와 전체 테스트를 실행했다.

## 실행 판단

- 최신 승인 목업은 main의 match-order-model.ts/match-order.tsx에 있었으므로 오래된 promotion 목업이 아닌 최신 원본을 읽기 참조했다. 원본 파일은 수정하지 않았다.
- 사용자 승인된 이전/후속 순차 실행 범위 내에서 파일 담당·저장 계약·검증 계획을 먼저 기록했다. 새 공개 저장 경계만 사용자 답변을 받아 확정했다.
- 기존 작업이 많은 격리 작업트리를 유지했다. 변경 전 스냅샷으로 구간 diff를 남겼으며 이전 사용자 변경을 포함하는 커밋/정리는 하지 않았다.
- 새 DnD 라이브러리나 DB 마이그레이션 없이 기존 pointer 패턴 및 roster 원자 저장소를 사용했다. iPhone 동작은 사용자 확인 전까지 미확인으로 남긴다.
