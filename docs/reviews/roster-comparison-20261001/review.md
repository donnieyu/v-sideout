# 명단 화면 원본 비교 — 2026-10-01

대상: web/components/sideout/roster-dialog.tsx, sideout.module.css / HEAD 3faaf54. 승인 baseline archive에서 추출한 RosterDialog와 현재 실제 서버 페이지를 비교했다. 제품 코드·D1 명단·계정은 변경하지 않았다.

## 사용자 인수

사용자는 iPhone에서 그룹 구분은 확인했지만 각 1명이라 다수 인원 배치 및 목업과의 디자인 차이는 추가 검토가 필요하다고 보고했다. 이전 안내의 나머지 항목(상세 새로고침·뒤로가기, 로그아웃 후 재로그인 홈 복귀, 일반회원 노출 범위, 화면/키보드)은 예상대로 동작한다고 확인했다. 이 수용은 다수 인원 명단·전체 이전 완료로 확대하지 않는다.

## 비교 방법

독립 A(roster_visual_review)는 승인 원본과 현재 컴포넌트/CSS·캡처를 비교했다. 독립 B(roster_evidence_review)는 TSX 정적 detector 및 별도 브라우저 context의 키보드 검사를 수행했다. A 판정이 끝난 뒤에만 B 결과를 합쳤다. 동작상 read-only이며 sandbox 격리는 아니다.

소속18명·게스트6명·대기4명, 총28명의 같은 가상 명단으로 320/390/1280px를 검사했다. 실제 데이터베이스는 그대로이며 현재 페이지의 상세 API 응답을 시험 브라우저에서만 치환했다. 원본은 보존 archive의 실제 React 컴포넌트/CSS를 임시 Vite 하네스로 실행했다. 공개 상태라 참가 취소 버튼은 없다. 목업 참가자 추가는 활성, P1은 비활성이라는 차이는 구현 단계 차이로 구분한다.

## 결론

현재는 완전히 다른 디자인이 아니라 승인 목업 구조를 유지한 이식본이며, 인원 배지·문자 규칙 등 일부 표현이 달라졌다. 현행 전체를 개선안으로 승인할 근거는 부족하다. 현재 열 수·스크롤 구조와 읽기 밀도를 유지하고 원본의 그룹 위계·날짜를 복원하는 편이 낫다.

| 항목 | 승인 목업 | 현재 P1 | 판단 |
|---|---|---|---|
| 320 /390 /1280px 열 수 | 1 /2 /3열 | 동일 | 유지 |
| 소속회원 타일 | 이름 중심, 50px | 동일 | 유지 |
| 게스트/대기 | 이름+작은 소속, 64px | 동일 정보, 약61px | 현행도 가독성 양호; 긴 소속 줄바꿈 별도 보존 |
| 그룹 인원수 | 옅은 파란 배지 | 작은 일반 텍스트 | 목업 배지가 구분 쉬움 |
| 날짜 | 10월 4일 운동 | 2026-10-04 운동 | 목업 표현이 서비스 문체에 맞음 |
| 제목·목록·하단 | 고정/내부 스크롤/고정 | 동일 | 유지 |
| 한명씩일 때 공백 | 650px 높이 때문에 있음 | 동일 | 이식 중 새로 생긴 차이가 아님 |

390px 목록 전체 높이는 원본992px/현재961px, 보여지는 목록 공간은 약479px/472px였다. 두 버전 모두 끝까지 휠 스크롤되고 footer 위치가 유지됐으며 이 데이터에서 가로 넘침은 없었다. 모바일 원본 dialog 폭이 15px 좁게 측정된 것은 scrollbar-gutter와 % 폭 영향으로 보이지만 실제 Safari 차이로 단정하지 않는다.

## 우선 보완

1. **P2: 그룹·인원 위계.** 소속 회원/게스트/대기자 제목과 인원 배지를 목업 기준으로 복원한다. 긴 명단의 그룹 구분에 도움이 된다.
2. **P3: 날짜·타이포그래피.** 한국어 날짜, 설명 크기·제목 행간을 기준과 맞춘다. 대규모 재디자인은 필요하지 않다.
3. **P2: 키보드 접근.** 양쪽 모두 목록 region에 Tab 진입이 되지 않았고 PageDown 후 scrollTop=0이었다. 목록 포커스 진입과 내부 스크롤을 보장해야 한다. 목업의 기존 결함이며 이전 과정의 신규 결함으로 분류하지 않는다.

저시력·명단 탐색 사용자에게 작은 인원 텍스트는 약점이고, 키보드 사용자에게 목록 아래쪽 접근 불가는 기능 장벽이다. 모바일 운영자는 그룹별 두열과 고정닫기의 이점을 얻는다. 주어진 명단 화면에는 과도한 선택지나 불필요한 포지션 정보가 없어 현재 정보량은 적절하다.

## 검증 한계

공개 전 취소 버튼이 있는 행, 실제iPhone 다수명단 터치스크롤, 화면읽기 도구는 이번에 검사하지 않았다. 정적 detector 결과 []는 단일 TSX 스캔0건이며 CSS/동작전체통과가 아니다. headless Chrome을 사용했으며 사용자 브라우저 overlay는 만들지 않았다. 별도 detector live-server는 사용하지 않았고 비교용 Vite4182는 종료했다. 기존4180서비스는 유지한다. 가상 fixture는 앱에 저장하지 않았기 때문에 현재 아이폰의 시험 명단은 여전히 각1명이다.

## 적용 방향

권장: 현행 격자·내부스크롤·간결한 타일 유지 + 목업 인원배지·한국어날짜·글자규칙 복원 + 키보드접근 보완. 사용자가 비교해 결정하기 전 제품에는 적용하지 않았다. 이후 실제iPhone 다수명단 확인에는 별도 시험데이터/검토경로를 마련해야 하며 현재 비교 캡처를 실기기 검증으로 대체하지 않는다.
