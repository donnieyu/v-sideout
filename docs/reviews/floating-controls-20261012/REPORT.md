# 플로팅 조작의 배경·크기 보정

사용자 요청: ‘운동 일정으로’처럼 본문 위에 버튼만 띄우고, 크기·폰트도 동일한 수준으로 적용.

원인: 작업 버튼 컨테이너는 이미 투명했지만, 모바일 등록/수정 및 팀편집의 바깥 main padding-bottom 76px이 내부 스크롤을 잘라 하단 배경 띠처럼 보였다. 실제 390px 화면에서 스크롤 하단 768px, 버튼 하단 828px이었다.

적용:
- 고정 높이 편집기 바깥 하단 여백을 제거해 본문이 버튼 뒤까지 이어진다. 마지막 항목은 버튼 위로 올릴 수 있도록 실제 스크롤 영역의 끝에 84px+safe-area 여백을 옮겼다. 버튼 바탕·블러·그라데이션은 추가하지 않았다.
- 기준 복귀 버튼의 computed style: 높이 44px, 글자 13px/400, line-height 1.55, padding 8px 18px, icon 16px, gap 4px. 모바일 공통 작업 버튼에 적용했다. 화면 전체를 채우는 동일 폭에서 콘텐츠에 맞는 폭으로 변경. 360px 이하에서는 가로 padding만 12px로 줄인다.
- 전역 Button 굵기 500이 더 높은 선택자 우선순위로 덮는 것을 실화면에서 발견해, 플로팅 그룹에만 400을 명시했다. 데스크톱 버튼과 기존 단독 복귀 디자인은 유지한다.

검증: 프로덕션 빌드 통과. 실제 Chrome 320/390/1280px 18화면, 모바일 computed 44px/13px/400 확인, 가로 넘침 없음, 본문이 viewport 끝까지 연장, 마지막 입력란이 버튼 위에 도달, 모달/드래그 숨김 및 이탈 확인 정상. 키보드 pointer down/up 한 번의 모의 저장 통과. 실제 일정 데이터 POST 0회. 런타임 오류 0. 서버 최신 빌드로 재시작. 실물 iPhone 별도.

근거: verify.mjs/browser.json, keyboard-save.mjs/keyboard-save.json, 각 화면 PNG. 기존 unified-schedule-20261012 보고의 48px/동일 폭 구성은 이 요청으로 대체된다. main 병합·배포 미수행.
