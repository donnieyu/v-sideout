# 준비 일정의 상세 확인 흐름 — 2026-10-12

## 요청과 반영
- 홈의 기존 초안 ‘이어서 준비’는 일정 수정이 아니라 운동 상세로 연결한다. 주/모임 필터를 유지한다.
- 저장된 일정 정보를 단일 읽기 카드로 보여준다. 모임 기본값으로 시작한 정보 또는 이후 저장한 변경을 덮어쓰지 않는다.
- ‘모집 준비 중’과 회원에게 아직 공개되지 않았다는 상태를 표시한다. 이 상태에서 명단·참석 신청·미공개 팀편성 빈 영역은 표시하지 않는다.
- 일정 정보의 수정 버튼으로만 편집기에 진입한다. 편집기 복귀는 기존처럼 운동 상세로 돌아온다.
- 하단 공통 플로팅 그룹에서 돌아가기/모집 시작 제공. 모바일 44px, 13px/400, 기존 공통 페이드 유지.
- 모집 시작은 기존 schedule API로 저장된 값과 revision을 보내 phase만 open으로 바꾼다. 팀 공개 작업과 분리한다. 성공 후 상세를 다시 읽고 일반 명단/팀편성 화면을 표시한다.
- 중복 클릭/작업 중 이탈 방지, 네트워크 실패 안내, 같은 요청 재시도 command 재사용, 충돌 시 새 정보 조회, 권한·시작 시각 제한을 적용한다.

## 검증
- 변경 전 신규 기대 동작 6건 실패 확인 → 변경 후 통과.
- 전체 SIDEOUT 39개 파일 / 393개 테스트 통과.
- TypeScript, 변경 파일 ESLint, production build 통과.
- Chrome + WebKit 320/390/1024px 6개 화면: 가로 넘침 없음, 모바일 버튼 44px/13px 확인.
- 양 브라우저에서 모집 시작 한 번만 전달, 저장된 정보와 revision 보존, 같은 상세에서 명단 노출 전환 확인.
- 브라우저 검증은 GET/POST를 가상 응답으로 가로채 수행. 기존 실제 일정/명단 데이터는 변경하지 않았다. 실제 iPhone Safari 확인은 별도이며 WebKit 자동 검증과 동일시하지 않는다.
- 4180 로컬 서버를 새 빌드로 재시작했다. 실행 스크립트 verify.mjs, 수치 measure.json, 화면 PNG 동봉.

## 범위
새 일정 최초 생성 폼은 유지한다. 이번 변경은 이미 저장된 준비 일정의 이어서 준비 및 상세 화면의 모집 시작 흐름이다. 이전 iPhone 등록 폼 넘침 방어 변경에 대한 실기기 결과는 아직 미확인이다.
