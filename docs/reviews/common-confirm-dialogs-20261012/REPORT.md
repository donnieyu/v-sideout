# 공통 확인 다이얼로그 전환 — 2026-10-12

## 반영 범위

앱의 남은 브라우저 기본 확인창을 기존 공통 Dialog, Button 디자인으로 전환했다.

- 참석 신청 및 대기 등록 취소
- 운영진 명단에서 회원 참가 취소
- 즐겨찾기 미저장 변경 폐기 및 최신 정보 다시 불러오기
- 일정 정보, 팀편성, 경기 순서의 미저장 변경을 버리고 최신 정보 다시 불러오기
- 편집 중 하단 복귀 또는 링크로 이동할 때 미저장 변경 확인

모집 시작과 공개 취소 등 이미 앱 다이얼로그를 사용하던 작업은 기존 디자인을 유지했다. components/lib/app의 alert, confirm, prompt 호출을 조사했고, 남은 confirm 식별자는 공통 확인 훅 또는 공개 취소의 지역 함수다. 앱이 직접 호출하는 브라우저 기본 대화상자는 없다.

## 동작 계약

AppConfirmProvider가 비동기 확인 결과를 반환한다. 확인 후에만 기존 작업을 실행하며 취소, 닫기, Escape, 바깥 클릭은 false를 반환한다. 확인창이 열린 동안 중복 요청은 취소 처리하고, 계정 재검증으로 provider가 해제되어도 대기 중 작업은 실행하지 않는다. 기존 서버 권한 검사와 revision 충돌 검사는 유지한다.

명단과 즐겨찾기 위에 확인창을 겹쳐 열 수 있다. 취소 시 원래 창과 입력을 유지하며, 명단 참가 취소 후에도 명단을 열어 둬 연속 처리한다. 닫힘 애니메이션 중 안내 내용은 유지하며 원래 버튼 또는 남아 있는 부모 다이얼로그로 초점을 복원한다.

편집 링크는 기본 이동을 먼저 막고 비동기 확인 결과를 기다린다. 승인된 이동에는 beforeunload 확인이 중복되지 않는다.

**예외:** 새로고침, 탭 닫기, 문서 이동을 동반하는 브라우저 뒤로가기의 미저장 경고는 브라우저가 통제하는 beforeunload다. 앱 다이얼로그로 바꿀 수 없으므로 데이터 유실 방지를 위해 유지했다.

## 검증

- 전체 SIDEOUT 테스트: 42개 파일, 413개 테스트 통과.
- 닫힘 애니메이션의 안내 내용 보존 보완 후 관련 테스트 재실행: 4개 파일, 40개 테스트 통과.
- TypeScript 검사 및 제품 빌드 통과.
- 변경 대상 ESLint: 오류 0개, 기존 schedule-editor/team-editor 경고 3개. match-editor의 기존 refs 오류는 이번 범위에서 변경하지 않았다.
- Chrome 및 WebKit, 390 × 844: 미저장 이동 취소/확인, 겹친 명단 확인창, 두 명 연속 취소, 본인 신청 취소, 즐겨찾기 변경 유지/폐기 검증.
- 확인창 너비 358px, 모든 버튼 터치 높이 44px. 넘침 없음. 검증 중 기본 브라우저 다이얼로그 발생 없음.
- Chrome은 원래 취소 버튼, WebKit 터치 환경은 확인창 진입 전 부모 창의 초점 위치로 복귀하는 것을 확인했다. 부모 창 밖으로 초점이 이탈하지 않는다. 캡처는 같은 폴더의 PNG, 치수는 measure.json, 재현은 verify.mjs.
- 첫 명단 검증은 닫힘 애니메이션 전에 부모 창의 접근성을 검사해 실패했다. 확인창이 완전히 닫힌 다음 부모 창을 확인하도록 수정한 후 두 브라우저에서 통과했다. 앱의 명단 유지 동작에 대한 제품 수정은 필요하지 않았다.

실제 회원/신청 데이터 변경 없이 요청을 가상 데이터로 대체하여 쓰기를 검증했다. WebKit 검증은 실제 iPhone Safari 확인을 대신하지 않는다. 최신 빌드를 4180 로컬 서버에 반영했다. 커밋, 병합, 외부 배포는 수행하지 않았다.
