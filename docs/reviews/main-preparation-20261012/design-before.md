# SIDEOUT 디자인 기준

갱신: 2026-10-12. 모드: Operate. 홈·명단·운동 안내·팀 조회는 사용자가 승인한 일정 v4 이미지와 구현이 기준이다. 원본 이미지 및 비교 기록: ../docs/design-review/schedule-home-concepts-20261009/. 계획: ../docs/superpowers/plans/2026-10-09-schedule-v4.md.

## 일정 읽기 화면

- 배경 #f5f6f8, 흰 표면, 본문 #243544, 보조 정보 #697b8b, 주요 행동 #284b6b. 인원 바는 절제된 녹색 #4d7764. 승인된 실제 화면 기반 색상 개선안에 따라 접수는 연한 파랑, 신청 완료·공개는 연한 초록, 대기는 연한 황토색 뱃지로 표시한다. 상태 문구는 신청 버튼과 같은 서버 신청 가능 여부를 따른다. 모임 표시는 작은 단색 이니셜(청록 #557d77, 히어로즈 회갈색 #76736e)과 카드 상단 2px 선으로 식별한다. 모임 색은 안정된 모임 ID 기준이며 업로드 로고는 후속 범위다. 선택 필터만 남색, 미선택 필터는 흰색이다. 글자·배치·카드 높이를 유지한다.
- 제목 16–18px/600, 본문·이름 13–15px/400–500, 보조 정보 11–13px. 실제 조작 영역은 44px 이상이다. 긴 이름·모임·공지에는 단어 줄바꿈과 overflow-wrap을 사용한다.
- 모바일 공통 헤더는 왼쪽 SIDEOUT과 오른쪽 메뉴 버튼만 둔다. 현재 페이지 제목은 본문 시작에 표시한다. 상세·계정·일정 등록/수정·팀편성·경기 순서의 모바일 복귀는 목적지를 명시한 하단 플로팅, 데스크톱 복귀는 제목 위 본문 링크를 유지한다. 메뉴는 기존 하단 시트로 열며 현재 영역을 강조한다. PC는 사이드바를 유지한다. 실제 팀 배정 본문은 유지하며 상단 작업과 하단 복귀는 승인된 2단계 배치를 따른다.
- 모임 필터 → 주 이동 및 날짜 띠 → 날짜별 일정. 모바일 날짜는 카드 밖에서 같은 날짜의 운동을 묶는다. 카드는 상태/마감, 모임/운동 공지, 장소, 입장·시작·종료, 명단 확인과 인원 바, 주요 행동 순서다.
- 신청 버튼과 취소 버튼은 같은 위치에 있다. 공개 열람 권한이 있으면 팀편성·경기 순서 조회 버튼을 표시한다. 운영진 일정 관리 진입은 별도로 유지한다. 행동 버튼에 장식적 화살표를 붙이지 않는다.
- 인원 숫자는 명단 안에 표시한다. 바는 18/21/24/28 단계의 다음 기준까지 차오른다. 이는 시각 표시이며 신청 정원·권한 집행은 서버 계약이 기준이다.
- 명단 확인은 공개 전후 같은 이름을 쓴다. 신청자·대기자 탭, 소속 회원·게스트 그룹, 읽기 권한에 따른 이름/인원 표시를 유지한다. 이름을 볼 수 없는 다른 모임 회원에게는 인원과 열람 제한을 안내한다.
- 명단·운동 공지 모달은 모바일 92dvh까지 사용하고 제목/하단 조작을 유지한 채 내용이 내부 스크롤된다. 홈의 운동 공지 모달은 저장된 자유 문장 공지만 표시한다. 상세에서는 공지를 본문에 3줄로 표시하고 넘칠 때만 펼치기를 제공한다. 공지가 없으면 회원용 영역을 숨기며, 시작 전 수정 권한이 있는 운영자에게 공지 추가/수정 링크를 제공한다. 링크는 기존 일정 수정 공지 탭으로 연결한다. 존재하지 않는 준비물·체육관 이용 정책을 만들지 않는다.
- 팀 조회는 작은 공개 표시, 중립적인 팀 카드, 내 팀/내 행의 작은 강조를 사용한다. 코트·행 토글, 팀 인원과 포지션, 수정 진입을 유지한다. 경기 순서는 아래에 이어지며 별도 바로가기를 두지 않는다. 미공개 예시 선수/팀을 실제 데이터처럼 렌더링하지 않는다.

## 편집과 접근성

- 신청·명단·공개 취소·편집 보호 등 권한과 서버 동작은 디자인 변경 범위에서 바꾸지 않는다. 팀 배정/경기 편집 내부 레이아웃과 저장 의미는 유지한다. 중복 취소는 제거하고 복귀의 미저장 확인과 초안 정리로 통합한다.
- 모든 모달은 키보드 트랩·Escape·닫기 후 원래 버튼으로의 포커스 복귀를 유지한다. 전체 메뉴는 헤더 버튼으로 열고 다른 화면으로 이동할 때 기존 미저장 변경 보호를 유지한다.
- 본문 이동은 같은 문서 안에서 이동한다. 같은 문서의 해시 링크가 임시 편집 상태나 이탈 보호를 해제해서는 안 된다.
- 명단 복원 키는 화면별로 구분하고 한 상세 화면에서는 명단 버튼을 하나만 렌더링한다. 인증 재확인 후에도 명단 창은 하나만 복원한다.
- 일정 홈은 화면 높이에 맞춰 헤더·모임 필터·주 이동·28px 날짜 요약을 고정하고 일정 목록만 스크롤한다. 주·필터 변경은 목록 맨 위, 상세 왕복은 회원·주·필터별 위치 복원, 자동 갱신은 현재 위치 유지가 원칙이다. 다른 일반 본문은 페이지 스크롤, 팀 편집기와 새 일정 등록은 높이가 고정된 내부 스크롤을 사용한다. 기존 일정 정보와 경기 순서는 본문 페이지 스크롤을 유지한다. 모바일 safe area와 고정 하단 버튼을 위한 여백을 확보한다.

## 모바일 복귀 1단계 — 2026-10-10

홈·상세·계정의 모바일 제목 시작 위치를 맞춘다. 홈은 복귀 버튼 없이 유지하고, 상세·계정만 목적지가 적힌 하단 플로팅 복귀를 사용한다. 페이지 끝 내용이 버튼 위로 올라올 수 있도록 하단 여백을 확보하고 오버레이가 열리면 복귀 버튼을 숨긴다. 데스크톱 복귀는 본문 위치를 유지한다.

일정 등록/수정·팀편성·경기 순서 편집은 기존 복귀와 저장·취소·공개 영역을 유지한다. 편집 화면의 하단 복귀 추가/통합은 비교 후 별도 적용한다. 비교 자료: ../docs/reviews/mobile-navigation-phase1-20261010/index.html.

## 편집 복귀 2단계와 등록·공지 — 2026-10-12 승인 적용

- 팀 편집 상단: 저장·공개/다시 공개. 공개 중에는 공개 취소만 표시한다. 기존 확인/권한 규칙은 유지한다.
- 일정 정보/경기 순서 상단: 저장. 모바일 하단: 운동 상세로. 저장은 편집 유지, 이동은 미저장 확인을 거친다.
- 등록 상단: 준비로 저장·모집 시작. 장소/시간 기본값 요약, 변경 펼침, 신청 마감, 우선/정원 설정 요약, 선택 공지를 하나의 스크롤 본문에 둔다. 최초 저장 전 복귀는 일정 홈, 생성 후는 해당 상세다.
- 저장 처리 중 복귀 링크를 숨기고 다른 내부 이동도 차단한다. 모바일 입력 초점/모달 중에는 배경 복귀를 숨긴다. 경기 드래그 중에도 숨긴 뒤 종료 시 복원한다.
- 위 1단계의 편집 화면 유지 유보는 이 승인으로 대체된다. 실기기 Safari 키보드·가로모드 확인은 별도다. 근거: ../docs/reviews/approved-editors-20261012/REPORT.md.

## 공통 일정 정보와 B안 작업 버튼 — 2026-10-12 최종 승인

이 결정은 위 2단계의 상단 저장/별도 하단 복귀와 등록 요약 펼침 구성을 대체한다.

- 모바일 편집의 돌아가기·저장·공개/모집 조작은 하단에 개별 둥근 버튼으로 모은다. 별도의 흰색 바탕 바는 두지 않는다. 주요 작업은 짙은 색, 복귀는 흰색. PC는 상단 조작 그룹을 사용한다.
- 일정 조회는 한 카드/한 수정 버튼, 등록과 수정은 같은 카드·같은 직접 입력 폼이다. 장소·시간/신청 정보/운동 공지 순서와 데이터를 공유한다. 등록과 기존 일정 수정 모두 고정 제목과 내부 본문 스크롤을 사용한다.
- 입력칸 포커스만으로 복귀를 숨기지 않는다. 실제 키보드 높이 변화가 있을 때 키보드 닫기/저장을 노출한다. 모달과 경기 드래그 중 배경 버튼 숨김, 저장 중 복귀 차단을 유지한다.
- 마감 날짜·시간은 읽기 쉬운 본문 크기로, 한국 날짜 기준 D-day는 작은 보조 배지로 표시한다. 공개 시 접수 종료 우선. 대기 접수 권한은 기존 서버 규칙을 따른다.
- 실기기 확인 범위와 증거: ../docs/reviews/unified-schedule-20261012/REPORT.md.

### 플로팅 버튼 크기와 본문 중첩 — 2026-10-12 후속 승인

모바일 작업 버튼은 단독 ‘운동 일정으로’와 동일한 44px 높이·13px/400 글자·24px 둥근 모서리로 한다. 균등하게 화면을 채우지 않고 콘텐츠에 맞춘 폭으로 가운데 모은다. 편집기 본문은 버튼 뒤까지 이어지며, 마지막 항목의 가림 방지 여백은 외부 고정 공간이 아닌 스크롤 내용 끝에 둔다. 버튼 주변 배경/블러를 추가하지 않는다. 검증: ../docs/reviews/floating-controls-20261012/REPORT.md.

### 플로팅 배경의 옅은 페이드 — 2026-10-12 후속 요청

사용자의 투명 그라데이션 요청에 따라 모바일 편집 작업 그룹 뒤에만 배경색을 0%→28%→62% 불투명도로 올리는 짧은 페이드를 적용한다. 버튼 본체와 글자는 불투명하게 유지한다. 별도 높이나 스크롤 공간을 만들지 않으며, 배경은 터치 이벤트를 받지 않는다. 모달 표시 시 버튼 그룹과 함께 숨긴다. PC에는 적용하지 않는다. 이는 직전 ‘배경을 추가하지 않는다’ 원칙에 대한 명시적 후속 변경이다. 검증 근거: ../docs/reviews/floating-fade-20261012/browser.json.

### 하단 플로팅 페이드 통일 — 2026-10-12

단독 ‘운동 일정으로’ 복귀 버튼에도 편집 작업 그룹과 같은 화면 너비의 페이드를 적용한다. 공통 --floating-control-fade를 사용하며 강도는 0%→42%→82%로 높인다. 모바일에서만 적용하고 버튼 크기·입력/스크롤 동작은 유지한다. 검증: ../docs/reviews/floating-unified-fade-20261012/browser.json.

### 준비 일정의 상세 확인 — 2026-10-12

홈 ‘이어서 준비’는 운동 상세로 들어간다. 모임 기본값으로 시작해 저장된 일정 정보를 읽기 카드로 보여주며, 이미 저장한 수정값을 보존한다. ‘모집 준비 중’과 회원 미공개 상태를 표시하고, 일정 정보의 수정 버튼을 통해서만 편집한다. 하단 공통 플로팅 버튼은 돌아가기/모집 시작이다. 시작 성공 후 같은 상세에서 일반 모집/명단/팀편성 관리로 전환하며, 팀편성 공개는 별도 동작이다. 검증: ../docs/reviews/prepared-detail-20261012/REPORT.md.

### 신규 일정도 상세 먼저 — 2026-10-12

새 ‘모임 등록’도 기존 ‘이어서 준비’와 같은 운동 상세에서 시작한다. 모임 기본 일정 정보를 읽기 상태로 확인하고, 필요할 때만 일정 수정으로 들어간다. 회원 미공개/모집 준비 중 상태와 하단 모집 시작을 공유한다. 화면 진입만으로 저장하지 않으며 준비로 저장 또는 모집 시작 시 생성한다. 저장 전 편집 복귀는 기본 정보 상세, 저장 후에는 생성된 실제 상세로 연결한다. 검증: ../docs/reviews/new-preparation-20261012/REPORT.md.

### 일정 수정은 저장만 — 2026-10-12

신규/준비/모집 중 일정의 편집 화면은 제목을 ‘일정 정보 수정’으로 통일하고, 공통 돌아가기 외 작업 버튼은 ‘저장’ 하나만 제공한다. 저장은 기존 phase를 유지하고 편집 화면에 머문다. Enter로 폼을 제출해도 동일하다. 모집 시작은 새/기존 준비 일정의 운동 상세에서만 제공한다. 검증: ../docs/reviews/schedule-save-only-20261012/REPORT.md.

### 모집 시작 확인 — 2026-10-12

새 일정과 기존 준비 일정의 모집 시작은 공통 상세 화면에서 브라우저 확인창으로 안내한다: ‘회원들에게 일정이 공개되며, 참석 신청을 받을 수 있습니다. 모집을 시작할까요?’ 취소는 어떤 쓰기도 수행하지 않으며 확인 후에만 기존 모집 시작 작업을 실행한다. 검증: ../docs/reviews/recruitment-confirm-20261012/REPORT.md.

### 모집 시작 앱 다이얼로그 — 2026-10-12

브라우저 기본 확인창을 제거하고 팀편성 공개 취소와 동일한 공통 Dialog/버튼을 사용한다. 제목 ‘모집을 시작할까요?’, 안내 ‘회원들에게 일정이 공개되며, 참석 신청을 받을 수 있습니다.’, 하단 취소/확인 순서. 확인만 모집을 시작하며 취소/닫기/Escape는 쓰기 없이 닫는다. 닫은 뒤 모집 시작 버튼에 초점을 복원하고 다이얼로그 표시 중 뒤의 플로팅 버튼은 숨긴다. 검증: ../docs/reviews/recruitment-app-dialog-20261012/REPORT.md.

### 남은 브라우저 확인창 통일 — 2026-10-12

참석/대기 취소, 운영진 명단 취소, 즐겨찾기 변경 폐기, 편집 최신 정보 불러오기, 미저장 화면 이동도 공통 앱 다이얼로그를 사용한다. 기존 창과 입력은 취소 시 유지하고 확인 후에만 작업한다. 취소 계열은 왼쪽, 실행은 오른쪽이며 실제 신청 삭제만 파괴적 동작 색을 사용한다. 버튼은 최소 44px. 겹친 명단/즐겨찾기 창은 확인창 종료 후 초점을 복원한다. 새로고침·탭 닫기 등 브라우저가 통제하는 beforeunload 경고는 미저장 데이터 보호를 위해 유지한다. 검증: ../docs/reviews/common-confirm-dialogs-20261012/REPORT.md.
