## 목적과 화면 흐름

운영자가 모바일에서 세 팀의 현재 배치를 보며 처음부터 연속으로 선수를 배정한다. B안의 보드는 하나이며 상단에서 `포지션별 배정`과 `자율 배치`를 전환해도 이미 배정한 선수는 유지된다.

| 방식 | 순서 | 후보와 자리 표현 |
|---|---|---|
| 포지션별 배정 | 세터 → 레프트 → 센터 → 라이트 | 현재 포지션 자리만 보이고, 후보는 주·부·전체로 좁혀 볼 수 있다. |
| 자율 배치 | 세터 → 나머지 선수 | 세터를 먼저 배정한 뒤 A팀 선수 1~5, B팀 선수 1~5, C팀 선수 1~5 순으로 빈자리를 채운다. 후보를 포지션으로 거르지 않는다. |

두 방식 모두 선수의 `배정`을 누르면 현재 자리 이후의 다음 빈자리로 이동하고, 끝에서 앞쪽으로 순환한다. 다음 단계로는 운영자가 직접 이동하며 빈자리를 남겨도 된다. 세터 자리가 비어 있을 때는 세터 주 포지션 선수를 자율 배치의 일반 선수 후보에서 잠시 제외한다. 이미 배정된 선수는 후보 목록에서 위치를 보여주고 다시 선택할 수 없다. 자리 타일의 X는 확인창을 거쳐 해제한다.

자율 배치에서 `선수 1~5`는 **편성 순서**를 뜻한다. 코트의 해당 칸에 선수의 포지션을 확정했다는 의미가 아니다. 팀 결과의 행·코트 보기에서도 이 이름을 유지하고 안내 문구로 구분한다. 선수 카드의 주·부 포지션은 참고 정보로 남긴다.

## 모바일 내비게이션

화면 아래 고정 공간에 `이전: …` · `전체 팀` · `다음: …`을 둔다. 현재 단계가 처음/끝이면 해당 방향 버튼만 숨기고 가운데 `전체 팀`의 위치는 유지한다. 전체 팀 화면에서는 같은 하단 공간의 `배정으로`로 돌아간다. 전체 팀의 빈자리를 직접 눌러도 그 자리의 배정 화면으로 이동한다.

자율 배치에는 세터 3명 요약을 현재 편성 위에 계속 보여준다. 다섯 줄짜리 팀판이 후보 목록을 과하게 가리는 낮은 화면에서는 고정을 풀어 스크롤하게 한다. 하단 이동 버튼은 안전 영역을 고려해 고정한다.

## 자동 배치 샘플

`자동 배치` 버튼은 확인창을 연다. 실행하면 **이미 배정된 선수와 자리를 유지하고 빈자리만** 가상 신청자의 주 포지션 → 부 포지션 → 나머지 가용 선수 순으로 결정적으로 채운다. 세터 자리를 먼저 채우고 중복 배정하지 않는다. 결과는 바로 전체 팀 보기에서 검토한다. 실력 점수·모임 우선권·팀별 균형 점수는 반영하지 않는다. 현재 18명·3팀 샘플용 편성 로직이므로 운영 데이터에 대한 자동 초안이나 공개 기능으로 해석하면 안 된다.

규칙 기반 헬퍼의 팀 수, 6~7명 구성, 교대, 대기자, 우선 편성 보장, 부족한 포지션과 평가 점수는 [팀편성 헬퍼 기획](TEAM_HELPER_PLAN.md)에 남아 있다. 이번 버튼은 이 계획의 제한적 시연이며, 전체 헬퍼 구현을 완료하지 않았다.
