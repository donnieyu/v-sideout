# SIDEOUT 팀편성 기획서

버전 0.5 · 2026-09-24 · **B 연속 배정 발전 / A 참고본 보존 / 운영 앱 미적용**

최신 상태: 사용자가 포지션별 배정을 기본 흐름으로 선택했고, [B v4 모바일 화면](MOBILE_POSITION_FLOW_V4.md)에 요약 배치판과 스크롤 선수 풀을 구현했다. 자율 배치 화면 선택은 보류했고 A/B 전환 탭은 제거했다. [모바일 높이 검토](MOBILE_ALLOCATION_HEIGHT_REVIEW.md)와 아래 초기 비교는 결정 경위 자료다.

제품 동작을 정리한 뒤 사용자의 제작 요청에 따라 [모바일 A/B 체험본](MOBILE_ALLOCATION_AB_EXPERIENCE.md)을 별도 경로에 구현했다. 현재 목업을 그대로 최종 설계로 인정하지 않는다. 사용자 확정 규칙, 실제 코드 동작, 개선 제안을 아래에서 구분한다. 기능 상세와 인수 조건은 [팀편성 기능 명세서](TEAM_ALLOCATION_SPEC.md)를 따른다.

## 0. 최신 검토 방향

최신 사용자 승인에 따라 [B안 v2 순환식 연속 배정](MOBILE_ALLOCATION_CONTINUOUS_V2.md)을 구현했다. 현재 자리 이후부터 빈자리를 순환 탐색하며 배정 즉시 편집본에 반영한다. 이전 포지션 요약, 자리 타일의 X 확인창, 수동 다음 포지션 이동을 제공한다. 아래 A/B 초기 비교의 자리별 적용 규칙은 B v2에서 대체되며, 초안 저장·공개 분리는 그대로 유지한다.

사용자는 A/B 비교 진행을 선택했고 **모바일에서 처음 전체 팀을 편성하는 과정**을 최우선으로 정했다. 한두 명 수정의 상세 과정은 최초 편성 완성 후 기획한다. 최종 제품은 대화·선택으로 헬퍼가 편성을 돕고 이후 수동 조정하는 방향이다. LLM 구현은 후속이다.

새 비교 기준은 [모바일 최초 편성 A/B 검토](MOBILE_ALLOCATION_AB_REVIEW.md)다. A는 자리별 선택창, B는 모바일 상단 팀 요약+하단 연속 배정 후보 영역을 비교한다. **B의 구조와 헬퍼 경험 선설계/수동 기능 선개발 순서는 제안**이며 비교 목업 제작 후 사용자 방향 선택을 기다린다. 운영 UI에는 적용하지 않았다. 기존 데스크톱 옆 패널 추천을 모바일에 그대로 적용하지 않는다.

## 1. 목표와 작업 범위

운영자는 한 운동 회차의 참가 후보를 보고 여러 팀을 비교하면서 수동으로 배정한다. 저장한 초안을 검토한 다음 공개한다. 회원은 권한이 있는 회차의 공개 결과에서 자신의 팀·배정 포지션·경기 순서를 확인한다.

이번 기획 범위는 일정 상세 안의 팀편성 편집, 선수 선택창, 초안 저장·공개, 회원 결과 화면이다. 모임 홈, 계정 발급, 모집 등록은 연결 조건만 다룬다. 자동 편성 헬퍼·AI·실력 투표는 후속 단계다. 실제 출석과 신청, 편성 결과를 동일한 기록으로 취급하지 않는다.

성공 기준:

- 다른 팀에 누가 들어 있는지 보면서 비교·이동할 수 있다.
- 현재 배정, 후보 탐색, 변경 적용, 초안 저장, 공개의 의미가 구분된다.
- 선수의 중복·유실 없이 배정/교체/이동/해제가 동작한다.
- 수정 중인 내용이 회원 공개본에 섞이지 않는다.
- 모바일에서도 검색·현재 배정·확정 행동에 접근할 수 있다.

## 4. 유지할 제품 규칙

| 항목 | 확정된 기준 |
|---|---|
| 진입 | 별도 편성 페이지를 주 동선으로 만들지 않고 일정 상세의 팀편성 영역에서 편집 |
| 여러 팀 비교 | 팀 하나만 표시하는 탭 대신 모든 팀을 함께 배치. 좁은 화면은 세로로 이어짐 |
| 보기 전환 | 코트/행 보기는 동일한 배정 데이터를 표현. 전환으로 배정이 바뀌지 않음 |
| 기본 자리 | 레프트2, 센터2, 라이트1, 세터1. 네트에 가까운 전위 오른쪽이 세터 전용 자리 |
| 세터 표기 | `세터`만 표시. `라이트 자리` 등의 보조 설명 없음. 행 보기는 세터가 먼저 |
| 교대 | 코트 아래 여러 줄 추가 가능. 빈 교대 줄만 전체 저장 시 제거. 교대 순서는 현장에서 결정 |
| 역할 | 프로필 주/부 포지션은 추천 정보. 자리 배정으로 회원 프로필을 변경하지 않음 |
| 수정 Dialog | 현재 배정 인원을 상단에 강조, X로 해제, 목록에 중복 표시하지 않음 |
| 후보 상태 | 미배정 강조, 이미 배정된 선수는 배정됨과 팀/역할 표시. 이동 가능 |
| 제목 | 클릭한 자리 기준 `A팀 · 센터에 배정`. 세터가 함께 나온다는 설명은 생략 |
| 후보 순서 | 미배정 우선. 그 안에서 신청자/대기자 구분 및 포지션 우선순위 유지 |
| 신청·대기 | 마감 후 또는 공개 후에는 시작 전까지 대기 접수. 초안 배정만으로 일반 신청 기록을 변경하지 않음 |
| 열람 | 일반 신청자는 공개 결과 확인 가능. 미신청자/미배정 대기자는 불가. 대기자는 공개본에 배정된 후 가능 |
| 취소 | 일반 마감 후 또는 공개 후 본인 참석 취소 불가. 반복 규칙 설명을 모집 카드에 되살리지 않음 |
| 개인정보 | 신청 순번/시각, 불참/미응답, 실력, 프로필 주/부 포지션은 운영용. 공개 배정 역할과 다름 |
| 소속/권한 | 소속은 하나 또는 무소속. 마스터는 소속 없음. 운영자의 복수 관리 권한은 회원 복수 소속이 아님 |
| 우선 보장 | 우선 기간에 신청한 정규 소속 회원의 보장은 공개 검증 조건. 후보 정렬이나 자동 초안이 이를 취소하지 않음 |

신입과 계정 없는 임시 인원은 기본적으로 정규팀 밖의 함께 참여하는 인원이다. 마스터·회장은 선택적으로 정규팀에 넣을 수 있다. 다른 모임 소속의 정상 회원은 임시 인원과 구분한다. 모임원 전체 검색을 통한 대리 편성도 마스터·회장 범위이며 추가 운영진에게 자동으로 부여하지 않는다.

## 5. 운영자의 일관된 작업 흐름

1. **회차 확인:** 일정 상세의 모임명·날짜를 확인하고 팀편성 `수정` 진입.
2. **전체 구성 확인:** 팀 수, 배정 수, 미배정 신청자/대기자, 우선 보장 미배정 인원을 운영자 관점에서 확인.
3. **세터부터 검토:** 고정된 세터 자리가 먼저 읽히게 하되 다른 자리 편집을 막지 않음. 별도 필수 포지션 분배 단계는 추가하지 않음.
4. **자리 편집:** +/수정 → 검색·필터 → 타일 배정 또는 X 해제 → Dialog 확정 → 편집 보드에 반영.
5. **전체 비교:** 코트/행을 바꾸며 팀 간 이동, 교체, 교대 추가. 필요하면 반복.
6. **초안 저장/저장:** 최초는 `초안 저장`, 기존 편성 수정은 `저장`. 빈 교대 줄을 정리하고 운영용 저장본을 갱신. 회원 공개본은 그대로.
7. **검토 후 공개:** 자격·중복·우선 보장 등 검증을 통과한 결과를 공개본으로 기록.
8. **회원 확인:** 회원은 공개본만 조회. 재편집 중에는 기존 공개본 유지.

Dialog 확정은 전체 초안을 영구 저장하거나 공개하는 동작이 아니다. 초안 저장 역시 공개가 아니다. 이 구분이 모든 화면과 버튼의 기준이다.

## 6. 화면 구성안

### A. 일정 상세 — 운영자 편집

```text
[상단 고정] 경로 / 모임명 / 운동 날짜
정보·공지 영역

팀편성                         [취소] [초안 저장/저장] [공개]
[코트로 보기] [행으로 보기]                [팀 추가]
배정 / 미배정 신청자 / 대기자   · 우선 보장 미배정 상태

       A팀 · 총원             B팀 · 총원             C팀 · 총원
       ── NET ──             ── NET ──             ── NET ──
    레프트 센터 세터        레프트 센터 세터        레프트 센터 세터
    레프트 센터 라이트      레프트 센터 라이트      레프트 센터 라이트
       교대 줄…                교대 줄…                교대 줄…
      [+ 교대 자리]           [+ 교대 자리]           [+ 교대 자리]

함께 참여하는 인원: 신입 / 임시 인원 (정규팀 배정과 별도)
경기 순서 (대진/시간 정보, 편성으로 자동 생성하지 않음)
```

최초 편성은 `초안 저장`, 기존 초안/공개 편성에서 `수정`에 들어온 경우는 `저장`이다. 두 동작 모두 운영용 초안만 저장한다. 새로운 정보 배치와 운영용 집계는 제안이며 아직 화면에 적용하지 않는다. 세터 우선 분배 전용 버튼은 필수 기능에서 제외하고 후속 헬퍼와 함께 검토한다.

자리 타일은 배정 역할·이름·소속과 +/수정을 보여준다. 팀 제목/이름 중심 정렬, 팀 총인원만 표시하고 포지션별 인원 그룹을 만들지 않는다. 실제 경기 시작 로테이션을 지정하는 전술판으로 사용하지 않는다.

### B. 선수 선택 Dialog

```text
A팀 · 센터에 배정
[현재 배정 또는 변경 예정: 이름 / 소속]             [X]
[검색]
[주 포지션] [부 포지션 포함] [전체 후보]  [미배정만]

미배정 · 신청자
  이름 / 소속 / 주·부 포지션       미배정            [배정]
미배정 · 대기자
  …
배정됨 · 신청자 / 대기자
  이름 / 소속 / 주·부 포지션       B팀 · 센터        [배정]

필요할 때 이동/교체 영향 표시
                                         [닫기] [적용]
```

Q-01에서 `적용`으로 확정했다. 현행 목업의 `저장` 표기는 이후 구현에서 변경한다. 상단 닫기 X를 다시 추가하지 않는다. 현재 선수 옆 X는 배정 해제 기능이므로 닫기와 혼동하지 않게 접근성 이름을 부여한다.

### C. 회원 결과

같은 일정 상세와 동일한 공개 배정 데이터를 사용한다. 코트/행 전환, 팀명·총원·이름·소속·이번 회차 역할, 본인의 `나` 표시, 교대 선수와 경기 순서를 제공한다. 편집/+·후보 목록·초안·프로필 평가·접수 순서는 숨긴다. 세터는 전위 오른쪽, 행 보기는 세터 우선이다.

공개 전에는 실제 선수 없이 자리 예시와 `아직 팀편성이 공개되지 않았어요.`를 표시한다. 열람 권한이 없는 사람에게는 실제 이름/대진 대신 `참석자만 팀편성을 확인할 수 있어요.`를 표시한다. 과거 운동은 당시 공개 기록을 보여주고 현재 프로필 변경으로 덮어쓰지 않는다. 이 결과 화면은 포지션 목업에 아직 연결하지 않았다.

## 7. 확정 결정과 남은 검토 항목

| ID | 현행 목업 | 사용자 확정 결정 | 상태 |
|---|---|---|---|
| Q-01 저장 명칭 | 기존 v8: Dialog 저장 / 전체 저장 / 통합 목업 공개 | Dialog `적용`; 최초 `초안 저장`; 기존 편성 `수정 → 저장`. 공개 별도 | 새 A/B에 `적용` 반영. 전체 저장·공개 연결은 후속 |
| Q-02 선택 중복 | 기존 v8: 본문 선택 토글 + 별도 배정 | 본문 선택 토글 제거. 배정 버튼으로만 임시 배정, X로 해제 | 새 A/B 반영. 기존 v8은 보존 |

다음 설계 단계에서 검토할 사항은 별도로 둔다. 이번 초안에서 임의로 확정하지 않는다.

- **Q-03 닫기/바깥 클릭:** 현행은 미적용 변경을 버린다. 추천은 하단 닫기·Escape는 취소, 바깥 클릭은 변경이 있을 때 닫지 않아 오조작 방지. UI 설계 때 비교.
- **Q-04 센터/라이트 후보 범위:** 고정 세터 자리가 생겼지만 현재 주 포지션 필터는 여전히 센터/라이트에 주 세터를 포함한다. 유지가 확정된 부분은 센터 후보의 순서다. 최종 추천은 주 포지션 필터의 예외 포함을 명시적으로 정리하는 것. 변경 전 사용자 확인.
- **Q-05 인원/빈자리 공개:** 6명 미만·8명 이상·세터 역할 부적합은 저장을 막지 않는 운영 판단 정보로 제안한다. 공개를 막을지 경고만 할지는 별도 확인. 빈 팀/중복/우선 보장 누락은 기존 제한 유지.
- **Q-06 공개 결과의 별도 참여 인원:** 신입·임시 인원을 함께 표시하는 요구는 유지. 공개 가능한 이름·분류·표시 범위는 기능 연동 전에 확인.

## 8. 진행 순서와 변경 원칙

단계별 결과물·완료 기준·사용자 선택 시점은 [단계별 작업·검토 보고서](TEAM_ALLOCATION_DELIVERY_PLAN.md)에 정리했다. 아래는 개괄이며, 실제 진행 순서는 해당 보고서를 따른다. A/B 제작은 이미 요청된 범위이며 구체적인 두 안을 체험한 뒤 방향을 선택한다.

| 단계 | 산출물 | 완료 조건 |
|---|---|---|
| 1 기획 검토 (현재) | 이 기획서 + 기능 명세서 | Q-01/Q-02 확정 완료. 나머지 상태/권한/용어 검토 후 문서 기준선 합의 |
| 2 모바일 A/B 구조 (현재 비교) | 자리별 선택창 A / 팀 요약+연속 배정 B | 최초 편성 과제로 비교,같은 정책·샘플·행동 의미 |
| 3 제한된 모바일 인터랙션 목업 | 세터3명→센터 일부→전체 검토를 A/B로 수행 | 방향 선택 후18~28명 최초 편성 검증 |
| 4 최초 편성 완성·일정 상세 통합 | 선택된 모바일 수동 편성과 회차/초안/공개 연결 | 권한·보장·대기·결과 조회 검증,이후 한두 명 수정 상세 기획 |
| 5 운영 연결 | 실제 인증·서버 저장·계정 발급 | 목업 역할 선택을 실제 보안으로 대체 |
| 6 헬퍼 확장 | 큰 경험/공통 경계는 선설계 제안, 구현은 코드 초안→LLM 순서 | 수동 편성/공개 규칙 재사용. 평가 투표는 별도 후속,자동 공개 금지 |

이후 변경은 기능 ID를 기준으로 **바꾸려는 문제 → 영향 받는 상태/화면 → 제안 → 결정 → 구현/검증** 순서로 기록한다. 보이는 버튼 하나를 바꾸더라도 저장·권한·모바일·결과 화면에 미치는 영향을 먼저 확인한다. 작은 색/간격 조정은 승인된 구조 안에서 진행하며, 행동 의미가 바뀌면 명세부터 갱신한다.

## 9. 최초 기획 작성 당시의 한계

문서 작성과 코드 대조만 수행했다. 새 UI나 자동 편성 기능을 구현하지 않았다. 이전 52개 모델 검사 및 브라우저 확인은 해당 시점의 목업 근거이며, 이 새 명세 전체가 검증되었다는 의미가 아니다. 실제 인증/계정 발급, 서버 권한/영구 저장, 동시 편집, 신입·임시 인원 연결, 우선 보장 공개 검증의 포지션 목업 연결, 회원 결과 통합은 아직 남아 있다.
