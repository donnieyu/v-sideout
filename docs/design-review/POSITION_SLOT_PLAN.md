## 구성

팀 제목과 총인원은 중앙 제목/오른쪽 인원 기존 배치를 유지한다. 큰 포지션 그룹과 포지션별 인원 집계는 추가하지 않는다. 각 행은 `포지션 | 이름·소속 | +` 구조이며 좌우 내부 여백12~16px,행 높이 최소64px,이름 중앙 정렬,+ 터치 영역44px로 만든다. 빈 자리는 `인원 선택`,배정된 자리는 이름·소속을 보여준다. 편집 종료 후에도 같은 행 정렬을 사용해 배치가 튀지 않도록 한다.

최신 결정: 기본 여섯 자리는 **레프트2·센터2·라이트1·세터1**로 고정한다. 코트의 전위 오른쪽은 빈 상태에서도 세터 자리이며,후위 오른쪽은 라이트다. 세터가 차지할 센터/라이트 자리를 고르는 설정은 없다. 프로필 주 포지션과 이번 편성의 배정 역할은 구분한다. 센터 자리에 주 포지션 세터인 선수를 골라도 그 칸은 센터로 유지한다.

- 센터 선택창 제목은 `센터에 배정`이다. 세터를 함께 표시한다는 설명은 제거한다.
- 센터 후보는 각 신청자/대기자 그룹 안에서 주 포지션 센터 → 부 포지션 센터 → 그 외 세터 순서다. 부 포지션 인원은 기존 `부 포지션 포함` 필터로 표시한다. 주 포지션 필터에서는 센터 다음 세터다.
- 세터 전용 자리에서는 주 포지션 세터를 기본 후보로 표시한다. 부 포지션 포함/전체 후보 확장은 유지한다.
- 행 보기도 빈 세터 자리를 포함하여 세터가 맨 위다. 실제 선수가 주 포지션 세터라는 이유로 다른 센터/라이트 자리 이름을 세터로 바꾸지 않는다.
- 교대 인원은 코트 밖에 여러 줄로 추가할 수 있다. 모든 포지션을 선택할 수 있으며 교대 순서는 지정하지 않는다.

## 여러 팀 비교와 + 선택 흐름 (최신)

A·B·C팀을 동시에 배치한다. 넓은 화면은3열, 중간 화면은2열, 모바일은 모든 팀을 세로로 이어서 표시한다. 한 팀 탭으로 다른 팀을 숨기지 않는다. 최대4팀까지 추가할 수 있다. 코트/행 보기 전환은 같은 배정 데이터를 사용한다.

1. 자리의 + 또는 수정 아이콘을 누르면 공통 shadcn Dialog가 열린다. 이름·소속·포지션 검색, 주 포지션/부 포지션 포함/전체 후보, 미배정 인원만 필터를 제공한다.
2. 신청자 다음 대기자를 별도 목록으로 표시한다. 실제 연동 시 각 목록 안의 접수 순서를 보존한다. 현재 비교 목업은 가상 회원 배열 순서다.
3. 다른 팀에 배정된 선수도 현재 팀·자리를 표시해 비교할 수 있다. 선택 후 `이동하여 배정`으로 확정하며 기존 자리에서는 빠진다.
4. 대상 자리가 이미 차 있으면 기존 선수가 미배정으로 돌아간다는 안내를 확정 전에 표시한다. 자동 맞교환은 하지 않는다.
5. 선택창을 닫으면 눌렀던 자리 버튼으로 포커스를 돌린다. 작은 화면에서도 검색·하단 확정 버튼을 유지하고 후보 목록만 스크롤한다.
6. 주·부 포지션/평가 정보는 운영진 선택창에만 표시한다. 신입/임시 인원 분리와 마스터·회장의 예외 배정 권한은 기존 정책을 유지한다. 이 비교 목업에는 해당 권한·회차 데이터 연결을 아직 하지 않았다.

장점: 다른 팀 구성과 빈자리를 함께 비교할 수 있고, 세터 자리 설정 없이 센터·라이트에서 자연스럽게 선택한다. 주의: 모바일 코트형은 세로 길이가 길어 여러 팀 비교에는 행형이 더 효율적이다. 실제 로테이션을 확정하는 전술판으로 해석하지 않도록 한다.

## 신청·열람 규칙 (이번에 로컬 구현)

일반 신청 기간이며 미공개→참석 신청. 마감 후 또는 공개 후→대기자 등록(운동 시작 전까지). 대기 등록만으로 일반 신청자에 합치거나 공개 편성 열람 권한을 주지 않는다.

홈 팀편성 버튼은 일반 신청자에게만 공개 전 비활성/공개 후 활성 표시한다. 미신청자/미배정 대기자는 표시하지 않는다. 대기자는 운영자가 배정하고 **공개**한 편성에 본인이 포함되어야 버튼과 상세 열람 권한이 생긴다. 초안에 배정하거나 저장만 한 경우에는 계속 비공개다. 초기 일반 신청자는 공개 후 열람 가능하며,운영 권한자는 관리 목적으로 열람한다. 이미 참가하던 회원의 취소 제한을 유지한다.

미신청자가 다른 모임 상세에 들어오면 이름과 경기 순서 대신 `참석자만 팀편성을 확인할 수 있어요.`를 표시한다. 실제 서비스에서는 서버 응답 단계에서도 동일한 권한을 적용해야 한다. 현재 브라우저 목업은 인증·서버가 없는 샘플이다.


## 초기 비교 기록: 네트가 있는 코트 배치 (세터 자리 규칙은 위 최신 결정으로 대체)

사용자가 기억한 기존 구현은 `web/app/team-board.tsx`의 court-floor/net-line/court-zones와 `web/lib/model.ts`의 courtSlots이다. 기존 운영 코드는 읽기 참조만 했으며 수정하지 않았다. 기존 도식은 네트를 위에 두고 레프트/센터/라이트를3열×2행으로 배치하고,세터는 센터 또는 라이트 자리 한 칸을 차지한다.

별도 목업에 `행으로 보기 / 코트로 보기`를 추가했다. 동일한 자리와 선택 데이터를 유지하며 전환한다. 현재 추천은 **회원 공개 화면의 기본을 코트형**,운영자는 같은 코트의 +에서 편집하되 필요할 때 행형으로 전환하는 방식이다. 실제 적용은 사용자 선택 후 진행한다.

- 네트 위쪽,밝은 녹색 코트,6개 자리3열×2행. 실명·소속은 가운데 정렬하고 포지션은 상단 작은 라벨로 표시한다.
- 세터 자리만 조금 진한 녹색으로 강조한다. 행형의 세터 맨 위 규칙은 유지하되,코트형에서는 점유한 센터/라이트 역할을 유지하면서 전위에 놓는다. `세터 맨 위`와 공간 배치를 동시에 강제하면 선수 수가 중복되거나 경기 위치와 혼동되므로 두 보기의 규칙을 구분한다.
- 교대 인원은 코트 밖 별도 자리로 표시하고 로테이션 순서를 강제하지 않는다. 코트에7명을 동시에 배치하지 않는다.
- 코트의 +도 동일한 주 포지션 우선 필터와 신청자→대기자 순서를 사용한다. 부 포지션 확장/다른 팀에서 이동/프로필 정보 비공개 규칙은 행형과 같다.
- 코트는 고정 전후위나 첫 로테이션을 확정하는 전술판이 아닌 구성도다. 편집 화면에 짧은 설명을 둔다. 향후 실제 시작 로테이션을 설정한다면 별도 정보로 설계해야 한다.
- 데스크톱은 팀별 코트2~3열,모바일은 코트1개씩 세로 배치. 이름을 줄이는3개 코트 가로 스크롤을 기본으로 삼지 않는다. 선택 버튼은44px 유지.

장점: 배구 모임의 성격이 드러나고 내 위치·팀을 찾는 재미가 있으며 빈자리가 잘 보인다. 단점: 행형보다 높이가 크고,주 포지션과 실제 전후위 로테이션을 혼동할 수 있다. 운영자의 여러 팀 선수 비교 속도는 행형이 유리하다. 두 보기의 저장 데이터를 공유하면 디자인 차이 때문에 권한이나 배정 결과가 달라지는 문제를 피할 수 있다.

## 결과 화면 방향과 다음 단계

현재 별도 목업은 **운영자 배정 화면**을 비교하는 단계다. 회원 결과 화면은 동일한 코트/행 배정 데이터를 사용하되 자리 추가·수정·후보 필터·운영용 대기 표시는 제거하는 방향을 제안한다. 팀명·총원·이름·소속·이번 회차 포지션만 남기고, 교대 선수는 코트 아래에 둔다. 일정 상세의 모임명/날짜 고정 헤더와 아래 경기 순서 표에 연결한다. 결과 열람에는 기존 참석자/공개본 권한 규칙을 그대로 적용한다. 결과 화면의 실제 연결은 아직 하지 않았다.

2026-09-23 후속 요청: 편성 화면과 결과 화면을 확정한 다음 **코드 기반 팀편성 헬퍼**를 설계한다. 지금 자동 배정이나 AI 연동을 추가하지 않는다. 자세한 후속 범위는 [TEAM_HELPER_PLAN.md](TEAM_HELPER_PLAN.md)를 따른다.

검증: 별도 Vite/TypeScript 빌드 및 포지션 모델18검사 통과. 실제 브라우저에서 센터·라이트 후보에 세터 포함, 다른 팀 선수 검색/이동, 행/코트 전환 배정 유지 확인.320px에서3팀 유지·가로 넘침 없음·Dialog 화면 내 배치·닫기 후 원래 버튼 포커스 복귀 확인. 가상 데이터의 메모리 상태이며 새로고침 시 초기화된다. 운영 web 및 본 앱의 팀편성 UI는 변경하지 않았다.

### 세터 전위 우선 (이전 기록: 현재는 고정 세터 자리 사용)

코트 렌더링에서 세터를 먼저 전위에 배치한다. 같은 포지션의 전후 칸을 우선 교환해 일반 선수를 후위에 표시하며,회원/팀/배정 역할은 삭제하거나 변경하지 않는다. 교대 자리는 코트 밖에 유지한다. 센터·라이트 선택창도 각 신청자/대기자 그룹 안에서 세터를 먼저 표시하고 나머지 순서를 보존한다. 이는 구성도 표시 순서이며 실제 시작 로테이션은 아니다. 행 보기의 세터 우선 정렬은 유지한다.31모델 검사와 별도 빌드 통과,브라우저3팀 전위 세터 및 센터 후보 세터 우선 표시 확인.

### 수동 편성의 우선순위 — 제안

사용자 검토 사항: 수동 편성에서도 세터를 가장 먼저 분배하기 쉽게 만들 필요가 있다. 별도의 필수 포지션 설정 단계를 추가하기보다는 모든 팀을 계속 보여주고,상단에서 `세터 먼저 배정` 작업으로 진입해 팀별 세터를 채운 뒤 나머지 포지션으로 이어지는 선택적 흐름을 제안한다. 세터가 부족해도 다른 자리 편집을 막지 않는다. 현재 후보 목록의 세터 우선 및 코트 전위 배치는 유지한다. 이 추가 흐름은 아직 구현하지 않았으며,현재 반영한 변경은 코트/행 카드의 `센터 자리·라이트 자리` 보조 문구 제거다.

### 고정 세터 자리 검증

36모델 검사 및 별도 빌드 통과. 브라우저에서3팀 모두 전위 레프트/센터/세터,후위 레프트/센터/라이트 확인.센터 Dialog 제목 유지·설명 삭제·부 포지션 포함 시 센터 주/부 후보 다음 세터 순서 확인. 별도 비교 목업만 수정했다.

### 후보 상태 강조·복수 교대 자리 (최신)

선택창에서 미배정 후보는 연한 녹색 배경·테두리·미배정 배지로 강조한다. 다른 팀에 배정된 후보는 배정됨 배지와 현재 팀/역할을 표시하고 기존 명시적 이동 동작을 유지한다. 신청자/대기자 구분과 포지션 정렬은 변경하지 않는다.

교대 줄은 여러 개를 추가할 수 있고,각 줄 아래에 다음 교대 자리 추가 버튼을 유지한다. 빈 줄 개별 삭제도 가능하다. 이 별도 목업에 저장 버튼을 추가해 저장 시 선수 없는 교대 줄만 제거한다. 코트 기본 여섯 자리와 선택된 교대 선수는 보존하며,인원 수는 선택된 선수만 센다. 교대 줄에는 고유 ID를 사용해 삭제/저장 이후 재추가가 다른 선수의 자리를 덮어쓰지 않도록 한다. 현재 저장은 메모리 목업 상태이며 새로고침 시 초기화된다. 서버 저장/공개 연동은 아니다.

검증:46모델 검사·빌드 통과. 브라우저에서 교대3줄 생성→두 번째 줄에 오수빈 배정→저장→빈2줄만 삭제 및 선수 유지→새 교대 줄 재추가 확인. 후보 미배정/배정됨 표현을 화면으로 확인했다.

### 현재 배정 고정·미배정 우선·선택 토글 (최신)

`/weekend/position-slots/?review=current-player-v7`: 수정 Dialog는 현재 배정 선수를 검색 위에 강조 카드로 고정하고 후보 목록에서 중복 제외한다. 카드의 X는 실제 자리 배정을 해제하며,Dialog를 유지하고 검색 입력으로 포커스를 옮긴다. 검색과 필터 변경으로 현재 배정 카드가 숨지 않는다.

후보는 미배정 신청자→미배정 대기자→배정된 신청자→배정된 대기자 순서다. 각 그룹의 기존 센터 주/부/세터 순서는 유지한다. 이는 최신 요청의 미배정 최우선 표시를 반영하며,자동 배정이나 우선 편성 보장 정책을 바꾸지 않는다. 후보를 다시 누르면 선택이 해제되고 배정 버튼이 비활성화된다. 이 토글은 현재 자리 배정 자체를 해제하지 않으며,현재 배정 해제는 상단 X로 한다. 검색어 변경 시 선택도 초기화해 숨겨진 후보가 배정되지 않게 한다.

검증:52모델 검사 및 빌드 통과. 브라우저에서 현재 배정 상단 표시/중복0,미배정 선두,후보 두 번 클릭 후 선택0·배정 비활성,X 후 자리 비움/창 유지/검색 포커스 복귀를 확인했다. 별도 메모리 목업이며 실제 서버 저장은 연결하지 않았다.

### Dialog 하단 닫기/저장·타일 배정 (최신)

`/weekend/position-slots/?review=dialog-save-v8`: 우측 상단 닫기 X를 제거하고 하단에 닫기/저장을 둔다. 각 후보 타일에 배정 버튼을 바로 표시한다. 타일 본문 선택/재클릭 해제는 유지하며 배정 버튼과 별도 형제 버튼으로 구현해 버튼 중첩을 피한다.

타일의 배정 또는 현재 선수 카드 X는 Dialog 내부의 임시 배정을 변경한다. 상단에 저장 전 배정으로 표시하며 저장 전에는 원래 코트와 다른 팀을 변경하지 않는다. 저장을 누르면 배정/해제/다른 팀에서 이동이 함께 반영된다. 닫기,Escape,바깥 클릭은 임시 변경을 버린다. 변경이 없으면 저장은 비활성이다. 이는 이전의 X 즉시 반영 동작을 대체한다. 팀 전체 저장 시 빈 교대 줄 정리는 유지한다.

브라우저에서 상단 닫기 제거·하단 닫기1개,타일 배정→원본 유지→닫기 취소,재배정→저장 반영,배정 해제→닫기 원복을 확인했다. 빌드 통과. 별도 목업의 메모리 상태이며 서버 영구 저장은 아직 연결하지 않았다.
