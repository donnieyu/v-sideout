# SIDEOUT 선택 범위에 따른 가변 달력

2026-09-23. A 선택 유지. 최신 사용자는 내 모임 토글의 중복을 지적하고 선택 모임만 남기는 간결한 배치, 즐겨찾기, 목표 인원의 바 색 유지, 상세 버튼 중복 제거, 주 이동과 과거 팀 조회를 요청했다. 현재 산출물은 비교/체험 목업이며 실제 사이트에 적용하지 않았다.

## 세 가지 접근과 판단

| 방식 | 장점 | 손해 | 판단 |
| --- | --- | --- | --- |
| 고정 격자 | 날짜·시간대 위치가 항상 같고 All에서 위치를 기억하기 쉬움 | 단일 모임에도 빈 오전/토요일을 유지해 스크롤과 공간 비용 발생 | 여러 모임의 전체 비교에는 유효, 필터 결과에는 비추천 |

현재 비교 목업의 가변 규칙: All에서는 선택된 A의 토/일 및 오전/오후 비교 구역 유지. 단일 모임/즐겨찾기는 비어 있는 날짜 열 및 모든 선택 모임이 비어 있는 시간대 행만 접는다. 카드 하나가 남으면 과도하게 넓히지 않고 최대 680px 안에서 표시한다. 모임마다 다른 디자인을 만드는 것이 아니라 동일 컴포넌트의 공간을 조절한다. 모바일은 기존 날짜별 시간순 흐름을 유지한다.

‘내 모임만’ 토글 삭제. 뉴배동 필터 하나로 선택한다. 정렬은 날짜/시작 시각순이며 소속/즐겨찾기에 따라 임의로 순서를 바꾸지 않는다. 내 모임 표시와 정보 공개 권한도 유지한다.

## 즐겨찾기 제안

필터에 즐겨찾기 모음, 별도 편집 대화상자로 여러 모임 선택. 소속 변경이나 신청 행위와 분리. 뉴배동/히어로즈는 목업 초기 예시이며 실제 사용자 선호를 추정한 값이 아니다. 체크를 바꾸면 즉시 목업 필터에 반영되고, 주를 이동해도 유지한다. 새로고침/비교 조건 변경 시 초기화되며 서버 저장은 없다.

실제 제품에 도입할 때는 계정별 모임 ID 집합 저장을 제안한다. 처음에는 비어 있고 사용자가 고른 모임만 등록한다. 즐겨찾기가 비면 전체 모임을 임의로 대신 보여주지 않고 선택 안내를 제공한다. 등록되지 않은 모임은 선택지에 표시하지 않으며 접근 불가/폐쇄된 모임 처리도 구현 단계에 정한다. 이미 가진 신청/명단 권한은 바뀌지 않는다.

## 인원 바

이전 계산은 n=18/21/24에서 다음 구간의 시작값과 같아 분자 0이 됐다. 현재 구간은 n≤18/21/24/28로 판단해 각 목표에서 100%를 유지한다. 그 사이에는 누적 n/다음 목표를 사용한다. 예: 18=100%,19≈90.5%,21=100%,22≈91.7%,24=100%,28=100%. 인원 증가 때 폭이 조금 줄어드는 것은 다음 참고 단계로 이동하기 때문이며, 0으로 지우지 않는다. 숫자 단계 설명은 다시 넣지 않는다. 정원/선발 확정 의미로 쓰지 않는다.

## 상세와 주 이동

상세 신청 영역의 팀편성 확인을 제거했다. 정보 바로 아래 동일 공개본/공개 전 영역이 존재한다. 홈·과거 운동의 팀 확인 바로가기는 유지한다.

이전 목업은 weekOffset에서 빈 배열/빈 화면을 반환하는 제한된 스케치였다. 이번 목업은 9/14–20, 9/21–27, 9/28–10/4의 세 주를 제공한다. 제목, 주간 날짜(월 경계 포함), 아래 날짜/운동 카드가 함께 바뀐다. 오늘은 실제 기준일인 9/23에만 표시한다. 모임 필터/즐겨찾기는 유지한다.

- 과거: 신청/취소 없음. 운동 정보와 당시 공개 팀 조회. 9/20 뉴배동 21명 팀/대진은 기록 화면을 설명하는 샘플이며 실제 저장 기록을 가져온 것이 아니다. 미공개 기록은 '공개된 팀편성 기록이 없어요.'로 구분한다.
- 이번 주: 기존 대표 신청/취소/공개 흐름 유지.
- 다음 주: 반복 일정 템플릿을 사용한 ‘예정’ 표시, ‘모집 준비 중’ 비활성 행동. 주간 반복 일정이 있다는 이유로 모집을 자동 오픈하지 않는다.

실제 구현에서는 고정 시간표와 회차 데이터를 분리한다. 회차의 변경된 시간/장소를 우선하며 휴무/취소도 기록한다. 과거 팀은 현재 회원 정보나 최신 회차로 재계산하지 않고 **해당 회차의 공개 스냅샷**을 열어야 한다. 회차 없는 과거 날짜에 가짜 모집/팀을 생성하지 않는다. 다음 주 예정 표시와 운영자가 오픈한 접수를 구분한다. 이 사항은 제품 개발 시 적용할 설계이며 목업의 샘플 생성 코드를 그대로 이식하지 않는다.

## 후속 사용자 정정: 일정 상세를 단일 확인 공간으로

- 명단 탭 제거. 홈·상세 인원수 옆의 명단 확인 → 같은 native dialog. 소속 신청자의 이름과 하단 게스트 수만 표시. 타 모임 공개 전 명단과 내부 정보는 노출하지 않는다.
- 정보/공지 탭 전환은 tab-body만 갱신한다. 팀편성은 탭 밖의 독립 섹션으로 항상 보인다. 일정 정보 영역의 높이를 유지하여 탭 전환 시 팀편성이 밀리지 않도록 했다. 긴 내용은 패널에서 스크롤할 수 있다.
- 사이드바 팀편성 메뉴 통합을 목업에서 제안했다. 홈/모임 공간만 남기고 팀 결과는 해당 일정 상세로 연결한다. 홈의 팀편성 확인은 일정 상세의 팀 섹션으로 바로 이동한다. 별도 팀 결과 화면으로 분기하지 않는다.
- 장점: 회차·인원·명단·공지·팀 결과가 한 맥락에 모이고 중복 메뉴/경로 감소. 단점: 팀만 찾는 사용자에게 상세 진입이 추가될 수 있음. 홈의 직접 팀 영역 이동과 과거 주간 이동으로 보완한다. 향후 여러 회차의 결과를 한꺼번에 비교할 별도 목적이 생길 때만 팀 기록 메뉴를 재검토한다.
- 과거 회차는 신청 명단 대신 당시 공개 팀을 조회하며 실제 구현에서는 회차 공개 스냅샷을 사용해야 한다. 명단 오버레이의 회원 이름/게스트 수 표시 규칙은 현재 신청 명단 범위에 적용한다.
