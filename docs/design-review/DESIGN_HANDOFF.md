## 목표와 현재 단계

서울 배구 모임의 회원이 운동을 찾아 신청하고, 운영자가 인원을 확인해 팀을 편성·공개하는 웹서비스를 완성한다. 디자인의 중심은 **일정 탐색 → 신청 → 본인 상태 확인 → 공개된 팀 확인**이다. 운영 화면은 **편성 대상 확인 → 코트 배정 → 공개**가 중심이다. Impeccable의 `Operate` 모드에 해당하는 작업 화면이며, 홍보용 랜딩 페이지로 바꾸지 않는다.

**현재 진행 지점: 목업 선택과 첫 사이트 적용이 완료되었다.** 사용자는 후속 문구·버튼 리뷰 후 “이 목업과 요청한 기능들을 기준으로 사이트에 적용해줘”라고 승인했다. 실행 세션은 C+B 디자인 및 관련 기능을 구현하고 비공개 사이트 반영 완료를 보고했다. 로컬 코드에는 커밋 `bdf36de`로 기록되어 있다.

다음 작업의 주 산출물은 **현재 화면을 어떻게 발전시킬지 보여주는 서로 다른 구조의 아이디어와 비교 목업**이다. C+B는 선호를 이해하는 기준으로 활용하며 카드 모양·배치 자체를 고정하지 않는다. 제품 규칙을 지키는 범위에서 적극적으로 대안을 제안한다. 새 제안은 사용자가 선택·조합한 뒤 적용하고, 엄격한 QA는 그 뒤 수행한다.

## 이전 미결 항목의 현재 상태

다음은 **현재 코드와 갱신된 제품 문서에서 확인한 구현 규칙**이다. 모든 세부 조건에 별도의 사용자 답변이 있었다고 확대 해석하지 않는다. 이미 구현·검증한 내용을 미결 질문으로 다시 올리지 않는다.

| 이전 확인 항목 | 현재 동작 / 근거 |
| --- | --- |
| 우선 보장과 일반 상한 | 기간 내 정규 소속 회원은 상한 초과에도 일반 신청·보장 처리. `operations.ts`, 관련 도메인 검사 |
| 기간 만료와 보장 보존 | 신청 시 `guaranteed` 저장. 시간이 지나도 유지. 취소 시 해제, 재신청 시 해당 시점 조건으로 다시 계산 |
| 우선 종료 경계 | 종료 시각과 같으면 우선 대상이 아님. 종료 시각은 일반 신청 마감 뒤로 설정 불가 |
| 신입·과거 기록 | 신입은 기존 별도 참여/리더 예외 유지. 이전 신청에 보장 소급 부여하지 않음 |
| 보장 인원 미배정 | 한 명이라도 미배정이면 공개 거절. 운영자가 수동 배정·구성을 조정. 임의 탈락·자동 증설 없음 |
| 대표 인원 집계 | 현재 참석 의사 인원의 total 사용: 일반+후보+계정 없는 임시 인원. 배정 인원이나 일반 상한 수와 별개 |
| 신청 명단 / 공개 팀 | 같은 소속 신청자의 현재 이름순 roster와 마지막 published 팀 스냅샷을 별도로 사용 |

운영 화면에서 미배정 사유와 공개 실패 후 다음 행동이 이해되는지, 취소 후 재신청 시 편성 상태가 명확한지 등은 **사용성 검토 대상**으로 남긴다. 실제 검토에서 요구와 충돌할 때만 해당 조건을 재논의한다.

현재 공통 스킬로 사용 가능하다. 목록에 없으면 위 SKILL.md를 직접 읽고 해당 경로를 기준으로 실행한다. 필요하면 세션을 다시 로드한다. 공통 설치이므로 다른 프로젝트에서도 사용 가능하다.

`web/`에서 context 실행으로 `app/court-app.tsx`와 기존 구현을 정상 인식했다. 현재 `PRODUCT.md`, `DESIGN.md`, Impeccable 자동 훅은 없다. Live Mode의 Vinext 연결·시안 생성은 아직 시험하지 않았다. 훅 설정, CSP, 웹 패키지, 도구별 추가 에이전트 등록은 변경하지 않았다. 기본 스킬 사용·진단 준비와 모든 통합 기능의 작동 검증은 구분한다.

스킬은 순서대로 필요한 역할에만 사용한다. 사용자 선택과 제품 규칙이 일반적인 미적 권고보다 우선한다. 같은 화면을 세 스킬이 연달아 전면 재설계하게 만들지 않는다.

## 시작 자료

- 적용 직전 최종 통합 목업 보존본: `reference-2026-09-23-applied/sideout-refined.html`
- 현재 기준 커밋·출처·검증 수준: `reference-2026-09-23-applied/manifest.json`
- 구성 참고: `reference-2026-09-23/sideout-night-court.html` — B의 필터와 카드 구조만 참고.
- 색상·밀도 참고: `reference-2026-09-23/sideout-court-desk.html` — C.
- 이전 준비 시점 기록: `reference-2026-09-23/manifest.json`. 이 폴더의 refined는 후속 문구·버튼 리뷰 전 상태이므로 현재 구현 목표로 사용하지 않는다.
- 현재 우선 작업: `DESIGN_IDEATION_BRIEF.md`.
- 이전 발견과 선택 후 마무리 검사: `DESIGN_REVIEW_PLAN.md`.
- 실행 세션에 붙여 넣을 시작 문구: `START_IN_WORKING_SESSION.md`.

목업은 원본을 그대로 복사한 visualization HTML 조각이다. 독립 웹앱으로 실행 가능하다고 검증하지 않았다. 표시 시 원본 시각화 런타임을 사용하거나 **별도 검토용 wrapper**를 만들고 필요한 아이콘/컨트롤을 확인한다. 목업 속 역할·인원 조절 패널은 검토 도구이며 실제 제품 UI로 이식하지 않는다.

## 실행 순서 — 탐색 → 선택 → 구현 → 검증

1. 현재 사이트와 최근 작업을 짧게 확인하고 발전 가능성을 찾는다. 이미 수행한 QA를 반복하는 것으로 시작하지 않는다.
2. 필요하면 참고 사례를 조사하고 적용할 구체적 원리를 제안한다. 기존 카드 배치도 발전 대상이다.
3. 서로 다른 구조의 발전안 3개를 같은 콘텐츠·상태로 비교 가능한 목업으로 만든다. 각 안의 의도, 장단점, 추천과 조합 가능성을 설명한다.
4. 사용자가 안을 선택하거나 요소를 조합할 수 있게 보여준다. 현재 제품 규칙은 유지하며 새 탐색안을 임의 적용하지 않는다.
5. 선택한 방향을 실제 기능에 연결한다. 구조 탐색과 관계없는 기존 수정은 보존한다.
6. 선택안 구현 후 실제 화면·기능·접근성·반응형 검증과 디자인 기록 정리를 수행한다. 이미 통과한 검사는 변경 범위에 따라 필요한 만큼만 확인한다.

탐색 산출물과 완료 기준의 상세는 DESIGN_IDEATION_BRIEF.md를 따른다. 이번 단계의 성공은 “오류 몇 개를 고쳤는가”보다 “사용자가 더 나은 방향을 비교하고 선택할 수 있는가”로 판단한다.

## 선택안 구현 후 최종 완료 기준

- 기존 사이트의 필수 업무 흐름을 유지하면서 최근 확정 요구가 일관되게 반영된다.
- 모임 필터와 소속이 혼동되지 않고, 날짜·시간·장소·신청 상태·핵심 행동이 명확하다.
- 동일 모임 회원 / 타 모임 회원 / 무소속 / 회장·마스터 / 추가 운영진의 정보·행동 범위를 검증한다.
- 모바일, 긴 한글, 빈 데이터, 오류·저장 중 상태에서 핵심 동작을 완료할 수 있다.
- 회원용 API에 내부 평가·신청 순서·금지된 명단이 새로 노출되지 않는다.
- 사용자에게 실제 화면을 보여주고, 선택된 목업과 구현 차이를 설명한다.
- 디자인 기록과 제품 기록이 현재 구현 및 최근 결정과 일치한다. 아직 구현하지 않은 인증·권한을 완료로 보고하지 않는다.
