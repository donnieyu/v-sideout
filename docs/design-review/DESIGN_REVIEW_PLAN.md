## 선택안 구현 후 확인할 후보 — 아직 결함 확정 아님

1. **핵심 행동 가독성:** 마감 정보, 신청 상태, 취소/팀편성 확인 버튼이 좁은 화면에서도 구분되는지. 제거한 규칙 설명을 다시 넣는 방식으로 해결하지 않는다.
2. **상태 표현:** `EnrollmentCard`의 `stateLabel`은 공개본이 있으면 “팀편성 공개”를 우선한다. 접수 종료와 공개 상태가 함께 있는 상황에서 신청 가능 여부를 오해하는지 실제 화면으로 확인한다. 공개 상태 문구만으로 실패 판정하지 않는다.
3. **카드와 모달의 긴 내용:** 긴 모임명·장소, 신청 후 3개 버튼, 많은 신청자, 공개 팀 Dialog에서 줄바꿈·스크롤·포커스가 유지되는지 확인한다.
4. **운영 화면의 일관성:** 홈에 적용된 밀도·색상·글자 체계가 코트/신청자 도크/운영 설정과 자연스럽게 이어지는지 확인한다. 팀 배정·드래그 대체 조작은 유지한다.
5. **갱신 피드백:** 30초 갱신이나 포커스 복귀 중 화면·열린 명단이 튀지 않는지, 팀 공개 후 확인 버튼이 활성화되는지 로컬 샘플에서 확인한다.

현재는 구조·표현의 발전안을 먼저 탐색한다. 위 후보는 선택안 구현 후 확인하며, 결함의 증명이 없다는 이유로 새로운 디자인 아이디어를 제한하지 않는다.

## 변경 후 검증

작업 경로는 `web/`다. **이번 갱신에서 재실행한 것은 도메인 35개뿐**이다. 타입·API·빌드 통과는 실행 세션 보고로 확인했으며, 브라우저 시각 QA는 미수행이다. 아래는 이후 변경에 맞춰 선택할 검증 지침이다.

- 타입: `npx tsc --noEmit`
- 도메인: `node tests/domain.mjs` — 기존 검사를 유지하고 우선 기간·고정 소속 등 변경한 정책의 경계 검사만 추가.
- API: 역할별 projection, 명단 열람, 수정 거부, revision 충돌을 로컬 샘플에서 확인. 기존 비공개 배포 데이터에 시험 신청을 쓰지 않음.
- Impeccable: 변경 UI가 끝난 후 설치된 런처의 `detect --json <변경 대상>` 한 번. 자동 훅은 현재 없음. 기계적 경고를 사용자 디자인 선택보다 높은 권위로 취급하지 않음.
- UI: 실제 브라우저에서 데스크톱/모바일, 키보드, 신청·공지·명단·팀 편성의 변경 경로 확인.
- web-design-guidelines: 스킬이 지정한 최신 원문을 읽고 변경 파일 범위 검토. 소스 확인만으로 화면 검증 완료라고 보고하지 않음.
- Sites: 실행 세션이 현행 sites-building의 검증 스크립트를 사용. 기존 `.openai/hosting.json`, 패키지·잠금 파일과 배포 대상을 유지.

색상·간격만 바꾼 경우 구현을 복제하는 테스트를 추가하지 않는다. 규칙·권한·집계·저장 변경은 실제 실패를 잡는 검사를 추가한다. 통과한 검사를 근거 없이 반복하지 않는다.
