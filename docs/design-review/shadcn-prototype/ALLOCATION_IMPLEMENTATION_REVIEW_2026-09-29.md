# 모바일 팀편성 구현·검증 보고 · 2026-09-29

## 적용 범위

[`ALLOCATION_MOBILE_UX_REVIEW_2026-09-29.md`](ALLOCATION_MOBILE_UX_REVIEW_2026-09-29.md)의 후속 설계를 `a-shadcn` 목업에 적용했다. 코트 기본 보기와 코트/행 전환, 코트 타일의 소속 표시, 취소·저장·공개 버튼의 같은 폭, 반복 안내 제거는 앞서 반영된 상태를 유지했다. 이번 변경은 포지션별 연속 배정의 **채워진 자리 교체**와 **신청자 우선 후보 선택**에 집중했다. A 비교 화면과 운영 앱 `web/main`에는 이번 배정 UX를 이식하지 않았다.

- 자리 타일 하나를 고르면 배경색과 아웃라인을 함께 표시한다. 빈자리는 `배정`, 채워진 자리는 `교체`다. 교체는 기존 선수를 미배정으로 돌리고 새 선수를 같은 자리에 넣는 한 명령이다. 빈자리 배정 때만 다음 빈자리로 이동하고, 마지막 자리나 교체 때는 현재 자리에 머문다.
- X는 별도 44px 터치 영역이며 확인 대화상자를 거쳐 해제한다. 미배정 후보만 교체 대상으로 보여서 이미 다른 팀에 배정된 선수를 잘못 이동시키지 않는다. 기존 선수는 `배정된 선수` 접힘 목록에서 위치를 확인할 수 있다.
- 선수 풀의 기본은 **미배정 신청자 전원**이다. 그 안에서 주 포지션 → 부 포지션 → 선택 가능한 세터 → 다른 포지션 순으로 묶는다. 포지션은 우선순위일 뿐 신청자를 목록에서 제외하는 조건이 아니다. 대기자와 미신청 회원은 상태 버튼으로 명시적으로 선택한다. 이름·소속 검색은 세 상태를 함께 찾되 결과에 상태와 포지션 구분을 남긴다. 미신청 회원 배정 후 저장/공개 전 참가자 추가 확인은 유지한다.
- 320px에서는 팀별 배치판에 가로 내부 스크롤을 제공해 긴 이름과 해제 버튼이 겹치지 않게 했다. 선수 풀은 별도 세로 내부 스크롤을 유지한다. 390px에서는 세 팀과 후보를 한 화면에서 함께 확인한다.

## 평가와 남은 경계

현재 목적이었던 **신청자를 먼저 배정하면서 현재 팀 배치를 보고 필요한 한 자리만 바로 교체**하는 흐름은 목업과 통합 테스트 양쪽에서 확인했다. 320px에서는 세 팀 전체가 동시에 들어가지 않아 배치판 내부 가로 스크롤이 필요하다. 이는 이름과 44px 해제 동작을 온전히 보이는 쪽을 택한 결과다. 390px에서는 세 팀이 한 화면에 들어간다.

현재 샘플 회차는 미배정 대기자·미신청 회원 수가 0명이므로 이 두 버튼의 실제 브라우저 조작은 하지 못했다. 합성 데이터의 React 검사에서 상태 전환과 전체 상태 검색은 확인했다. 실물 iPhone Safari에서 키보드가 열린 상태, 터치·스크롤·안전 영역은 확인하지 못했다. 이미 배정된 두 선수의 자리 맞교환은 이번 교체 규칙과 구분해 미구현으로 남겼다. 실제 로그인·계정 발급·서버 영속 저장과 `web/` 운영 셸 이식도 이 목업 변경에 포함되지 않는다.
