## 확정한 의미와 이번 제안

**달력 이동과 참석 기록 조회는 별개다.** 과거 참석 여부 또는 데이터 유무로 이전/다음 주 이동을 제한하지 않는다. 지나간 주에는 실제 참석 기록이 있는 운동만 표시한다. 아무 기록이 없는 주에도 날짜·요일·주 이동 버튼은 유지하고 아래에 ‘이 주에는 참석한 운동이 없어요.’를 표시한다. 과거 기록을 정기 일정으로 추정해서 생성하지 않는다. 과거 카드에는 팀편성 확인만 두고, 상세에서 장소·일정·당시 팀편성을 확인한다. 신청 이력만으로 참석으로 간주하지 않는다.

샘플 기준일은 2026-09-23이며 4주에만 회차 자료가 있다. 9/20 뉴배동, 9/12 히어로즈만 실제 참석한 것으로 설정한 테스트 데이터다. 다른 과거 회차도 데이터에는 있지만 표시하지 않는다. 실제 사용자 기록이 아니다.

| 위치 제안 | 장점 | 한계 / 선택 |
|---|---|---|
| 즐겨찾기 필터 옆 관리 버튼 | 편집 대상과 동작이 바로 연결됨. 운동별 반복 버튼이 없음 | 작은 화면은 아이콘으로 축약. 이번 목업 추천안 |
| 각 카드 우측 별 | 눈앞의 모임을 즉시 추가 | 상세 버튼과 경쟁하고 동일 모임 회차마다 반복됨 |
| 사이드바 계정 아래 | 본문 필터가 짧아짐 | 필터와 관리의 거리가 멀어 찾기 어려움 |

필터는 모임 소속 변경이 아니다. 내 모임 전용 토글은 없다. 모임·즐겨찾기 필터 선택 시 빈 날짜/시간 행을 접고, 상단 주간 스트립은 유지한다.

- 공개 전 안내: ‘아직 팀편성이 공개되지 않았어요.’ 실제 이름 대신 포지션 구획 예시를 보여준다.

## 팀편성과 경기 순서

각 팀 카드를 **세터 → 레프트 → 센터 → 라이트**로 나누고 구분선·라벨·인원수를 둔다. 이름은 우측에 정렬한다. 포지션마다 인원이 다른 경우에도 같은 그룹을 유지한다. 예시는 7명/팀이며 고정 교대 선수를 지정하지 않는다. 실력 평가와 운영용 프로필은 표시하지 않는다.

첨부 이미지에서 경기 순서만 참조했다. 신입 a–b → A–B → B–C → A–C를 세 번 반복하며 20분씩 총 12경기, 13:00–17:00이다. 세 묶음을 ‘라운드’로 구분한 것은 이번 표현 제안이다. 은행 정보·그림·실명은 복사하지 않았다. 뉴배동 공개 상태에만 이 순서 예시를 표시하고, 다른 모임은 별도의 경기 순서가 등록되지 않았다는 상태를 보여준다. 자동 대진 생성 기능이 아니다.

### 즐겨찾기 내부 보조 아이콘으로 변경

사용자 리뷰: 분할 버튼은 선택 외곽선·배경과 관리 동작이 섞여 부자연스럽다. 위의 분할 버튼 추천은 이 수정으로 대체한다.

비교한 패턴:
- Atlassian Split button: 기본 동작과 추가 메뉴를 나누는 대조 사례. 여기서는 실행 명령보다 선택/편집의 의미 차이가 커서 채택하지 않았다. https://atlassian.design/components/button/split-button
- MUI Chip의 Clickable and deletable: 본문 동작과 끝 아이콘 동작을 분리한 실제 예시. 원래 삭제 용도이며 관리 메뉴의 직접 표준 사례는 아니다. 그 구조를 관리 메뉴로 응용했다. https://mui.com/material-ui/react-chip/#clickable-and-deletable
- 별도 관리 버튼은 역할이 명확하지만 필터 줄을 늘린다. 현재 간결성 요구에 따라 내부 보조 아이콘을 채택했다.

구분선·관리 문자를 없앴다. 하나의 외곽선과 배경을 공유하는 비대화형 group 안에 형제 button 두 개를 둔다. 본문만 aria-pressed를 갖고 필터를 선택하며, 44×44 관리 아이콘은 shadcn DropdownMenuTrigger로 메뉴만 연다. button 안에 button을 중첩하지 않는다. https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/button

선택 테두리는 전체 표면에 한 번만 그린다. 아이콘 색은 중립색을 유지하고 hover/open 시 아이콘 주변에만 작은 강조가 생긴다. 그룹 자체에는 클릭 핸들러를 두지 않아 관리 클릭이 필터 선택으로 전파되지 않는다. 키보드 포커스는 각 동작에 별도로 표시한다.

빌드 통과. 데스크톱·390px 모바일에서 검토: All 상태에서 관리만 열어도 All 유지, 즐겨찾기 선택 시 하나의 전체 테두리/본문 테두리0px, 중첩 button0개, 관리44×44, 모바일 페이지 넘침 없음. Tab으로 본문→관리 이동, Enter로 메뉴 열기, Escape 종료 후 관리 아이콘으로 포커스 복원 확인. screenshots/favorite-inline-desktop.png와 favorite-inline-mobile.png 참고. 운영 사이트는 변경하지 않았다.

### 버튼 위 아이콘 onClick 구조로 후속 변경

사용자 요청에 따라 즐겨찾기를 전체 너비의 실제 Button 하나로 만들고, 형제 span 아이콘을 position:absolute로 버튼 우측 위에 겹쳤다. 기존 두 Button 구조를 대체한다. 아이콘에는 onClick으로 제어하는 shadcn DropdownMenu를 연결했다. 상위 버튼의 자식으로 중첩하지 않아 버튼 클릭이 함께 실행되지 않는다. 별도 아이콘 배경·구분선은 없다.

span은 role=button, tabIndex=0, 접근 가능한 이름을 가지며 Enter/Space/ArrowDown으로 메뉴가 열린다. 기본 pointerdown 토글은 막아 onClick과 이중 실행되지 않는다. 마우스 영역40×44, coarse pointer는44×44. 빌드와 브라우저 확인: 실제 button1개/span아이콘, All 유지한 채 메뉴 클릭 열림, 즐겨찾기 본문 선택, Tab→Space 메뉴 열기, Escape 후 포커스 복원, 390px 가로 넘침 없음. 키보드 사용 중 아이콘 포커스 윤곽선은 접근성을 위해 유지한다.

### 달력 등록 통합·복수 운영 권한 (최신)

- 별도 `운동 등록` 메뉴와 #register 화면 진입을 제거했다. 홈에서 원하는 주를 선택하고 기존 준비 카드 형태의 **모임 등록** 버튼으로 들어간다. 버튼은 모임 자체 신규 생성이 아닌 운동 회차 등록이다.
- 미등록 카드는 정기 날짜·시작 시각·장소를 바탕으로 만든 운영용 진입점이다. 달력 이동만으로 저장 레코드는 생성하지 않는다. 마스터는 모든 모임, 운영자는 `managedClubIds`에 속한 여러 모임에 진입할 수 있다. 상단 검토 선택에서 회원/마스터/뉴배동 운영자/뉴배동·히어로즈 운영자를 비교한다. 실제 인증이 아니다.
- 기존 다음 주 준비 예시 데이터를 제거했다. 회원에게는 미등록·draft 카드와 관련 운동 개수가 모두 숨겨진다. 준비로 저장하면 권한 보유 운영자에게만 `이어서 준비`가 표시된다.
- 기존 Detail 헤더·Breadcrumb·정보/공지 Tabs·하단 팀편성을 그대로 사용하고 신규/준비 회차의 본문만 SessionEditor로 전환한다. 정보 탭에서 입장/시작/종료/장소,공지 탭에서 안내문,오른쪽 인원 타일 자리에서 신청 설정을 편집한다. 모임·날짜는 홈에서 선택한 값이다. 정기 모임 설정에 변경을 전파하지 않는다.
- 준비 저장→홈→이어서 준비 및 모집 시작→일반 상세→회원 홈 표시/신청/명단을 로컬 메모리 안에서 연결했다. 새 회차에 이전 샘플 신청자나 명단을 복사하지 않는다. 새로고침 시 샘플 등록·신청 내용이 초기화된다. 운영web/서버 데이터는 미변경이다. 이 단계에서는 열린 회차의 재편집 UI를 제외했다. 아래 「등록 상태 구분·등록된 회차 수정」에서 후속 구현했다.
- 미저장 입력의 링크 이동·권한 전환에는 이탈 확인,페이지 종료에는 beforeunload를 적용했다. 준비 저장과 모집 시작으로 변경 사항을 확정한다. 브라우저 네이티브 확인창의 모든 플랫폼 조합은 검증하지 않았다.

### 등록 상태 구분·등록된 회차 수정 (최신)

운영용 카드의 세 상태를 색상뿐 아니라 테두리·텍스트·버튼으로 구분한다. 전체 opacity를 낮추는 방식은 글자 대비와 조작 가능성을 흐리므로 쓰지 않는다.

| 상태 | 카드 | 행동 | 회원 노출 |
| --- | --- | --- | --- |
| 미등록 | 점선, 투명 배경(내 모임은 아주 옅은 녹색), `미등록` | 아웃라인 `+ 모임 등록` | 숨김 |
| 준비 저장 | 실선, 옅은 청회색, `준비 저장 · 운영자만 확인` | 아웃라인 `이어서 준비` | 숨김 |
| 모집 시작 | 기존 일반/내 모임 카드, 권한 보유자에게 `모집 중` | 기존 참석 신청 | 공개 |

팀편성 공개는 회차 등록과 별도 상태다. 공개된 회차는 `팀편성 공개`를 표시하고 취소 불가 규칙을 유지한다. 내 모임의 이름 색/마크/배지는 준비 카드에도 유지한다.

상세 상단의 상태 표시 왼쪽에 공통 shadcn Button outline `수정`을 추가했다. 마스터 또는 해당 모임 운영 권한 보유자에게만, 시작 전 회차에서 표시한다. 모바일은 제목 아래 별도 행에서 상태 왼쪽/수정 오른쪽으로 배치하며 버튼 높이44px를 유지한다. 정보·공지·신청 설정을 동일 상세 안에서 수정한다. `취소 / 변경 저장`만 제공하고 이미 공개된 회차를 준비 상태로 되돌리는 버튼은 제공하지 않는다. 저장 성공 안내 및 제목 포커스 복귀를 적용했다.

동일 회차 ID로 갱신해 샘플 참석 여부·신청 수·명단·팀 공개 상태를 유지한다. 기존 fixture를 override할 때 달력 중복 생성과 인원 초기화를 막는다. 새로 등록한 회차는 샘플 기존 명단을 받지 않는다. 기존 회차 공지/마감을 편집 기본값에 보존하고, 이미 지난 우선 종료/마감도 원래 값 그대로면 저장 가능하다. 새로운 과거 시각 입력은 막는다. 운동 날짜/모임은 편집하지 않는다. 정기 모임 기본값과 경기 대진표를 자동 변경하지 않는다.

검증: 빌드 및 등록12+달력14+기존 회차 수정17=43검사 통과. 실제 브라우저에서 미등록→준비 저장→모집 시작,기존 공개 회차 장소 수정 후21명/소속15명·게스트6명/3팀/취소 불가 유지,수정 취소(미변경 상태),일반 회원 및 타 모임 운영자 수정 버튼 숨김,신규 회차 신청1명 유지 확인. 390px 상세 수정 버튼44px,320px 편집 폼 가로 넘침 없음 확인. 입력 변경 후 네이티브 이탈 확인창 전체 동작은 이번 검증에서 재검사하지 않았다.

### 무소속 마스터·상단 편집 액션·카드 크기 통일 (최신)

- 마스터는 `homeClubId=null`,모든 모임 운영 가능이며 `내 모임` 강조를 표시하지 않는다. 프로필/계정도 소속 없음으로 표시한다. 운영자는 자기 소속 모임을 기본 운영 범위에 포함하고 추가 모임 권한을 합친다. 일반 회원에게 소속만으로 운영 권한을 주지 않는다. 단일 소속 뉴배동 + 추가 히어로즈 예시를 권한 선택으로 확인한다.
- 상세 헤더의 팀편성 공개/신청 완료/모집 중/작성 중 배지를 모두 제거했다. 오른쪽 끝 `수정`을 누르면 동일 상단 영역이 `취소 / 저장`으로 바뀐다. 모바일도 같은 행 위치를 유지한다. 실제 form의 상태/검증을 사용하는 공통 Button을 헤더로 portal 렌더하며 하단에 중복하지 않는다.
- 신규/준비 상세도 상단에 `취소 / 준비로 저장 / 모집 시작`을 둔다. 신규는 취소 활성화→홈 복귀. 저장된 준비/등록 회차는 현재 입력과 저장값이 다를 때만 취소 활성화(직접 원복하면 비활성화). 준비 취소는 저장값으로 되돌리고 입장 입력에 포커스,등록 회차 취소는 변경을 버리고 일반 상세로 돌아간다. 준비 저장 직후 취소는 다시 비활성화된다.
- 등록 카드도 제목44px/상태/인원44px+바/하단 행동의 같은 구조를 사용한다. 미등록·준비 카드 인원은 `—명 · 모집 전`과 빈 바이며 가짜 신청 숫자를 만들지 않는다. 운영용 세 상태의 테두리와 배경은 유지한다.

### 홈 타일의 중복 상태 문구 제거 (최신)

공개된 팀편성은 신청 여부에 관계없이 홈 `팀편성 확인` 버튼으로 접근한다. 신청 후 공개 전에는 기존처럼 비활성 버튼을 표시하고, 상세에서는 바로 아래 팀편성이 있으므로 중복 버튼을 추가하지 않는다. 검토용 상태 선택에 `미신청 · 공개 후`를 추가해 이 조합을 확인한다. 명단 공개/참석 취소 제한은 변경하지 않는다.

검증: TypeScript/Vite 빌드 통과. 실제 브라우저1280px에서 세 종류 카드 모두202.59px(기존보다30px 축소),320px 모두197.05px로 동일하며 가로 넘침 없음. 미신청·공개 후 버튼 활성화→팀 영역 이동 및 포커스/3팀 표시를 데스크톱·모바일에서 확인했다. 신청 후·공개 전 팀 버튼 비활성 유지 확인. 모바일 행동 버튼 높이44px 유지. 화면: `screenshots/compact-status-free-cards.png`. 운영 web 변경 없음.

### 일정 상세의 팀편성 직접 편집 (최신)

별도 운영 화면 대신 같은 일정 상세의 팀편성 섹션 오른쪽에 권한 기반 `수정`을 제공한다. 등록된 시작 전 회차에만 표시한다. 마스터는 모든 모임,운영자는 소속+추가 권한 모임을 편집한다. 미등록/준비 저장 회차는 먼저 모집 등록을 완료한다. 지난 운동은 당시 공개본 조회를 유지한다.

편집 모드의 같은 섹션 헤더에 `취소 / 저장 / 공개`를 둔다. 저장은 회차별 운영용 초안,공개는 별도 복사본이다. 기존 공개본이 있으면 새 초안을 편집/저장하는 동안 회원은 이전 공개본을 본다. 운영자 조회에는 저장된 초안임을 표시한다. 저장/공개 후 편집을 종료하고 수정 버튼에 포커스를 돌린다. 취소는 미저장 변경을 버린다. 저장된 기준이 있고 변경이 없으면 취소는 비활성화한다. 새 편성은 취소 가능하다.

팀 카드는 세터 우선의 세로 명단을 유지한다. 편집 중 인원별 포지션 Select/배정 해제,팀별 인원 추가 Dialog,검색·미배정/신청자 필터,팀 간 이동(중복 자동 제거)을 제공한다. 팀 추가는 최대4개이며 빈 팀만 삭제할 수 있다. 회원 선택은 실제 shadcn Dialog/Input/Select/Button을 사용한다. 마스터의 모든 회원 필터는 기존 대리 편성 권한에 해당하며,현재 운영자 예시는 추가 운영진이므로 신청 인원 범위만 사용한다. 회장 계정의 별도 미리보기는 아직 없다. 회원의 신청 기록을 편성 저장으로 덮어쓰지 않는다.

빈 편성/빈 팀/중복 배정은 공개 검증으로 막는다. 6명·7명 등 팀 인원 및 포지션 구성은 운영자가 판단하며 강제 자동 배치하지 않는다. 공개하면 홈 팀편성 확인과 공개 이후 참석 취소 제한에 반영한다. 정보 편집과 팀편성을 동시에 열어 서로 다른 저장 단위를 혼동하지 않도록 상대 수정 버튼은 편집 동안 비활성화한다. 미저장 편성 변경은 링크 이동/권한 전환/리뷰 상태 전환 및 beforeunload 보호에 포함한다.

검증: 빌드 및 기존56+팀편성17=73검사 통과. 브라우저에서 포지션 변경 취소→세터 복원,공개본7명→초안6명 저장 후 회원7명 유지→담당 운영자 공개 후 회원6명 확인. 회원/타 모임 운영자 수정 버튼 없음. 첫 공개 전 초안의 실명0명 노출,빈 편성 공개 오류/포커스,검색 추가와 중복 없는 A→C 이동,최초 공개 이후 홈 팀 확인 활성화/취소 불가 확인.320px 편집·후보 Dialog 가로넘침 없음,Dialog top16/bottom552(height568),버튼44px 확인. 네이티브 이탈 확인창의 브라우저별 동작은 이번 검증에서 재검사하지 않았다.

범위: 로컬 메모리 목업이며 새로고침하면 초안·공개본이 초기화된다. 실제 인증·계정 발급·서버 권한 검증/저장·알림·변경 이력은 미구현이다. 드래그 배치,임시 게스트/신입 전용 분류·예외 배정,실력 평가/자동 배치,경기 대진 순서 편집은 아직 연결하지 않았다. 신청 후보와 명단은 가상 샘플로 동작한다. 기존 경기 순서 표는 참조 예시이며 편성 수정으로 자동 변경하지 않는다. 신규 공개 회차에는 예시 대진표를 복사하지 않는다. 운영 web은 미변경이다.

### 공개 이후 대기 접수·참석자 열람·포지션/코트 설계 (최신)

이전의 신청 여부와 관계없는 공개 편성 열람을 사용자 후속 결정으로 폐기했다. 공개 전 일반 신청은 참석 신청,일반 마감 후 또는 편성 공개 후는 운동 시작 전까지 대기자 등록이다. 대기 등록 완료는 중복 접수하지 않고,일반 신청자 수/명단에 합치지 않는다. 등록된 대기자가 공개 편성에 배정되면 확정 인원으로 표시한다. 샘플 사용자의 대기 이력을 공개 snapshot의 배정 여부와 결합해 판정하며,초안 배정으로 승격하지 않는다.

홈 팀편성 확인은 일반 신청자(공개 전 비활성/공개 후 활성) 또는 공개본에 배정된 참가자에게만 표시한다. 다른 회원/미배정 대기자는 상세에서도 실명/편성/경기 순서를 렌더하지 않고 `참석자만 팀편성을 확인할 수 있어요.`를 표시한다. 해당 모임 운영 권한자는 관리 목적으로 확인한다. 로컬 샘플의 공개본에서 미신청자인 본인이 이미 배정되어 있던 모순도 제거했다.

운영자 선택창에 신청자→대기자→그 외 회원(허용 권한만) 순서의 분리된 목록을 적용했다. 미배정 필터와 검색은 두 신청 그룹에 함께 적용한다. 초안에 들어간 대기자는 편집 행에서 `대기`를 표시한다. 일반 신청자는 공개 이후 열람 가능하다는 규칙을 적용하며,대기자는 실제 공개본 배정이 필요하다.

검증: 빌드 및 기존73+대기정책11=84검사 통과. 실제 브라우저 회원 미신청 홈에서 대기자 등록만 노출,상세 team-member0/match-table0,대기등록 후에도 비공개 확인. 운영자 후보창 신청자20/대기자1 순서 확인.대기자를 초안에 배정→저장한 뒤에도 회원 버튼은 대기등록완료/실명0,재공개 후 취소불가+팀편성확인/21명 편성 노출 확인. 실제 서버 인증/응답 권한 검사는 아직 없으므로 데이터 보안 완성으로 해석하지 않는다.

포지션 UI는 [별도 설계안](../POSITION_SLOT_PLAN.md)에 기록하고 `/weekend/position-slots/`에 비교 목업을 만들었다. 큰 포지션 그룹 대신 자리별 포지션/+ 및 해당 주 포지션 신청자→대기자 후보를 제안한다. 기존 운영 web의 코트 도식을 참조해 네트3열×2행과 행 보기 전환을 추가했다. 실제 앱의 팀편성 UI에는 아직 적용하지 않았다. 공개 화면 코트형 기본/운영자 행 전환을 추천한다. 세터의 센터·라이트 점유,별도 교대 자리,로테이션과 구성도의 구분은 설계안에 명시했다. 실명은 가상 샘플이다.

### 현재 배정 고정·미배정 우선·선택 토글 (최신)

`/weekend/position-slots/?review=current-player-v7`: 수정 Dialog는 현재 배정 선수를 검색 위에 강조 카드로 고정하고 후보 목록에서 중복 제외한다. 카드의 X는 실제 자리 배정을 해제하며,Dialog를 유지하고 검색 입력으로 포커스를 옮긴다. 검색과 필터 변경으로 현재 배정 카드가 숨지 않는다.

후보는 미배정 신청자→미배정 대기자→배정된 신청자→배정된 대기자 순서다. 각 그룹의 기존 센터 주/부/세터 순서는 유지한다. 이는 최신 요청의 미배정 최우선 표시를 반영하며,자동 배정이나 우선 편성 보장 정책을 바꾸지 않는다. 후보를 다시 누르면 선택이 해제되고 배정 버튼이 비활성화된다. 이 토글은 현재 자리 배정 자체를 해제하지 않으며,현재 배정 해제는 상단 X로 한다. 검색어 변경 시 선택도 초기화해 숨겨진 후보가 배정되지 않게 한다.

검증:52모델 검사 및 빌드 통과. 브라우저에서 현재 배정 상단 표시/중복0,미배정 선두,후보 두 번 클릭 후 선택0·배정 비활성,X 후 자리 비움/창 유지/검색 포커스 복귀를 확인했다. 별도 메모리 목업이며 실제 서버 저장은 연결하지 않았다.

### Dialog 하단 닫기/저장·타일 배정 (최신)

`/weekend/position-slots/?review=dialog-save-v8`: 우측 상단 닫기 X를 제거하고 하단에 닫기/저장을 둔다. 각 후보 타일에 배정 버튼을 바로 표시한다. 타일 본문 선택/재클릭 해제는 유지하며 배정 버튼과 별도 형제 버튼으로 구현해 버튼 중첩을 피한다.

타일의 배정 또는 현재 선수 카드 X는 Dialog 내부의 임시 배정을 변경한다. 상단에 저장 전 배정으로 표시하며 저장 전에는 원래 코트와 다른 팀을 변경하지 않는다. 저장을 누르면 배정/해제/다른 팀에서 이동이 함께 반영된다. 닫기,Escape,바깥 클릭은 임시 변경을 버린다. 변경이 없으면 저장은 비활성이다. 이는 이전의 X 즉시 반영 동작을 대체한다. 팀 전체 저장 시 빈 교대 줄 정리는 유지한다.

브라우저에서 상단 닫기 제거·하단 닫기1개,타일 배정→원본 유지→닫기 취소,재배정→저장 반영,배정 해제→닫기 원복을 확인했다. 빌드 통과. 별도 목업의 메모리 상태이며 서버 영구 저장은 아직 연결하지 않았다.

### 참가 명단 관리·미신청 후보 구분 (2026-09-28)

미신청 회원은 회녹색(`#f0f3f1` 배경, `#d8dfda` 테두리)의 선택 가능한 참고 후보로 표시한다. `미배정 신청자` 수는 신청자 중 미배정인 회원만 집계하며 미신청·대기자를 포함하지 않는다. 자동 배치에서도 미신청 회원을 제외한다.

홈·상세의 명단 확인을 마스터와 해당 모임 운영 권한자에게 제공한다. 운영진은 소속 회원·게스트 실명과 대기자 목록을 확인하고, 추가 화면에서 이름/소속 검색과 체크박스로 여러 회원을 선택해 일괄 등록할 수 있다. 이미 신청/대기 등록한 회원은 추가 목록에서 제외하며 검색어를 바꿔도 선택은 유지된다. 일반 회원은 자기 모임의 소속 회원 실명과 게스트 인원수만 확인한다.

운영진 추가는 회차별로 저장하고 홈 인원수·명단·팀편성 후보에 동일하게 반영한다. 일반 마감 또는 편성 공개 후에는 대기자로 등록하며 기존 공개본을 바꾸지 않는다. 과거·시작한 회차에는 추가할 수 없다. 샘플 인원 숫자도 실제 후보 목록에서 산출하도록 통일했다(기존 런업 숫자 22와 실제 샘플 회원 20의 불일치 해소).

검증: 대상 React/모델 테스트 17개, 팀·대기 정책 28개, 배정 모델 67개 및 빌드 통과. 모바일에서 2명 선택→일괄 추가→15명에서17명→배정 신청자17명 확인. 자동 배치 후 미배정 신청자0명 확인. 담당 운영자 게스트 열람/추가, 일반 회원 게스트 이름 비공개, 공개 후 대기자 등록 확인. 실제 서버 저장·인증은 미연결이며 새로고침하면 샘플 변경은 초기화된다.
