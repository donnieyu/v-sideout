# 모바일 팀편성 화면 검토 · 2026-09-29

> 아래의 「다음 설계」는 구현 전 검토 기록이다. 적용 결과와 현재 한계는 [팀편성 구현·검증 보고](ALLOCATION_IMPLEMENTATION_REVIEW_2026-09-29.md)를 우선 참조한다.

## 목적과 현재 확인

운영진이 휴대폰에서 **현재 배정 자리와 신청자 후보를 동시에 보며** 팀을 완성하는 것이 우선이다. 현재 포지션별 연속 배정과 하단 선수 풀의 내부 스크롤, 저장/공개 구분, X 해제 확인은 유지한다. A 비교안과 실제 `web/` 앱은 범위 밖이다.

`SessionAllocation`의 전체 팀 보기는 코트/행 버튼이 일반 텍스트 버튼처럼 보여 전환 조작이 약했다. 코트 타일에 소속이 없었고, 상단 저장 동작은 좁았으며, 반복 안내가 후보 영역의 높이를 차지했다. 이 네 가지는 현재 목업에 반영했다. 코트를 기본 보기로 바꾸고 선택 상태가 강한 한 그룹으로 묶었다. 코트 타일은 기존 72px 안에서 포지션·이름·작은 소속을 보여준다. 취소/저장/공개는 높이 44px를 유지하면서 같은 폭으로 넓혔다. 배정 안내는 화면에서 빼고 변경 사실만 접근성 알림으로 남겼다.

390×844 브라우저 화면에서 전환 그룹, 두 개의 관리 동작, 코트 타일과 소속 표기를 확인했다. 320×700에서는 넓힌 세 버튼 때문에 제목이 여러 줄로 접히는 문제가 드러나, 그 너비에서만 제목·인원을 한 줄, 세 동작을 다음 한 줄로 정리한 뒤 후보 풀이 화면에 남는 것을 다시 확인했다. 넓은 화면에서도 회귀 검사를 진행했다. 실물 기기 터치·Safari 키보드 노출은 확인하지 않았다.

## 다음 설계: 선택한 자리를 유지하며 교체

현재 `ContinuousAllocation`은 채워진 자리를 선택하면 선수 풀이 사라지고, 그 포지션의 모든 자리가 차도 풀이 사라진다. `assign`과 `continuous-assign`은 채워진 자리의 선택을 거부한다. 따라서 요청한 교체는 **가능하지만 타일 색만 바꿔서는 동작하지 않는다.** 후보 렌더 조건과 배정 명령을 함께 바꿔야 한다.

권고 흐름은 다음과 같다.

1. 어느 자리든 선택하면 그 자리 하나만 배경색과 아웃라인을 함께 표시한다. 최근 배정의 녹색 강조는 없앤다. X는 기존처럼 확인창을 거쳐 해제한다.
2. 선택한 자리가 비었으면 후보 버튼은 `배정`, 차 있으면 `교체`다. 후보 풀은 역할 전체가 가득 찬 뒤에도 유지한다.
3. 미배정 후보로 교체하면 한 명령에서 기존 선수를 미배정으로 돌리고 새 선수를 그 자리에 넣는다. 중간에 빈 팀 상태를 저장하지 않는다. 교체 후에는 현재 자리에 머물러 세 팀을 확인한다. 빈자리에 배정했을 때만 지금처럼 다음 빈자리로 이동한다.
4. 이미 다른 자리에 배정된 선수를 고르는 행위는 `교체`와 구별한다. 기존 `placeOnBoard` 방식은 그 선수의 원래 자리를 비워 버리므로 팀 인원 균형이 무너질 수 있다. 첫 구현에서는 기본 후보에서 제외하고, 후속 `자리 교환`을 명시적인 두 자리 맞교환으로 제공하는 편이 안전하다.

교체는 편성 초안의 변화다. 참가 신청 취소가 아니다. 대기자를 교체 배치해도 초안 저장만으로 신청자 승격이 일어나지 않고, 공개 성공 때만 기존 명단 규칙대로 승격한다. 미신청 회원을 선택한 경우에는 저장/공개 전 참가자 추가 확인을 유지한다.

## 후보의 우선순위와 필터

현재 `주 포지션 / 부 포함 / 전체`는 **포지션만 거르는 필터**다. `전체`를 누르면 미신청 회원과 이미 배정된 사람까지 같은 스크롤 풀에 표시된다. 참가 신청자를 먼저 다루려는 운영 흐름이 필터 명칭과 화면 구조에 담겨 있지 않다.

권고안은 필터의 첫 차원을 **참가 상태**로 바꾸고, 포지션 적합도는 목록 안의 순서와 작은 구분 제목으로 처리하는 것이다.

```text
검색: 이름 또는 소속
[신청자 3] [대기자 1] [미신청 회원]
주 포지션에 맞는 신청자
  김서현   더브이    [배정/교체]
부 포지션에 맞는 신청자
  …
센터에서 선택 가능한 세터  (해당할 때만)
  …
```

- 기본은 **미배정 신청자**다. 신청자 내부에서 주 포지션 → 부 포지션 → 해당 역할에 허용된 세터 순서로 보여준다. 빈 그룹은 생략한다. 부 포지션을 보기 위해 필터를 한 번 더 누를 필요가 없다.
- 대기자는 명시적인 상태 선택으로 확인한다. 팀에 넣고 재공개할 때 승격되는 기존 규칙을 화면에서 바꾸지 않는다.
- 미신청 회원은 기본 목록에 섞지 않는다. `미신청 회원`을 선택하거나 이름/소속 검색 결과에 일치할 때만 회색 계열로 표시한다. 배정하면 저장 직전 참가자 추가를 확인한다.
- 이미 배정된 신청자는 기본 추천 목록 밖의 접을 수 있는 `배정된 선수` 영역에서 현 위치와 함께 확인한다. 다른 자리에 옮기거나 맞교환하는 동작은 위 4번 정책을 확정한 뒤 별도 명령으로 만든다.
- 검색은 모든 상태를 찾되 결과를 신청자 → 대기자 → 미신청 회원 순서로 구분한다. 검색된 미신청 회원이 신청자로 오인되지 않게 출처를 남긴다.

이 방식은 후보 필터 줄의 높이를 거의 유지하면서 신청 자격을 선택의 최우선 기준으로 만든다. 단점은 `전체` 한 번으로 모든 프로필을 섞어 보던 빠른 탐색이 사라지는 것이다. 그 용도는 검색과 명시적인 상태 선택으로 대체한다. `주 포지션만 보기`가 꼭 필요한 경우에는 목록 제목 옆 좁은 보조 필터로 둘 수 있으나 기본 화면에는 추가하지 않는 편이 낫다.

## 버튼 배치와 모바일 높이

취소/저장/공개를 하단 고정 탐색 바에 함께 넣으면 후보 스크롤 높이와 `이전 / 전체 팀 / 다음`의 역할이 충돌한다. 지금처럼 상단에서 세 동작을 같은 폭의 44px 버튼으로 유지하는 편을 권한다. 390px에서는 너비가 늘고 높이는 늘지 않는다. 320px에서는 제목 옆 배정 요약을 한 줄로 묶고 버튼 세 개를 그 아래 한 줄에 둔다. 저장/공개는 서로 결과가 다르므로 한 메뉴에 숨기지 않는다.

전체 팀 보기는 배정 작업과 달리 내부 스크롤 화면이다. 390px에서 보기 전환 한 줄, `자동 배치 / 팀 추가` 한 줄로 정리해 한 버튼만 홀로 내려가는 문제를 없앴다. 코트/행은 팀 데이터가 아니라 읽는 방식을 바꾸므로, 전환해도 선택 선수와 초안은 그대로 유지한다.

## 구현 단위와 검증 기준

다음 변경은 ① 후보 조회/정렬 함수, ② 선택 자리와 원자적 교체 명령, ③ 화면 연결의 순서로 나누는 것이 안전하다. `position-board-model.ts`와 `allocation-ab-model.ts`의 순수 검사 후 `ContinuousAllocation` 렌더 통합 검사로 실제 타일 선택·후보·배정 결과를 함께 확인한다. 특히 **마지막 빈자리 배정 후 풀 유지, 채워진 자리 선택→미배정 신청자 교체, X 해제 취소/확인, 대기자/미신청 회원 저장 경계, 팀 사이 기존 선수 이동 시 중복·빈자리**를 검증해야 한다. 320/390px의 후보 가시 높이와 키보드·스크롤도 확인한다.

이미 배정된 두 선수의 이동은 `빈자리 생성`과 `맞교환` 중 어떤 결과를 원하는지 정한 뒤 구현해야 한다. 기본 교체는 미배정 후보만 사용하므로 이 선택이 현재 요청의 코트 전환·소속 표시·신청자 우선 배치에 영향을 주지 않는다.
