# SIDEOUT 명단·운영진 취소 독립 검토 인계

## 검토 범위

대상은 `docs/design-review/shadcn-prototype`의 로컬 목업이다. 실제 앱 `web/`의 기능 배포나 서버 저장, 계정 권한 검증을 완료했다는 뜻은 아니다. 요구와 상태 전이는 [ROSTER_CANCELLATION_SPEC.md](./ROSTER_CANCELLATION_SPEC.md)에 적었다.

주요 변경 파일은 `src/roster-dialog.tsx`, `src/roster-model.ts`, `src/main.tsx`, `src/styles.css`, `src/roster.test.tsx`, `src/roster-transitions.test.tsx`다. 비교용 A안과 `web/`은 수정하지 않았다. 이 작업 폴더에는 Git 메타데이터가 없어 커밋 또는 diff 기준점을 제시할 수 없으며, 현재 파일을 검토 기준으로 삼는다.

## 구현된 동작

- 운영진 명단은 소속 회원, 게스트, 대기자를 분리한다. 소속 회원 타일에는 이름만 두고 게스트·대기자는 이름 아래 작은 소속을 둔다. 일반 회원은 자기 모임 회원 이름과 게스트 수만 본다.
- 운영진은 타일의 `취소` 버튼에서 신청 또는 대기 등록을 취소한다. 버튼의 접근성 이름은 회원 이름과 등록 상태를 포함한다. 확인 화면에는 대상 이름을 쓰고, 공개 팀 배정 선수라면 공개된 자리도 빈다는 점을 명시한다.
- 취소는 해당 회차 명단, 신청자·대기자 수, 팀편성 후보, 해당 선수의 초안·공개 배정에 반영한다. 다른 선수의 초안 수정은 공개하지 않는다.
- 공개 후 취소한 회원을 다시 추가하면 대기자로 들어가며 공개 팀의 빈자리에 자동 복귀하지 않는다.
- 기본 샘플 공개 팀편성을 다시 구성할 때 현재 본인의 미신청 상태를 보존한다. 운영진이 본인 신청을 공개 전에 취소했다면 본인의 재신청 시 제외 기록을 해제한다. 공개 후 본인 재등록은 대기 상태를 유지한다.
- 명단 하단에 `참가자 추가`와 `닫기`를 모아두고, 기존 복수 선택·검색 추가를 유지한다.

## 실행·재현

`npm run build`가 만든 화면: [명단 취소 검토 화면](http://localhost:4173/weekend/a-shadcn/?state=published&review=roster-state-fix-v3#/session/2026-09-27-nb?week=0&filter=all). 로컬 서버가 실행 중이어야 하며 새로고침하면 샘플 상태가 초기화된다. 상단 권한 미리보기에서 마스터/운영자/일반 회원을 전환할 수 있다.

1. 마스터 상태로 뉴배동 9월 27일 상세의 `명단 확인`을 연다. 소속 회원과 게스트 타일, 하단 추가·닫기 버튼을 확인한다.
2. 김도윤 타일의 `취소`를 누른다. 공개 팀편성의 자리가 비워진다는 안내와 확인 버튼을 살핀다. 취소 뒤 명단 21→20명, A팀 7→6명, 김도윤 부재를 확인한다.
3. 다시 명단의 `참가자 추가`에서 김도윤을 선택한다. `대기자` 1명으로 돌아오고 A팀은 6명인 채 유지되는지 확인한다.
4. 일반 회원 미리보기에서는 타일 취소·추가 버튼과 게스트 실명이 보이지 않는지 확인한다. 다른 모임 운영자에게 뉴배동 관리 동작이 없는지도 확인한다.
5. 모바일 390×844 및 320px 폭에서 타일, 취소 버튼, 확인 화면, 하단 작업 버튼, 내부 스크롤, 포커스 복귀를 확인한다. 실제 iPhone의 터치·키보드 검증은 아직 하지 않았다.
6. `state=published-unapplied`로 연 뒤 김도윤을 취소한다. 인원 20→19명이며 김나래가 명단·공개 팀에 나타나지 않는지 확인한다. 일반 회원으로 바꿔 공개본 열람도 차단되는지 확인한다.
7. `state=applied`로 연 뒤 운영진이 김나래 신청을 취소하고, 그녀가 다시 `참석 신청`을 누른다. 인원 20→21명, 명단 복귀, 본인 취소 가능 여부를 확인한다.

## 수행한 검증

- `npx vitest run --config vitest.allocation.config.ts`: 5개 파일, 24개 테스트 통과. 기존 명단·팀편성 검사에 더해 공개 후 미신청 본인 유지, 공개 전 취소 후 재신청, 공개 후 대기 재등록을 React 화면에서 검사한다.
- `npm run build`: TypeScript 검사와 Vite 빌드 통과.
- `impeccable detect --json src/roster-dialog.tsx src/styles.css`: 기본 탐지 결과 `[]`.
- 이전 화면 검증에서는 데스크톱 두 열, 390px 두 열, 320px 한 열의 명단 배치와 내부 스크롤·하단 버튼을 확인했다. 이번 수정의 새 탭에서는 모바일 폭의 초기 상태(미신청·공개 후, 20명, 본인 미배정)를 확인했다. 자동 브라우저 제어에서 버튼 클릭 후 화면 변화가 없어 새 회귀 경로의 실제 브라우저 상호작용은 검증하지 못했다. 해당 경로는 위 React 통합 검사로 검증했으며 실제 iPhone Safari 검사는 남아 있다.

## 독립 검토에서 집중할 지점

- 권한 경계: 화면에서 취소 버튼이 숨겨지는 것과 실제 취소 함수의 회차·모임 권한 검사 모두 확인한다.
- 데이터 일치: 기본 샘플 신청자, 수동 추가 신청자, 대기자 각각의 취소·재추가가 명단·카운트·초안·공개본에서 같은 결과를 내는지 확인한다.
- 공개본 안전성: 취소 대상 외 다른 선수와 공개 팀은 바뀌지 않고, 공개되지 않은 초안 수정이 노출되지 않는지 확인한다.
- 접근성: 좁은 화면과 키보드 사용에서 직접 취소 버튼, 확인 화면, 취소 후 초점, 44px 터치 영역을 확인한다.

실제 로그인·계정 발급, 서버 영속성, 동시 편집, 실제 iPhone Safari 입력·터치 동작은 이번 검증 범위 밖이다. 앞선 독립 검토(`/Users/donnieyu/.codex/review-runs/2026-09-28-roster-cancellation-implementation-v2/report.md`)의 두 회귀 지적을 반영했으며, 이 문서는 후속 검토를 위한 재현 자료다.
