# 운동 등록 화면 — 설계 기록

> 최신 적용: 별도 등록 페이지/메뉴를 제거하고 홈의 해당 주 등록 카드→기존 일정 상세 편집으로 통합했다. 아래 1차 설계는 이전안이다. 최신 동작과 확인은 README의 「달력 등록 통합·복수 운영 권한」 및 「등록 상태 구분·등록된 회차 수정」을 따른다. 회원 관리 계획은 ../../../docs/MEMBER_ADMIN_PLAN.md를 참조한다.

2026-09-23. 화면 경로: `weekend/a-shadcn/#register`. 운영 web과 서버 데이터는 수정하지 않는다.

## 작업 목적

매주 같은 장소·시간에 운동하는 운영자가 정기 정보를 반복 입력하지 않고 새 회차의 신청을 준비한다. 현재 회원 화면의 색감·버튼·하단 계정 영역을 유지하면서 운영용 입력 화면을 확장한다.

## 선택한 구성과 대안

- 추천안: 한 화면의 폼+실시간 미리보기. 모임/날짜→참가 신청→공지 순서. 반복 작업에 단계 이동이 적고 신청 마감과 운동 시간을 함께 비교할 수 있다. 단점은 세로 길이이며, 시간 변경은 접고 모바일은 한 열로 줄인다.
- 단계형 등록은 처음 배우기에는 쉽지만 매주 반복하기에 클릭이 늘고 이전 입력과 비교하기 어렵다.
- 작은 등록 모달은 진입이 빠르지만 날짜·모집 정책·공지까지 편집하기에는 공간과 모바일 스크롤이 부족하다.

## 범위와 규칙

- 마스터: 등록된 다섯 모임 선택. 회장·추가 운영진: 담당 뉴배동만 표시. 회원 생성·대리 신청 권한과는 별개다. 역할 선택은 목업 체험용이며 인증이 아니다.
- 정기 장소/입장/시작/종료를 기본값으로 불러오고 이번 회차만 변경한다. 변경이 정기 설정이나 기존 회차에 전파되지 않는다.
- 기본 날짜는 고정 샘플 현재일(2026-09-23) 이후의 미등록 정기 운동일이다. 기존 샘플 회차가10/4까지 있으므로 뉴배동은10/11,토요일 모임은10/10을 제안한다.
- 우선 기간 사용 여부 및 종료, 일반 마감, 일반 상한, 공지를 설정한다. 우선 기간 외부 회원 신청 가능/정규 소속 회원 편성 보장/상한 초과 후보 허용 규칙을 유지한다. 후보 종료는 운동 시작과 연결한다.
- 준비로 저장은 draft,모집 시작은 open으로 샘플 목록에 반영한다. 준비 목록을 불러와 계속 작성하고 같은 기록을 모집 상태로 변경할 수 있다. 모집 시작 후 해당 폼은 잠가 실수로 준비 상태로 되돌리지 않는다. 열린 회차 수정·종료는 이번 범위가 아니다.
- React 메모리의 샘플 목록은 페이지를 오가도 유지되지만 새로고침하면 초기화된다. 실제 홈 카드 생성·모집 접수·서버 저장·실제 권한 검증은 연결하지 않았다. 이는 등록 화면 검토 단계이며 운영 기능이 완성된 것으로 표시하지 않는다.

## 이번에 제안한 기본값 (확정 운영 정책 아님)

우선 종료는 운동2일 전18시, 일반 마감은1일 전18시로 시작하며 변경할 수 있다. 날짜 변경 시 두 값도 다시 계산되고 폼에 이를 안내한다. 같은 모임/같은 날짜의 중복 등록은 막는다. 한 모임이 같은 날 복수 회차를 운영할 경우 중복 기준을 시간 구간으로 바꾸어야 한다. 예약 오픈은 넣지 않고 직접 모집 시작을 기본으로 제안한다.

## 구현과 확인

`src/registration.tsx`, `src/registration-model.ts`를 추가했다. Input/Textarea는 기존 운영 저장소의 shadcn 컴포넌트를 목업으로 복사했다. Select/Checkbox/Button/Card/Badge는 목업의 기존 공통 컴포넌트를 사용한다. 기본 입력 최소44px, 모바일 입력16px. 에러/성공 영역에 포커스하며 네이티브 날짜·시간 입력을 사용한다.

TypeScript/Vite 빌드와 `node scripts/check-registration.mjs` 12검사 통과. 실제 브라우저에서 마스터 모임 변경→히어로즈13:30/14:00/18:00 기본값,준비 저장→모집 시작 시 동일행1개와 입력잠금,운영진 뉴배동 고정,중복 날짜 에러/포커스 확인.320px에서 폼/입력/버튼 가로 넘침 없음,390px 단일열,1440px 폼+미리보기 확인. 날짜 입력의 툴 fill은 React 상태에 반영되지 않아 실제 ArrowUp/Down 입력으로 중복 날짜 검사를 확인했다. 날짜 정책은 모델 검사도 별도 수행했다.

스크린샷: `screenshots/registration-desktop.png`, `screenshots/registration-mobile.png`. 브라우저·OS마다 다른 네이티브 날짜 선택창의 모든 조합과 실제 모바일 기기는 검증하지 않았다.
