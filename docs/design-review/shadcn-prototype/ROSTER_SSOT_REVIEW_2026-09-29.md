# 신청·대기·취소 및 공개 팀편성 상태 재검토

검토일: 2026-09-29 KST. 대상: SIDEOUT 로컬 `shadcn-prototype`. 제품 소스는 변경하지 않았다. 현재 사용자 결정과 코드 확인, 별도 React 재현 검사에 근거한 검토·설계 제안이다.

## 1. 최신 결정과 이전 검토의 관계

**팀편성이 한 번 공개된 이후에는 본인·운영진·마스터 모두 참가 신청을 취소할 수 없다.** 공개 후 참가자는 대기자로 등록할 수 있고 운영진은 팀편성을 수정하여 추가·공개할 수 있다는 기존 결정은 유지한다. 마감 후 본인 취소 금지, 운동 시작까지 대기 접수, 권한별 정보 공개도 유지한다.

이에 따라 이전 문서 `ROSTER_CANCELLATION_SPEC.md`의 공개 후 운영진 취소, 공개 선수 삭제 후 대기 재등록 예시는 앞으로 허용할 동작의 명세로 사용하지 않는다. 과거 검토는 당시 구현을 평가한 기록으로 남기되, 후속 테스트는 공개 후 취소 성공 대신 **취소 요청 거부와 상태 불변**을 검사해야 한다.

그러나 공개 전 취소 → 첫 공개 → 대기 등록 → 운영진 배정·재공개는 허용되는 경로다. 따라서 공개 후 취소 버튼을 막는 것만으로 명단 불일치를 모두 해결할 수는 없다.

현재 질문한 정책: 공개 후 기존 공개 선수의 **배정 해제**도 금지할지, 배정 해제는 허용하되 신청자 명단에는 유지할지. 이는 신청 취소와 다른 동작이다. 답변 전에는 미확정이며 어느 쪽도 구현된 것으로 간주하지 않는다. 검토안은 아래 두 경우를 모두 다룬다.

## 3. 왜 현재 구조가 SSOT가 아닌가

`applied`, `waiting`, `manualEntries`, `excludedApplicants`, 기본 `applicantPool`, `teamRecords.draft/shared`가 각자 참가 여부 일부를 표현한다. 같은 회원이 신청 집합에서는 빠지고 공개 팀에는 남거나, 대기 집합과 제외 기록에 동시에 들어갈 수 있다. `confirmed = joined || assigned`로 팀 배정을 다시 신청 여부에 이용하여 읽기 경로가 참가 상태를 복원하는 효과도 있다.

샘플 데이터가 필요하더라도 최초 로딩 시 정규화된 회차 기록으로 한 번 넣어야 한다. 조회할 때마다 원본 샘플에 신청·취소 예외를 덧붙이는 방식은 제거하는 편이 좋다. 현재 이름이 ID인 샘플도 제품에서는 고유 회원 ID로 바꿔 동명이인을 구분해야 한다.

## 5. 권고 데이터와 읽기 규칙

회차마다 하나의 상태 묶음을 둔다.

- 회차: 회차 ID, 모임 ID, 일정, 접수 마감, 최초 공개 시각, 회차 버전.
- 참가 기록: `(회차 ID, 회원 ID)`별 한 건. 상태는 `신청 / 대기 / 취소`. 미신청은 기록이 없거나 취소 상태로 해석한다. 등록 시각·순번, 등록 주체(본인/운영진), 취소 시각·주체, 우선 편성 자격을 함께 둔다.
- 팀 초안: 편집자가 저장한 자리별 회원 ID. 참가 상태를 변경하지 않는다.
- 공개본: 공개한 자리별 회원 ID와 공개 버전. 초안 저장으로 덮어쓰지 않는다.

신청은 팀 배정 여부와 다르다. 신입 등 정규팀 밖 참여자도 신청자다. `대기→신청`은 운영진이 실제로 공개 배정하는 시점에 일어난다. 그 이전 초안 배정은 계속 대기다. 취소자를 배정하려면 먼저 적법한 재등록을 해야 하며 팀 편성만으로 취소 상태를 몰래 되살리지 않는다. 미신청 회원을 편집 중 선택하는 기존 기능은 명시적인 참가자 추가 처리와 연결하고, 참가자 추가의 저장 여부를 팀 초안과 혼동하지 않도록 한다.

공통 조회 함수는 이 기록만 읽는다.

- 신청자 목록/홈 인원 = 상태가 신청인 회원. 대기·취소는 제외.
- 대기자 목록/대기 수 = 상태가 대기인 회원. 신청자와 교집합 없음.
- 미배정 신청자 = 신청자 중 현재 운영진 작업 초안에 배정되지 않은 회원. 회원용 집계는 공개본 기준임을 구분한다.
- 공개 팀 인원 = 공개본에 배정된 회원. 신청 인원과 같을 필요는 없다.
- 본인 버튼 = 같은 참가 상태와 회차의 취소·접수 가능 여부로 계산.
- 회원용 팀 열람 = 운영 권한 또는 일반 신청 자격 또는 공개 배정에 따른 기존 권한. 미배정 대기자·미신청자에게 공개 팀 명단을 보여주지 않는다.

**SSOT는 모든 사람이 같은 개인정보를 본다는 뜻이 아니다.** 운영진은 소속·타 모임·대기를 모두 보고, 일반 회원은 자기 모임의 소속 신청자 이름과 게스트 합계, 타 모임 회원은 허용된 인원수만 본다. 이름·내부 평가·신청 순번/시각은 권한에 맞게 응답에서 제외한다. 각 화면은 같은 참가 기록에 권한별 표시 범위를 적용해야 한다.

## 6. 허용 상태 전이

| 회차 상태 | 새 신청/운영진 추가 | 본인 신청 취소 | 운영진 신청 취소 | 초안 편집/공개 |
| --- | --- | --- | --- | --- |
| 미등록·준비 | 불가 | 불가 | 불가 | 준비만, 회원에게 비공개 |
| 모집 중·마감 전·미공개 | 신청자로 등록 | 가능 | 담당 권한으로 가능 | 가능 |
| 마감 후·미공개·운동 시작 전 | 대기자로 등록 | 불가 | 공개 전 운영진 정정은 허용하는 안을 권고 | 가능 |
| 최초 공개 후·운동 시작 전 | 대기자로 등록 | **불가** | **마스터 포함 불가** | 권한 있는 운영진 수정·재공개 가능 |
| 운동 시작 후/과거 | 불가 | 불가 | 불가 | 현재 기능에서는 읽기 전용 |

운영진의 마감 후·공개 전 취소는 기존 구현 범위를 유지하는 제안이며 최신 사용자 결정이 직접 확정한 것은 공개 이후 금지다. 공개 이후에는 신청자뿐 아니라 대기 등록의 철회도 금지하는 해석을 기본으로 기록한다. 대기자만 예외를 두려면 별도 정책으로 명시해야 한다. 공개 전 대기 철회는 과거 합의가 없고 현재 본인 UI도 제공하지 않으므로 새 기능으로 추가하지 않는다.

취소 가능 시간에 취소하면 참가 상태와 초안의 해당 배정을 하나의 처리에서 함께 제거한다. 재신청 시 일반 접수인지 대기인지는 당시 접수 상태로 판단한다. 순번·우선 자격은 새 신청 시각 기준으로 다시 계산하는 것을 권고한다.

공개 명령은 다음을 한 번에 적용한다: 권한/시간/현재 버전 검증 → 참가 자격·중복·팀 검증 → 배정된 대기자의 신청자 전환 → 공개본 저장 → 버전 증가. 실패하면 모두 미반영이다. 초안 저장은 참가자 전환이나 공개본 변경을 일으키지 않는다.

## 7. 공개 후 편집과 취소의 구별

공개 후에도 대기자를 추가 배정하고 재공개하는 기능은 유지된다. 다음 두 안 중 결정이 필요하다.

1. **기존 공개 선수 보존:** 팀 간 이동·자리 교환·대기자 추가는 허용하고 기존 공개 선수를 빠뜨린 재공개는 거부한다. 초안 작업 중 일시적으로 자리를 비우더라도 공개 직전 기존 공개 선수 집합이 유지되어야 한다. 공개 후 취소 금지를 가장 엄격하게 해석한 안이다.
2. **배정 해제 허용:** 팀에서 빠져도 참가 상태는 신청으로 유지한다. 자동으로 취소 또는 대기로 바꾸지 않는다. 신청 인원은 그대로이고 배정 인원만 줄어든다. 실제 현장 조정에는 유연하지만 신청자와 출전 확정자를 구별해야 한다.

어느 안이든 기존 공개본의 선수를 화면에서 빼는 동작을 신청 취소 함수에 연결하지 않는다. 실제 갑작스러운 불참 처리가 필요하다면 향후 출석 결과/운영 기록으로 다룰 수 있지만, 현재 확정한 공개 후 취소 금지에 임의의 관리자 예외를 만들지 않는다.

`firstPublishedAt`는 첫 공개 이후 지우지 않는다. 재편집·마감 연장·초안 저장으로 공개 전 상태로 되돌려 취소 제한을 우회하면 안 된다. 공개 후 회차를 준비 상태로 내리는 동작도 참가자 잠금을 풀어서는 안 된다.

## 8. 다중 사용자에서 필요한 조건

목업의 React 상태를 하나로 묶는 것만으로 여러 사용자에게 같은 최신 명단이 제공되지는 않는다. 실제 제품에서는 서버의 회차 참가 기록이 최종 원본이어야 한다. 로컬 단계에서는 같은 도메인 명령/검사 규칙을 reducer로 구현하고, 이후 서버 명령 처리로 옮기는 구조를 권한다.

- 모든 명령에서 서버가 권한·서버 시각·최초 공개 여부를 다시 검사한다. 버튼 숨김은 UX일 뿐 최종 검사가 아니다.
- 참가 취소와 팀 공개가 동시에 들어오면 회차 버전과 트랜잭션으로 순서를 확정한다. 먼저 공개되었다면 취소 거부, 먼저 취소되었다면 오래된 초안의 공개 거부/재검토.
- 중복 클릭·재시도는 같은 명령 ID로 한 번만 반영한다. 회원 중복 등록은 회차+회원 유일 조건으로 방지한다.
- 명단과 인원수, 공개본을 같은 버전으로 반환한다. 별도 캐시를 갱신할 경우 모두 무효화/재조회한다. 다른 기기의 열린 명단도 재조회 또는 구독으로 갱신한다.
- 저장 실패 시 성공 안내를 띄우지 않고 입력을 유지한다. 오래된 확인창의 취소도 실행 시 최신 상태를 재검사한다.
- 신청 상한과 우선 편성은 등록/공개 명령의 검사에 포함한다. 현재 목업의 `registrationMode`는 공개/마감만 판단하고, 저장된 상한/우선 기한을 접수·공개 검증에 연결하지 않는다. 설정 필드가 존재하는 것과 해당 정책이 적용되는 것은 구별해야 한다. 상한 도달 시 대기 등록, 보장 회원을 누락한 공개 거부 등의 세부 규칙을 구현 전에 수용 조건으로 확정한다.
- 내부 프로필(주·부 포지션/실력)과 공개 배정 포지션은 구별한다. 공개 편성에 쓰는 포지션을 보여준다고 내부 평가 프로필 전체를 노출하지 않는다.

## 9. 필요한 검사와 권고 작업 순서

1. 새 정책을 기준으로 공개 후 본인/운영진/마스터 취소 거부를 UI와 명령 양쪽에 명세화한다. 성공을 기대하던 이전 공개 후 취소 검사를 거부·상태 불변 검사로 교체한다.
2. 회차 참가 기록을 정규화하고 샘플도 처음 한 번만 이 형식으로 초기화한다. 화면마다 따로 유지하던 신청·대기·제외 목록을 제거한다.
3. 본인 신청/운영진 복수 추가/취소를 같은 명령 처리로 통일하고, 공개의 대기 승격과 공개본 저장을 하나의 원자적 처리로 묶는다.
4. 홈·상세·명단 모달·팀편성 후보·내 버튼·열람 권한을 공통 조회 결과에 연결한다. 미신청 회원은 검색 자원으로만 표시하며 미배정 신청자 카운트에 넣지 않는다.
5. 허용/금지 경계와 복합 경로를 검사한 뒤 실제 모바일에서 완료한다.

검사 행렬은 역할(본인/담당 운영진/마스터/권한 없는 운영진), 회차(준비/접수/마감/공개/시작 후), 등록 주체(본인/대리), 참가 상태(미신청/신청/대기/취소), 편성 상태(없음/초안/공개), 명령 중복·오래된 버전을 포함한다. 모든 조합을 무작정 생성하기보다 불변 조건별로 대표 전이를 고른다.

필수 불변 조건:

- 같은 회원은 한 회차에서 신청자와 대기자에 동시에 속하지 않는다.
- 공개 후 어떤 취소 요청도 참가 기록·초안·공개본을 변경하지 않는다.
- 취소 가능 시 취소는 등록 주체와 무관하게 동일한 결과이며 초안의 잔류 배정이 없다.
- 공개된 배정자는 신청 상태이며, 초안에만 배정된 대기자는 아직 대기다.
- 신청 인원=권한 적용 전 신청자 원본 수, 대기 수=대기 원본 수, 미배정 수=신청자와 해당 편성의 차집합이다.
- 일반적인 팀 이동은 신청자 수·대기 수를 바꾸지 않는다.
- 공개 전 취소→공개 후 대기→공개 배정은 취소 이력 없는 동일한 최종 상태와 결과가 같다.
- 불허/실패 명령·중복 명령은 부수 효과가 없고, 다른 회차에 영향을 주지 않는다.
- 일반 회원의 응답에 비공개 명단·순번·평가가 포함되지 않는다.

현재는 검토·설계 제안까지다. 다중 사용자 동시성, 실제 계정 권한, 서버 저장, iPhone Safari 터치 동작을 검증 완료로 주장하지 않는다.
