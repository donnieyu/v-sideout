# 회원·운영자 계정 등록 계획

> 2026-09-29: 회원 접근·계정 발급·관리의 현행 기준은 [회원 접근·계정 관리·공개 배포 SSOT](ACCESS_AND_DEPLOYMENT_SSOT.md)로 이동했다. 아래 소속·권한 규칙은 새 문서에 승계했으며, 이 문서는 2026-09-23 설계 맥락으로 보존한다. 계정 기능의 구현 완료를 뜻하지 않는다.

기록 시점 사용자 결정: 2026-09-23. 당시 적용은 로컬 목업의 권한 예시와 등록 진입에 한정한다.

## 계정의 소속과 운영 권한은 별도

- **회원 소속**: 기존대로 모임 하나 또는 무소속. 마스터가 지정하고 본인이 변경하지 않는다.
- **운영 권한 모임**: 운영자 한 명에게 여러 모임을 지정할 수 있다. 운영자의 단일 소속 모임은 기본 운영 권한에 포함하고, 그 외 모임을 추가로 지정한다. 복수 운영 권한을 회원의 복수 소속으로 해석하지 않는다.
- **마스터**: 소속 모임이 없으며 내 모임 하이라이트를 표시하지 않는다. 모든 등록 모임의 운동 등록 권한. 특정 모임 목록을 수동으로 모두 체크해서 얻는 권한이 아니다.
- **모임 운영자**: 자기 소속 모임과 마스터가 추가로 지정한 모임들에 한해 운동 등록·준비를 수행한다.
- 복수 모임 선택 자체가 회장 전용 권한을 부여하지 않는다. 기존 마스터·회장/추가 운영진의 대리 신청 및 예외 배정 차이는 그대로 유지하고 역할별 권한을 모임별로 판정한다.

## 향후 계정 등록 화면

1. 회원 기본 정보와 단일 소속 모임(또는 무소속)을 입력한다.
2. 운영자 계정이면 소속 모임을 필수로 지정하고 해당 모임의 기본 운영 권한을 표시한다. **추가 운영 권한 모임**을 체크박스 등으로 다중 선택한다. 소속 모임을 중복 지정할 필요는 없다.
3. 선택한 모임 목록을 확인한 뒤 마스터가 계정을 생성한다.
4. 추가 운영 권한의 부여·해제·변경도 마스터만 처리한다. 소속 모임의 기본 권한은 운영자 역할에 포함한다. 본인/일반 운영자가 권한 모임을 확장할 수 없다.
5. 실제 서버 인증·권한 검사에서도 대상 모임의 권한을 확인한다. 메뉴나 카드 숨김만으로 보안을 구현하지 않는다. 권한 회수 후에도 이전에 열어둔 편집 화면을 통해 저장되지 않도록 서버에서 다시 검사해야 한다.

마스터 계정은 `homeClubId=null`로 관리한다. 운영자는 `homeClubId`를 기본 운영 범위에 합하고 중복 없이 추가 권한을 적용한다. 일반 회원은 소속만으로 운영 권한을 받지 않는다.

권장 데이터 구분: `homeClubId: clubId | null`과 모임별 운영 권한 목록을 별도로 관리한다. 현재 로컬 목업의 `managedClubIds`는 등록 UI 검토를 위한 단순 예시다. 실제 역할별 권한·계정 저장 스키마는 회원 관리 구현 시 확정한다.

## 달력과 등록 화면에 반영할 규칙

- 홈의 주 선택 후, 권한이 있는 모임의 정기 날짜·시간 위치에 기존 준비 카드와 같은 간단한 등록 카드를 표시한다. 버튼은 **모임 등록**이다. 모임 신규 생성 기능이 아니라 해당 모임의 운동 회차 등록 진입이다.
- 준비로 저장한 회차는 해당 운영 권한 보유자에게만 보인다. 회원의 카드·운동 개수에는 포함하지 않는다.
- 모집 시작 이후 회원 홈에 실제 운동으로 표시한다.
- 계정은 발급되지 않았지만 달력을 탐색했다는 이유로 회차가 자동 생성되지는 않는다. 등록 카드는 권한 기반의 진입점이다.

## 현재 상태

실제 로그인·계정 발급·다중 운영 권한 지정 UI는 **계획만 기록**했다. 로컬 목업 상단의 회원/마스터/운영자(뉴배동)/운영자(뉴배동·히어로즈)는 디자인 검토를 위한 예시이며 인증이 아니다. 운영 web·서버 계정 데이터는 변경하지 않았다.
