# 회원 접근·관리 개발 로드맵

갱신: 2026-09-30 · 담당 A(회원·인증)  
기준: [회원 SSOT v0.8](ACCESS_AND_DEPLOYMENT_SSOT.md), [기존 인증 검토](reviews/MEMBER_AUTH_REUSE_REVIEW_2026-09-29.md), [Task 1·2 인계](reviews/MEMBER_AUTH_TASK1_2_HANDOFF_2026-09-29.md), [Task 3 인계](reviews/MEMBER_AUTH_TASK3_HANDOFF_2026-09-30.md), [Task 4 인계](reviews/MEMBER_AUTH_TASK4_HANDOFF_2026-09-30.md), [M2 인계](reviews/MEMBER_MANAGEMENT_M2_HANDOFF_2026-09-30.md), [M3 화면 인계](reviews/MEMBER_ACCESS_M3_UI_HANDOFF_2026-09-30.md), [통합 계획](INTEGRATION_PLAN.md) 9절.

**기존 회원의 사전 등록 → 임시 로그인 → 첫 비밀번호 변경을 먼저 완성한다.** 그다음 신규 신청·승인·메일을 연결한다. 두 경로가 완성되고 통합/운영 검증을 통과한 뒤 공개 URL을 제공한다. 아래 단계 구분은 신규 가입 요구를 출시 범위에서 제외한다는 뜻이 아니다.

## 확정 정책과 설계 선택

- 사용자 확정: 최소 **8자**, 영문·숫자 포함. 생일/이름 의미 검사와 특수문자·대소문자 혼합 필수 없음.
- 사용자 확정: 임시 비밀번호 **7일** 유효, 동일 임시 비밀번호 유지 불가. 미활성 계정도 만료만으로 아이디 자동 반환 없음.
- 기존 확정: 무소속 선택, 내부 공백 없는 고유 로그인 ID, 비활성 ID 보존, 마스터가 신규 신청의 최종 ID 선택, 중복 발급 방지.
- 구현 제안: 기존 코드의 NFC/소문자 비교키·앞뒤 공백 정리를 재사용. 비밀번호에는 변환하지 않는다. 아이디 허용 문자·최대 길이는 계정 관리 상세 설계에서 정한다.
- 구현 제안: 초기에는 기존 코드의 세션 12시간을 설정값으로 분리해 유지하되 제한 세션은 임시 자격 만료를 넘지 않는다. 실제 운영 전 사용성/런타임 검사에서 확정한다.
- 기존 회원 이메일 선택과 파일 가져오기는 별도 제안이다. 첫 사전 등록 화면은 수동 등록을 우선 설계하여 파일 형식 결정에 종속시키지 않는다.

## M2–M4 상세 계획에서 유지할 데이터 경계

| 원본 | 소유자 | 처리 원칙 |
| --- | --- | --- |
| 회원/로그인 ID/권한 | A | 불변 내부 ID와 서비스 전체 유일 로그인 비교키. 비활성·미활성 만료도 키 유지 |
| 가입 신청 | A | 희망 닉네임/이메일/희망 소속과 결정 상태. 신청만으로 아이디 예약/계정 생성 안 함 |
| 자격 발급 | A | 발급 ID·회원 ID·자격 버전·만료·전달 상태. 명시적 재발급만 버전 갱신 |
| 메일 작업 | A | 발급 ID에 결합한 중복 방지 키, 성공/실패/불명 분리. 재시도는 새 계정/비밀번호 생성 금지 |
| 참가 이력/레거시 참조 | R/I | I가 검토된 ID 매핑을 적용. 닉네임 동일성만으로 합치지 않음 |

최초 승인 명령은 신청 상태 전이, 회원/아이디 점유, 발급, 발송 작업을 함께 확정한다. 같은 신청 재시도는 같은 결과를 반환하고 다른 신청의 동일 아이디 충돌은 발송 전에 실패한다. 외부 메일은 DB 확정 후 실행한다. 전달용 임시 자격의 단기 암호화 보관·폐기와 재발급/발송 동시성은 M4 상세 계획의 필수 결정이다. 이를 정하기 전에 평문 자격을 일반 DB에 저장하지 않는다.

## 화면 파일·통합 경계 제안

- 새 화면은 인수한 W의 `components/member-access/`에 작성하고 기존 `components/ui/`를 소비한다. 기존 참가 프로토타입·공통 스타일을 수정하지 않는다.
- A 화면 모듈 후보: `login-form.tsx`, `password-change-form.tsx`, `join-request-form.tsx`, `member-admin.tsx`. API 클라이언트는 `lib/member-access-client.ts`에 둔다.
- 독립 미리보기만을 위한 두 번째 앱을 만드는 이전 제안은 우선순위를 낮춘다. 합성 데이터 미리보기와 실제 API 연결 상태를 구분해 표시한다.
- `app/` 공개/보호 경로, 앱 셸·내비게이션 연결은 I가 담당한다. A는 컴포넌트·계약을 넘기며 루트 레이아웃/업무 API를 직접 변경하지 않는다.
- UI 실행 계획 작성 시 frontend 디자인 지침과 기존 모바일 기준을 읽고 화면/브라우저 증거를 남긴다. 320px/390px, 직접 URL, 새로고침, 뒤로가기, 만료, 입력 보존, 비밀번호 자동완성을 확인한다.

## 통합 담당에게 전달할 계약

- A가 토큰 진위·만료·비활성·버전·최초 변경 상태를 검증한다. I의 `requireBusinessPrincipal`은 A 결과 중 정상 상태만 업무 API에 허용한다.
- 브라우저 `SessionView`에는 최소 회원 정보만 제공한다. 비밀번호 해시·토큰·이메일·권한 원본을 포함하지 않는다.
- 서버 전용 권한 결과의 `grants`는 소속 기본 역할과 추가 역할을 A가 합성한 **최종 유효 목록**이다. I가 다시 합산하지 않는다. 동일 모임 명시 권한 우선과 중복 명시값의 첫 일치 규칙을 I와 확인했다. 빈 배열이어도 일반 참가 자격을 부정하지 않는다.
- 계정 비활성화/재발급/권한 변경 시 인증 버전을 갱신하고 기존 자격을 거절한다. 업무 저장 직전 권한 변경 경합은 I와 저장 경계를 함께 검증한다.
- M3 `MemberAdmin.onDirtyChange`는 편집 중 여부를 I 앱 셸에 전달한다. I는 내부 경로 이동·브라우저 뒤로가기에서 저장/폐기 확인을 연결한다. 컴포넌트의 `beforeunload`는 새로고침·탭 종료만 보호한다.
- 각 인계에는 실제 파일 해시·커밋, 새로 실행한 검사, 미검증 범위, 알려진 실패를 기록한다. 현재 기준 `v-sideout/docs/`를 코드와 같은 저장소에서 관리하며 과거 `v-team-builder/docs/`는 보존용으로 둔다.
