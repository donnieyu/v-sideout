# 경기 순서 편집 실제 앱 승격

2026-10-06. 사용자 승인 목업과 누적 요청을 구현한다. 마스터/해당 모임 운영자가 저장된 팀편성에 맞는 경기 순서를 별도 자식 화면에서 조절하고 저장한다. 팀편성과 참가 명단은 바꾸지 않는다.

## 결정/범위
- 기존 승인 흐름의 이식. 3팀 3라운드(3경기씩), 신입 기본 2팀·라운드 사이 한 경기. 4팀 1라운드(6경기), 신입 앞뒤 한 경기. 1~2팀은 편성 초안만 허용하여 경기 편집 없음.
- 신입 경기 포함 토글, 신입 2~4팀 선택 및 순차 대진, 신입 경기 추가/삭제/대진 선택. 일반 경기는 삭제/대진 변경 없이 순서 이동.
- 손잡이 드래그(터치/마우스), 키보드 위/아래. 일반 페이지 스크롤은 유지. 전체 행이 아닌 손잡이만 touch-action:none. 이동 시 안내, 모바일에서 줄바꿈/가로 넘침 방지.
- 상단 취소/저장, 저장 후 편집 유지, 미저장 이탈 보호. 20분씩 시작/종료 재계산, 운동 종료 초과는 경고하되 저장 허용.
- 저장은 인증·권한·서버 시간·session/roster revision CAS·commandId 재시도 검증. 일반 대진의 누락/추가/중복, 잘못된 팀, 중복 게임 ID, 상한 100경기 차단.
- 편집 기준은 실제 저장된 초안 팀(없으면 공개 팀). 팀 ID 집합이 바뀌면 기존 팀 저장 로직이 기본 경기 재생성. 선수만 바뀌면 사용자 순서 보존.
- 사용자 확인: 같은 팀 구성의 공개 이후 경기 순서 저장은 참석자에게 즉시 반영. 공개 팀과 다른 팀 ID 집합이면 초안만 저장하여 비공개 팀 유출 방지. 선수 배정은 공개하지 않으며 같은 구성은 팀 ID 집합의 일치로 판단.
- 기존 공개 열람 범위와 참가 신청/취소 정책 유지. 원격 배포/DB 마이그레이션/인증 파일 수정 없음.

## 대안 판단
목업 HTML 복사는 실제 회원·revision 계약과 맞지 않아 채택하지 않음. 기존 MatchPlanRecord와 원자 저장소를 확장하는 방식을 채택. 별도 경기 공개 단계는 사용자 요구와 불일치하여 만들지 않음. 새 DnD 의존성 없이 검증된 목업 pointer 패턴을 이식하되 자동 스크롤/취소/키보드 경계를 보완.

## 파일 담당 및 통합 순서
이 작업은 promotion-p1의 sideout 경기 도메인·API·컴포넌트만 담당. 원본 main 목업은 읽기 참조, 인증/프로필 작업은 편집하지 않음. 기존 변경 전 스냅샷을 보존한다.
1. match-plan 순수 함수/검증 → 2. matches API/권한/저장 및 클라이언트 → 3. 자식 화면/상세 링크/안전한 return URL → 4. 실제 브라우저 및 독립 구간 검토.

## 완료 조건
기본 생성·신입 토글/대진·이동, 권한/동시성/재시도, UI 저장 유지/실패 복구, 320/390px 화면, 실제 로컬 저장 재조회와 공개본 경계 검증. iPhone 실제 드래그는 에뮬레이션과 구분하여 사용자 확인 요청.
