# 기존 회원 접근 화면 M3 구현 계획

> 사용자 확정 [회원 SSOT](../../ACCESS_AND_DEPLOYMENT_SSOT.md)와 [로드맵](../../MEMBER_ACCESS_IMPLEMENTATION_ROADMAP.md)을 따른다. A는 `web/components/member-access/`와 `web/lib/member-access-client.ts`를 소유하며 I의 앱 셸·업무 라우트는 수정하지 않는다.

**Goal:** 사전 등록된 회원이 아이디·임시 비밀번호로 로그인하고 첫 변경을 마치며, 마스터가 기존 회원을 수동 등록·관리할 수 있는 연결 가능한 화면을 만든다.

**Architecture:** API 클라이언트는 서버 응답을 타입과 오류 코드로 정리한다. 접근 화면은 `GET /api/auth/session`의 `anonymous → password_change_required → active` 상태를 기준으로 폼을 전환한다. 마스터 화면은 실제 `api/members`만 호출하고 소속 선택지는 I가 제공할 `ClubOption[]`을 주입받는다. 화면은 운영 경로를 스스로 소유하지 않으며 I가 라우트와 앱 셸에 연결한다.

**Tech Stack:** 기존 React 19/vinext, TypeScript, CSS module, 기존 UI 컴포넌트. 추가 런타임 의존성 없음.

**Spec:** [회원 SSOT](../../ACCESS_AND_DEPLOYMENT_SSOT.md) 4.1·4.2·4.4·4.5절과 [M2 인계](../../reviews/MEMBER_MANAGEMENT_M2_HANDOFF_2026-09-30.md).

## 경계와 화면 방향

- 기존 `web/DESIGN.md`의 Operate 모드와 회청색 #f5f7fa, 흰 카드, #172535 본문, #607080 보조, #1e3e64 주 행동을 따른다. 장식보다 상태와 행동을 먼저 보인다.
- 로그인 ID는 한글/영문 닉네임 그대로 표시하고 중간 공백 입력에는 수정 안내를 한다. 비밀번호는 최소 8자·영문·숫자를 안내한다. 첫 변경에서는 현재 임시 비밀번호, 새 비밀번호, 확인만 받는다.
- 로그인·관리 응답의 `Cache-Control:no-store`에 더해 클라이언트는 `cache:'no-store'`를 사용하고 자격을 로컬 저장하지 않는다. 임시 비밀번호는 등록·재발급·재활성화 성공 직후 단일 컴포넌트 상태에만 보유하고 닫으면 버린다.
- 가입 신청은 M4 의존성이다. 동작하지 않는 링크를 만들지 않고 I가 실제 신청 화면을 연결할 수 있는 `onJoinRequest` 콜백이 있을 때만 표시한다. 비밀번호 분실 도움에는 기존 연락 경로의 마스터를 안내한다.
- 운영 모임 목록이 없으면 무소속 등록만 허용한다. 예시 모임을 운영 정본으로 사용하지 않는다. 비활성 계정도 기존 로그인 ID를 보존하고 재활성화는 같은 회원을 대상으로 한다.
- `active` 세션은 I의 실제 앱으로 넘기는 콜백을 호출한다. 클라이언트 화면만으로 업무 API 권한을 증명하거나 루트 앱 셸을 교체하지 않는다.
