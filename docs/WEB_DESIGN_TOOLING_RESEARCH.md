# 공통 웹 디자인 제작 환경 조사

조사일: 2026-09-23

사용자 선택: 여러 프로젝트에서 쓸 공통 환경. 우선순위는 디자인 완성도와 화면 구성.

## 현재 결론

디자인 방향 수립 → 화면 구현 → 실제 브라우저 확인 → UI 품질 점검을 기본 흐름으로 삼는다. 디자인 스킬 두 개로 시작하고, Figma·컴포넌트 검색·문서 검색은 필요가 확인되는 순서대로 연결한다. 아래 순위는 문서와 현재 환경을 바탕으로 한 적합성 판단이며, 화면 개선 효과를 실험으로 검증한 결과는 아니다.

스킬은 작업 방법을 담은 지침, MCP는 도구와 데이터에 연결하는 인터페이스, 플러그인은 이를 묶은 설치 단위다. GitHub는 스킬·MCP 서버·UI 라이브러리 등의 원본을 배포하는 장소다. [OpenAI 설명](https://developers.openai.com/plugins/concepts/skills)

## 확인한 환경

- Node.js v24.16.0, npm 11.13.0, Git 2.50.1, Python 3.14.6 사용 가능. pnpm과 Codex CLI도 경로가 확인되었다.
- GitHub CLI `gh`는 현재 셸 경로에서 찾지 못했다. 공개 저장소 조사와 이번 스킬 설치에는 필요하지 않았다.
- 이번 세션에 Sites 제작·호스팅, 이미지 생성, 브라우저 조작 도구가 제공된다. 각각의 실제 작동과 계정 상태를 이번 조사에서 시험한 것은 아니다.
- 플러그인 디렉터리 조회상 Figma와 GitHub는 설치 가능하지만 미설치 상태다.
- 현재 `web/`는 React·Tailwind·shadcn 계열 구성이 있는 Sites 프로젝트다. 다른 프로젝트의 공통 기술 스택으로 확정하지 않았다.

## 단계별 진행

1. **기초 환경과 디자인 스킬 — 완료:** 환경 확인, 원본 조사, 공통 스킬 두 개 설치 및 파일 검증.
2. **작은 화면으로 효과 확인 — 다음:** 선호 사이트와 주제를 받아 한 화면을 제작한다. 모바일·데스크톱 화면, 정보 위계, 타이포그래피, 콘텐츠 밀도, 버튼·폼 상태를 실제 브라우저에서 비교한다. 구현과 브라우저 검수는 아직 수행하지 않았다.
3. **필요한 연결 추가:** Figma를 사용하는 경우 플러그인, React/shadcn 구성요소 탐색이 잦으면 shadcn MCP를 도입한다. 각 연결은 실제 자료 읽기 또는 검색으로 검증한다.
4. **공통 작업 방식 정리:** 효과가 확인된 제작·검수 흐름을 재사용 가능한 스킬로 정리한다. 프로젝트별 색상·글꼴·브랜드는 프로젝트 안에 둔다.
5. **개발·배포 확장:** 문서 검색, 반복 브라우저 검사, GitHub 협업, 호스팅은 실제 필요에 따라 추가한다.

## 사용자에게 필요한 정보

- 마음에 드는 사이트 2~3개와 각 사이트에서 좋아하는 부분. 가능하면 피하고 싶은 예시도 하나.
- 자주 만들 사이트 유형: 소개/랜딩, 대시보드/관리 도구, 커뮤니티/서비스 등. 주 사용 기기와 언어.
- Figma 사용 여부, 유료 도구 허용 범위. 없으면 기본은 추가 유료 구독 없이 실험.
- 실제 첫 화면 제작 시: 대상 사용자, 핵심 행동, 대표 콘텐츠, 로고/브랜드 자료가 있으면 제공.

API 키·비밀번호는 대화에 붙여 넣을 필요가 없다. 필요한 도구를 선택한 뒤 해당 서비스의 로그인 또는 로컬 비밀값 설정 경로를 사용한다.

이번 변경은 위 두 사용자 스킬 설치와 이 조사 문서 추가다. 웹 프로젝트 구현·패키지·MCP 설정·배포에는 변경을 가하지 않았다.
