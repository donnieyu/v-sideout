## 1. 목표와 개발 방향

회원은 운동 일정과 공지를 확인하고 참석 의사를 전달한다. 운영진은 신청자·후보·직접 연락한 회원·임시 게스트를 함께 검토하여 팀을 편성하고 공개한다.

운영 흐름: 회차 준비 → 일반 신청 오픈 → 일반 신청 마감·후보 접수 → 팀 편성·공개 → 후보 접수 종료 → 운동·회차 종료. 팀 초안은 모집 중에도 만들 수 있고, 공개 이후에도 후보를 검토해 변경안을 재공개할 수 있다.

최초에는 마스터 운영자가 모임 하나의 회장 역할까지 수행한다. 추후 마스터가 여러 모임을 등록하고 회장을 연결할 수 있어야 하므로 모임별 데이터·권한 구분은 처음부터 설계한다. 다중 모임 관리 화면과 전체 계정 관리 기능은 핵심 운동 기능 이후에 개발한다.

초기 팀 편성은 수동으로 제공하고, 실력·포지션을 활용한 무작위 배치 보조 도구는 후속 개발한다. 회원 관리 화면을 미뤄도 편성에 필요한 회원 식별자·모임 소속·포지션·실력 정보는 핵심 단계부터 준비한다.

## 2. 확정 요구와 이번 검토의 결론

| 항목 | 확정 요구 또는 처리 방향 |
| --- | --- |
| 초기 운영 | 한 모임으로 테스트하되 추후 여러 모임 등록 지원 |
| 모임 등록·회장 연결 | 마스터 운영자만 모임 생성 및 회장 지정 |
| 모임 설정 | 지정된 회장이 자기 모임 장소·요일·시간 설정 |
| 모집 | 운영자가 회차를 준비하고 모집을 직접 오픈 |
| 인원 정책 | 선택적 일반 신청 상한. 도달 이후에도 후보 접수 허용. 18·21·24·28명은 참고 표시 |
| 배정 권한 | 신청 순서로 자동 선발하지 않고 운영진이 판단 |
| 마감 후 회원 동작 | 불참으로 직접 변경 불가. 새 참석 의사는 후보로 신청 가능 |
| 편성 대상 | 해당 모임의 모든 등록 회원을 운영진이 검색·대리 신청하여 활용 가능 |
| 신입 | 별도 분류. 운영진이 선택하면 정규팀 배정 가능. 배정과 승급은 별개 |
| 게스트 | 계정 없는 회차별 임시 인원으로 팀 편성 화면에서 생성 |
| 회원에게 항상 비공개 | 신청 순번·시각, 불참·미응답 명단, 실력·주·부 포지션 프로필 |
| 회원 명단 공개 | 팀 공개 전에는 인원 수만, 공개 후에는 공개된 신청·편성 명단 확인 |
| 후속 편성 도구 | 운영진이 정한 참가 대상에 포지션·실력을 고려한 무작위 배치 제안 |
| 포지션 구성 | 리베로 없음. 센터 또는 라이트 자리 하나를 세터가 맡고 해당 포지션 선수는 1명으로 감소 |
| 7명 팀 | 등록 7명 중 6명이 플레이하고 1명씩 돌아가며 휴식. 같은 포지션 인원 중복 허용 |
| 후속 개인 기록 | 출석·포지션·이벤트·팀 편성 이력 조회·집계 |

이전 기획의 ‘항상 무제한’, ‘마감 후 새 신청 불가’, ‘신청자만 편성 가능’, ‘다중 모임은 단순 후보’, ‘자동 배치는 개발 대상 아님’은 이번 요구로 대체한다.

## 3. 모임과 운영 권한

| 역할 | 권한 |
| --- | --- |
| 마스터 운영자 | 모임 생성, 회장 지정·교체, 추가 운영진 지정·해제, 전체 서비스 관리. 초기에는 테스트 모임의 실제 운영까지 수행 |
| 모임 회장 | 지정된 모임의 장소·요일·시간·모집 기본값 설정, 회차·회원·편성·게시물 운영 |
| 모임 운영진 | 해당 모임의 모집·신청자 편성·공지 운영. 대리 신청과 신입·게스트의 예외 팀 배정 불가 |
| 회원 | 소속 모임의 일정·공지 확인, 본인 응답·후보 신청, 공개된 결과 확인 |

‘운영자’라는 표현은 화면에서 마스터와 모임 운영진으로 구분한다. 추가 운영진 지정 권한은 마스터만 가진다. 모임 회장은 다른 모임 생성·회장 지정·추가 운영진 지정 권한을 갖지 않는다. 마스터가 회장을 연결하면 그 사람에게 해당 모임의 설정 권한이 생기며, 해제·교체 시 이전 권한도 회수한다.

제안: 모임 설정은 새 회차의 기본값으로 사용한다. 기본 장소·시간을 바꾸더라도 이미 공개된 회차는 자동 변경하지 않는다. 회차별 수정은 별도로 처리한다.

설계 원칙:

- 회차·게시물·회원 소속·평가·참가·편성 기록에 모임 소속을 연결한다.
- 운영진의 ‘모든 회원’ 검색은 해당 모임에 등록된 회원을 뜻한다. 다른 모임 회원은 포함하지 않는다.
- 계정과 모임 소속을 분리한다. 같은 사람이 나중에 복수 모임에 속하더라도 역할·신입 여부·평가를 모임별로 관리할 수 있게 한다.
- 마스터의 테스트 운영에서도 대상 모임을 명확히 지정한다. 모임 소유자가 없다는 이유로 모든 데이터에 공용 권한을 적용하지 않는다.
- 실제 서비스의 데이터 요청에서도 소속·권한을 검증한다. 화면 메뉴를 숨기는 것만으로 접근을 제한하지 않는다.

## 4. 회원·참가자·편성 기록의 구분

### 회원 정보

모임 소속 회원은 식별자, 표시 이름, 정규/신입 분류, 주·부 포지션, 실력 정보를 가진다. 실력은 1~5단계와 ‘미평가’를 우선 제안하며, 점수 방향·평가 기준은 추후 정한다. 포지션 미지정도 허용한다.

이 모임의 포지션 선택 항목은 센터(Middle Blocker, MB), 세터(Setter, S), 레프트(Outside Hitter, OH), 라이트(Opposite Hitter, OP)다. 리베로는 사용하지 않는다. 표시에는 익숙한 한글 명칭을 우선하고, 추후 다른 모임의 포지션 설정과 분리할 수 있게 한다.

회원 유형, 운영 권한, 신청 상태, 이번 회차 팀 배정은 별개다. 신입을 한 번 팀에 배정해도 자동 승급하지 않는다. 실력·주·부 포지션 프로필은 본인을 포함한 회원 화면에 제공하지 않는다.

### 회차 참가 상태

다음 정보를 하나의 ‘참석 여부’에 섞지 않는다.

| 구분 | 예시 | 목적 |
| --- | --- | --- |
| 참석 의사 | 미응답 / 참석 / 불참 | 회원의 의사 또는 운영진이 전달받은 의사 |
| 접수 구분 | 일반 신청 / 후보 신청 | 접수 시점·정책 구분. 팀 배정 보장이나 순위가 아님 |
| 입력 경로 | 회원 직접 / 운영진 대리 / 임시 게스트 추가 | 연락 경로와 대리 처리 기록 |
| 배정 상태 | 미배정 / 팀 배정 | 운영진의 편성 결과 |
| 실제 출석 | 미기록 / 출석 / 불참 | 후속 출석 기능에서 별도 기록 |

회원 한 명은 한 회차에 참가 기록 하나만 가진다. 후보 사유는 일반 신청 상한 도달 / 신청 마감 경과로 구분해 기록한다. 후보가 팀에 배정되어도 최초 접수 시각·사유와 대리 입력 여부를 보존한다. ‘신입’과 ‘후보’는 서로 다른 분류이며 신입도 일반 신청 또는 후보일 수 있다.

### 임시 게스트

운영진은 팀 편성 화면에서 계정 없이 이름으로 임시 인원을 추가한다. 포지션·실력은 선택 입력이며 ‘게스트 1’ 같은 기본 이름을 제안한다. 수정·팀 이동·배정 해제·제거를 지원한다.

회차 내 고유 식별자로 동명이인을 구분하고, 다음 회차에 복사하지 않는다. ‘1회용’은 지난 팀 기록 삭제를 뜻하지 않는다. 공개된 당시 이름·배정 결과는 보존한다. 계정을 제공하려면 일반 회원 등록 절차를 사용하며 신입/정규 분류는 별도로 정한다. 과거 게스트 기록을 이름만으로 새 회원에 자동 연결하지 않는다.

## 5. 모집 단계와 마감 후 후보 신청

운동 회차 상태(준비 / 진행 예정 / 종료 / 취소), 접수 단계, 편성 공개 상태를 구분한다. 팀 공개만으로 후보 접수가 종료되지는 않는다.

| 접수 단계 | 회원 동작 | 운영진 동작 |
| --- | --- | --- |
| 모집 전 | 일정 확인, 신청 불가 | 회차 준비·오픈 |
| 일반 신청 중 | 참석·불참 응답과 변경. 상한 도달 후 새 참석은 후보 신청 | 명단 확인, 대리 신청, 편성 초안 |
| 일반 신청 마감·후보 접수 | 기존 참석을 불참으로 변경 불가. 새 참석 의사는 ‘후보 신청’ | 후보 확인·배정, 전체 소속 회원 검색·대리 신청, 필요 시 취소 정정 |
| 전체 접수 종료 | 새 신청·직접 변경 불가 | 최종 편성·필요한 정정 |
| 회차 취소·종료 | 신청 불가 | 취소 사유·지난 기록 관리 |

마감 전에 불참 또는 미응답이었던 회원도 마감 후 후보로 참석 의사를 낼 수 있다. 이미 일반 신청 또는 후보 기록이 있으면 새 기록을 만들지 않는다.

마감 이후 불참 변경 금지는 후보의 철회에도 동일하게 적용하는 것을 제안한다. 실제 불참 연락은 운영진이 정정할 수 있어야 하므로 마감 후 화면에 짧게 ‘변경은 회장에게 연락’ 경로를 제공한다. 정정 시 처리자·시각·변경 전후를 보존한다.

확정: 후보 접수는 해당 회차의 운동 시작 전까지 열어 두고 시작 시 자동 종료한다. 후보 신청은 회원의 선택 사항이다. 회차 취소는 별도로 접수를 종료한다.

일반 신청 마감 시각은 서버 기준으로 판정한다. 마감 직전 열린 화면에서 늦게 제출해도 후보로 접수되며, 결과 화면에서 실제 접수 상태를 알린다.

상한 도달은 신청 마감 시각과 별개다. 상한 때문에 일찍 후보가 되었더라도 마감 시각 전에는 기존 응답 변경 규칙을 적용하고, 마감 이후에는 불참으로 직접 변경할 수 없게 하는 것을 제안한다.

### 운영진 대리 신청

마스터·회장만 팀 편성 화면에서 ‘회원 찾아 추가’를 사용한다. 추가 운영진은 대리 신청할 수 없다. 해당 모임의 모든 등록 회원을 검색하고, 참석 연락을 받은 사람을 선택해 대리 신청·팀 배정을 수행할 수 있다. 기존 불참 응답을 바꾸는 경우 기존 상태가 보이게 하고 변경 이력을 남긴다. 참가 의사를 확인하지 않은 전체 회원을 일괄 참석 처리하지 않는다.

일반 신청 기간이고 상한에 여유가 있으면 일반 접수, 상한 도달 또는 마감 후에는 후보 접수로 기록한다. 후보라도 운영진은 바로 팀에 넣을 수 있다. 최초 입력 경로와 접수 구분은 팀에 넣었다는 이유로 사라지지 않는다.

마감 후 일반 접수가 금지되어도 운영진의 대리 추가·임시 게스트 추가·수동 배정은 가능하다. 기존 참가 기록이 있으면 이를 사용하며 동일 회원을 중복 생성·집계하지 않는다.

## 6. 인원 참고 표시와 선택적 신청 상한

### 비판적 검토

18·21·24·28은 자주 쓰는 팀 구성의 인원 기준이다. 이 숫자가 찼다고 포지션 균형이나 모든 신청자의 배정이 보장되지는 않는다. 신입·후보·운영진 대리 추가·게스트에 따라 실제 편성 대상도 달라질 수 있다.

‘18+2’를 주표시로 쓰면 앞의 18명은 확정이고 뒤의 2명은 탈락 대상으로 읽힐 수 있다. 숫자는 인원 구성 참고로만 사용하고 사람의 신청 순번과 연결하지 않는 것을 제안한다.

### 회원 화면 제안

- 현재 일반 신청 수를 가장 크게 표시한다: **신청 20명**.
- 아래에 작은 숫자 눈금 **18 · 21 · 24 · 28**을 배치한다. 지난 기준점과 다음 기준점을 차분한 강조색·굵기로만 구분한다.
- 필요하면 작은 보조 문구 ‘21명 기준까지 1명’ 또는 ‘18 + 2’를 사용하되 주표시로 쓰지 않는다. 기본안은 숫자 눈금과 ‘인원 구성 참고’라는 짧은 설명이다.
- ‘편성 가능’, ‘2명 제외’, ‘참가 확정’, 경고 아이콘·빨간 부족 표시·성공 배지는 사용하지 않는다.
- 색만으로 정보를 전달하지 않고 실제 숫자와 작은 설명을 함께 둔다. 모든 기준점 도달은 참고이지 참가 승인 조건이 아니다.
- 18명 미만·28명 초과도 그대로 실제 인원을 보여준다. 28을 암묵적 상한으로 만들지 않는다.

집계 제안: 일반 신청과 후보를 따로 센다. 일반 신청 20명, 후보 2명인 경우 ‘신청 20명 · 후보 2명’으로 표시하고 기준 눈금은 일반 신청 20명에 적용한다. 운영진은 여기에 임시 게스트·직접 추가 인원·배정 수를 함께 확인한다. 회원에게 숫자만 공개하며 분류별 이름은 공개 정책을 따른다.

예: 일반 신청 20명(신입 포함) + 후보 2명 + 임시 게스트 2명 = 회차에 추가된 참석 의사 인원 24명. 모든 소속 회원이 검색 가능하더라도 그 전체 회원 수를 24명에 더하지 않는다. 직접 추가 회원은 일반/후보 중 하나로 이미 집계되므로 별도로 중복 합산하지 않는다.

### 선택적 상한 — 상한 이후 후보 접수 확정

상한과 인원 눈금은 목적이 다르므로 독립된 설정으로 제안한다. 기본은 상한 없음, 참고 눈금 사용이다. 회차별로 상한을 켤 수 있고, 눈금은 접수 정책을 바꾸지 않는다.

상한은 ‘일반 신청 접수 인원’에 적용하고, 도달 이후 새 참석 의사는 후보로 받는다. 일반 신청이 팀 배정을 보장하지 않는다는 원칙을 유지한다. 마감 후 후보 접수와 동일한 참가 상태 구조를 사용한다.

집계 제안: 일반 신청 중인 정규·신입 회원과 일반 접수된 대리 신청 회원을 센다. 후보·임시 게스트는 일반 신청 상한에 포함하지 않는다. 이는 실제 경기 참가자 총원의 제한이 아니므로 운영진은 후보·게스트도 배정할 수 있다.

예: 상한 24명에 일반 신청 24명이면 다음 사람에게 ‘후보 신청’ 버튼을 제공한다. 일반 신청 마감 시각이 지나면 상한 미달이어도 새 신청은 후보가 된다. 전체 접수 종료·회차 취소·종료가 가장 우선하며 이때는 후보도 받지 않는다.

세부 규칙 제안: 일반 신청 자리 취소로 빈자리가 나도 기존 후보를 자동 승급하지 않고 운영진이 결정한다. 상한 변경으로 기존 신청을 자동 취소하지 않는다. 일반 신청 처리 시에는 동시 접수에도 상한을 넘기지 않도록 판정한다. 운영진은 일반 상한을 넘겨도 후보로 대리 추가·편성할 수 있다. 상한 변경이나 자리 발생이 팀 배정의 우선순위를 만들지는 않는다.

공개 명단은 신청 순번·시각을 유추하기 어렵게 이름순 또는 팀순으로 정렬하고 신청 순서 정렬을 제공하지 않는다. 내부 실력 정보는 이름 카드뿐 아니라 팀 합계 점수·분포, 데이터 응답에도 넣지 않는다.

공개 시점은 운영진이 ‘공개’를 누른 때다. 초안 저장·일반 신청 마감만으로 명단을 열지 않는다. 공개 후 들어온 새 후보나 내부 변경을 즉시 실명으로 노출하면 검토 중인 명단이 공개되므로, 명단·팀 결과는 마지막 공개본을 기준으로 보여주는 것을 제안한다. 새 후보는 운영진이 확인하고 재공개할 때 반영한다. 신청 수와 본인 상태는 현재 값이므로, 공개본에는 갱신 시각을 표시한다.

팀 미배정자를 제외·불참으로 표시하지 않는다. 전체 공개 신청 명단에는 포함할 수 있으나 신입 분류·내부 미배정 사유는 기본 비공개로 제안한다. 댓글 등 회원이 직접 올리는 정보와 신청 데이터의 공개는 별개다.

| 회차 참가 목록 | 일반 신청 / 후보 / 임시 게스트 탭, 회원 유형·신청 시각·입력 경로·포지션·실력 필터 |

신입과 임시 게스트는 모임에 나오는 인원이므로 팀 편성 화면의 ‘함께 참여하는 인원’에 기본 표시한다. 정규팀 미배정을 불참·제외로 표현하지 않는다. 마스터·회장은 필요하면 선택적으로 팀에 배정할 수 있다. 추가 운영진에게는 이 예외 배정 권한을 주지 않는다. 모든 소속 회원이 검색 가능하다는 것은 모두를 무작위 배치 대상으로 삼는다는 뜻이 아니다.

초기 ‘팀 틀 만들기’는 3팀 × 6명 / 3팀 × 7명 / 4팀 × 6명 / 4팀 × 7명을 제공하고 자동으로 사람을 채우지 않는다. 수·목표 인원은 변경 가능하며 불균등한 팀도 저장할 수 있다. 게스트와 회원 모두 한 회차에서 여러 팀에 중복 배정되지 않게 한다.

모바일에서는 드래그 외에 참가자 선택 → 팀 선택으로 배정한다. 프로필 주·부 포지션과 회차 배정 포지션은 분리한다. 포지션 부족·실력 차이는 참고 정보이며 수동 편성을 강제로 막지 않는다.

## 9. 후속 기능: 포지션·실력 기반 빠른 배치

### 확정된 포지션·교대 방식

운영진이 정한 참가자들을 포지션과 운영진 평가를 참고하여 무작위 배치하고, 이후 직접 수정하는 보조 도구다. 이 모임에서는 센터·레프트·라이트 각 2자리 중 센터 또는 라이트 한 자리를 세터가 맡는다. 세터를 추가해 7명이 되는 것이 아니라 해당 자리의 선수를 세터로 대체하여 6명을 구성한다.

| 세터가 맡는 자리 | 세터 | 센터 | 레프트 | 라이트 | 합계 |
| --- | --- | --- | --- | --- | --- |
| 라이트 자리 — 기본 | 1 | 2 | 2 | 1 | 6 |
| 센터 자리 — 선택 | 1 | 1 | 2 | 2 | 6 |

‘세터 역할’과 ‘세터가 맡는 자리’를 구분한다. 세터가 라이트 자리에 배치되어도 회원 프로필을 라이트로 바꾸지 않는다. 회차 기록에도 역할=세터, 자리=라이트 또는 센터를 구분하여 저장하는 것을 제안한다. ‘세터(라이트 자리)’와 같은 표기를 사용하고, 이를 세터·오포짓의 대각 관계로 해석하지 않는다. 리베로 자리는 생성하지 않는다.

7명 팀은 7명 모두 같은 팀 소속이며 매번 6명이 플레이하고 1명씩 돌아가며 빠진다. 고정된 한 사람을 상시 벤치 선수로 분류하지 않는다. 추가 인원은 특정 포지션에 중복될 수 있으므로 센터·레프트 등이 3명 또는 세터·라이트 등이 2명이어도 허용한다.

제안: 빠른 배치는 6명 기본 구성을 참고하여 팀원을 분산한 뒤 일곱 번째 인원까지 팀에 배정한다. 7명 팀에는 정확한 포지션별 정원 검사를 강제하지 않는다. 팀 카드에는 7명 전원을 동등하게 표시하고 ‘6명 플레이 · 1명 순환 휴식’을 안내한다. 확정: 교대 순서는 현장에서 정한다. 웹에서 휴식 순서·출전 6명 자동 계산을 구현하지 않는다. 팀 명단만으로 모든 교대 상황의 세터 유무·포지션 균형이 보장된다고 표시하지 않는다.

### 추천 설계

1. 운영진이 팀 수·6명/7명 구성, 세터가 맡을 자리(라이트/센터), 배치할 인원을 선택한다. 일반 신청·후보·임시 게스트 중에서 고르고, 신입은 명시적으로 선택한다. 미응답·불참 회원은 참석 의사를 확인해 대리 추가한 뒤 포함한다.
2. 이미 정한 선수의 팀·포지션을 고정할 수 있다. 고정 선수는 재추첨에서도 이동하지 않는다.
3. 세터를 먼저 분산하고 선택한 센터/라이트 자리 한 칸을 사용한 것으로 계산한다. 줄어든 해당 포지션 인원에 맞춰 나머지를 채우며 포지션 적합도와 팀 간 실력 차이를 함께 검토한다. 7명 팀은 추가 인원을 포함해 균형을 검토하되 포지션 중복을 허용한다.
4. 가능한 여러 배치안을 만든 뒤 포지션 충족·균형이 나은 안들 중 무작위로 제시한다. 완전 무작위에 점수를 표시하는 것과 구분한다.
5. 주 포지션 우선, 부 포지션 대체를 허용한다. 미평가를 0점으로 계산하지 않고 불확실한 정보로 표시한다.
6. 특정 포지션 선수가 부족하면 부족한 자리·대체안을 운영진에게 보여준다. 같은 선수를 복제하거나 임의로 참석자를 늘리거나 선정하지 않은 회원을 끌어오지 않는다.
7. 제안 결과를 검토·수정한 후 운영진이 적용한다. 기존 편성을 자동 덮어쓰거나 자동 공개하지 않는다. 다시 뽑기·이전 안 복구를 제공하는 것을 제안한다.

‘포지션별 실력 점수’와 ‘개인 전체 실력 등급’은 다르다. 초기 수동 편성은 전체 5단계 등급을 사용하고, 빠른 배치 도입 시 주·부 포지션별 평가를 추가할지 확인한다. 같은 점수라도 어느 포지션을 맡는지에 따라 전력이 다르므로, 단순 팀 총점만으로 균형이 보장된다고 표시하지 않는다.

현재 평가는 운영진이 직접 단계로 입력하는 방식이다. 향후 객관적인 평가 지표와 평가 절차를 연구한다. 같은 포지션 선수끼리 두 명씩 비교하는 투표·토너먼트는 아이디어로 보존하되 당장 구현하거나 회원에게 평가 정보를 공개하지 않는다. 인기·친분, 대진·참여 수에 따른 편향 때문에 토너먼트 승패를 객관적 실력으로 단정하지 않는다. 후속 검토에서는 반복 비교, 관찰 항목, 평가자 범위와 결과 비공개 정책을 함께 검토한다.

## 10. 화면·커뮤니티와 기록

회원 화면은 홈 / 운동 / 소식 / 내 정보로 구성한다. 홈은 현재 모집 회차·인원 참고 표시·본인 상태·중요 공지·공개 이후 내 팀을 보여준다. 운동에는 목록·달력·회차 상세·후보 신청·공개 결과를 제공한다.

공지·이벤트·자유게시판은 스레드와 댓글을 기본으로 하고 중요 표시·고정을 지원한다. 회차별 댓글도 제안한다. 별도 이벤트 참가·참여 집계, 개인 상세 통계는 후속 단계로 둔다. 게시물 역시 모임별로 구분한다.

처음부터 저장할 데이터:

| 기록 | 내용 |
| --- | --- |
| 모임·소속 | 모임 식별자, 회원 소속, 회장·운영진 역할과 변경 |
| 신청 | 회차·회원, 참석 의사, 일반/후보 구분, 입력 경로, 처리자·접수·변경 시각 |
| 임시 게스트 | 회차·참가자 식별자, 표시 이름, 선택 정보 |
| 편성 공개본 | 당시 참가자 이름·회원 연결·분류, 팀·배정 역할·자리, 6명/7명 구성, 공개 시각·수정 기록 |
| 실제 출석·이벤트 | 후속 입력 기능에서 수집. 신청이나 배정을 출석으로 추정하지 않음 |

회원 프로필·신입 분류를 바꾸어도 과거 공개 기록을 덮어쓰지 않는다. 임시 게스트는 회차 기록에만 남기며 동명 게스트끼리 연결하거나 회원 통계에 합치지 않는다.

포지션 횟수는 우선 회차 최종 배정 역할 기준 집계를 제안한다. 라이트 자리를 맡은 세터는 세터 배정으로 집계하며 라이트까지 중복 계산하지 않는다. 재공개 횟수도 참가 횟수로 중복 계산하지 않는다. 실제 경기별 수행 횟수와 순환 휴식 횟수가 필요하면 경기·교대 기록이 별도로 필요하다. 기록 기능 도입 이전 실제 출석은 ‘미기록’으로 둔다.

다음 회차 복사 시 장소·시간·안내·모집 기본 설정만 복사하고 날짜·마감 시각·상한을 확인한다. 신청·후보·대리 추가·게스트·팀 배정은 복사하지 않는다.

## 11. 개발 순서와 검증 기준

### 1차: 한 모임의 핵심 기능

모임 소속·권한 구조를 준비하고 샘플 회원·마스터 테스트 역할로 모집, 선택적 상한과 초과 후보 접수, 인원 표시, 마감 후 후보, 운영진 대리 신청, 임시 게스트, 수동 팀 편성·공개, 공지·게시판을 검증한다. 수동 편성에서도 세터가 맡는 자리와 7명 순환 교대 팀을 표현한다. 계정 생성·복구 화면보다 운동 운영 기능을 먼저 만든다.

### 2차: 계정과 모임 운영 연결

마스터의 모임 생성·회장 지정, 회장의 장소·일정 설정, 회원 계정 발급·로그인·중지·복구, 신입 분류·승급과 실제 권한 검증을 구현한다. 초기 데이터는 모임 하나지만 두 모임 데이터로 격리도 검증한다. 마스터가 회장 역할을 겸하는 경로와 실제 회장에게 넘기는 경로를 모두 지원한다. 이 단계 이후 실제 회원 대상 운영을 시작한다.

계정은 운영자가 발급하며 공개 회원가입은 제공하지 않는다. 임시 비밀번호 발급 후 첫 변경을 제안하며 사용 중인 비밀번호를 운영자가 조회하는 기능은 두지 않는다.

### 3차: 편성 보조와 개인 기록

확정된 포지션 구성을 바탕으로 빠른 배치, 포지션별 평가, 실제 출석, 개인별 포지션·팀 이력, 이벤트 참여 기록을 추가한다. 교대 순서 관리는 개발 범위에서 제외한다. 여러 모임을 실제로 확대하는 시점은 한 모임의 운영 검증 후 결정한다.

### 핵심 검증 사례

- 신청 순번·시각, 불참·미응답 명단, 실력·주·부 포지션 프로필은 공개 이후에도 회원 데이터에 포함되지 않는다.
- 공개 명단이 신청 순서로 정렬되거나 팀 점수로 내부 평가를 노출하지 않는다.
- 일반 신청 마감 후 회원은 불참으로 변경할 수 없고, 미응답·불참이었던 회원은 후보 신청할 수 있다.
- 같은 회원이 후보 버튼을 반복하거나 운영진이 대리 추가해도 참가 기록과 인원이 중복되지 않는다.
- 운영진은 미신청 회원도 해당 모임에서 검색해 대리 신청·배정하며 처리 이력이 남는다.
- 검색 가능한 전체 회원이 참석자 수나 무작위 배치 대상에 자동 포함되지 않는다.
- 후보 접수 종료·회차 종료·취소 이후 회원의 새 후보 신청을 받지 않는다.
- 신청 20명에서 18·21 기준 표시는 참고만 제공하고 특정 두 사람의 배제나 확정 참가를 나타내지 않는다.
- 신청 수·후보 수·게스트 수·배정 수가 구분되고 대리 신청자를 중복 합산하지 않는다.
- 상한 미사용 시 28명 초과도 신청 가능하고, 상한 도달 후 새 신청은 후보로 받는다. 마감 이후에는 상한 미달이어도 후보가 된다.
- 일반 상한의 마지막 한 자리에 동시 접수해도 일반 신청 수가 초과되지 않고 나머지는 후보로 기록된다.
- 신입의 직접 팀 배정이 자동 승급을 일으키지 않는다.
- 게스트는 계정 없이 생성·편성되고 다음 회차에는 복사되지 않으며 지난 공개 기록에는 남는다.
- 편성 초안 저장·마감은 명단을 공개하지 않고, 공개 후 추가 후보 실명도 다음 공개본 전까지 노출하지 않는다.
- 한 회차에서 동일 참가자가 여러 팀에 중복 배정되지 않는다.
- 마스터만 모임 생성·회장 연결을 수행하며 회장은 자기 모임 설정만 변경한다. 교체된 회장에게 이전 권한이 남지 않는다.
- 모임 A 운영진이 모임 B 회원·평가·신청·게시물에 접근하거나 편성에 넣을 수 없다.
- 후속 빠른 배치에서 고정 선수 유지, 인원 중복·누락 방지, 포지션 부족 처리, 미평가 처리, 자동 공개 방지를 검증한다.
- 라이트 자리 세터 구성은 S1·MB2·OH2·OP1, 센터 자리 세터 구성은 S1·MB1·OH2·OP2로 각각 6명이며 리베로를 생성하지 않는다.
- 세터 배치 자리를 바꾸어도 프로필은 세터로 유지되고 회차 역할·자리 기록이 구분된다.
- 7명 팀은 전원 배정되고 포지션 중복을 허용하며 특정 한 사람을 고정 교대 선수로 지정하지 않는다.

## 12. 질문과 다음 작업

이번 답변으로 확정된 사항:

1. 신청 상한 이후에도 후보 신청을 허용한다.
2. 세터가 센터 또는 라이트 자리 하나를 맡고 해당 포지션 선수 수를 1명 줄인다. 리베로는 없다.
3. 7명 팀은 6명 플레이·1명 순환 휴식이며 특정 포지션 인원 중복을 허용한다.

후속 화면 설계 또는 해당 기능 개발 직전에 확인할 사항:

- 후속 평가 연구에서 사용할 관찰 항목·평가자 범위. 현재는 운영진 단계 평가, 교대 순서는 현장 결정으로 확정.
- 상한의 집계 대상과 마감 후 후보 철회 처리의 화면 표현.
- 공개 후 신입·게스트 표기와 미배정자의 표현, 회차 배정 포지션 공개 범위.
- 비활성 회원의 검색·대리 신청 처리. 추가 운영진 지정은 마스터만, 대리 신청은 마스터·회장만 가능으로 확정.
- 실력 단계의 명칭·설명. 실제 운동 날짜·시간·위치는 모임 등록 시 입력하고 회차 기본값으로 사용한다.

다음 단계는 ‘신청 20명’의 조용한 인원 표시와 상한 도달·마감 후 후보 신청 화면, 운영진의 일반·후보·전체 회원 검색·임시 게스트를 연결하는 편성 화면을 구체화하는 것이다. 상한 이후 동작과 6명/7명 팀 구성은 확정되었으며, 남은 세부 선택은 화면 설계와 해당 기능 개발 과정에서 정한다.

## 13. 첫 구현 범위와 확인 상태

2026-09-22 사용자 확인: 대리 신청은 마스터·회장만 가능하며 추가 운영진은 불가. 신입·임시 게스트의 선택적 정규팀 배정 예외도 마스터·회장에게 유지한다. 개발을 막는 질문은 해소되었다.

첫 구현은 별도 `web/` 프로젝트에서 샘플 모임·회원으로 시작한다. 회원·마스터·회장·추가 운영진의 화면 체험을 제공하되 실제 로그인·계정 권한을 구현한 것으로 보지 않는다. 회차·신청·후보·편성·공개·공지·댓글은 서버에 저장하고, 계정 발급 및 다중 모임 등록은 후속 단계에서 연결한다. 날짜·위치는 샘플 값이며 실제 모임 정보를 추정하지 않는다.
