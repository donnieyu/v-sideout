# SIDEOUT 디자인 기준

현행 기준: 2026-10-12. 사용자의 마지막 승인과 현재 앱을 기준으로 한다. 승인 과정의 이전 배치는 [보존 이력](../docs/reviews/main-preparation-20261012/design-before.md)이며 현행 요구사항으로 적용하지 않는다. 통합/검증/실기기 상태는 [메인 통합 준비](../docs/reviews/main-preparation-20261012/REPORT.md)를 따른다.

## 공통 시각 체계

- 배경 #f5f6f8, 흰 표면, 본문 #243544, 보조 정보 #697b8b, 주요 행동 #284b6b. 상태는 접수 연한 파랑, 신청 완료·공개 연한 초록, 대기 연한 황토색 배지로 표시한다. 색 외에 상태 문구도 유지한다.
- 모임은 작은 단색 이니셜과 카드 상단 2px 선으로 구분한다. 청록 #557d77, 히어로즈 회갈색 #76736e 등 안정된 모임 ID 기반 표현을 사용한다. 로고 업로드는 향후 별도 기능이다.
- 선택 필터만 남색, 미선택은 흰색이다. 제목 16–18px/600, 본문·이름 13–15px/400–500, 보조 정보 11–13px. 조작 영역은 최소 44px, 긴 이름·소속·공지에는 줄바꿈을 허용한다.
- 모바일 헤더는 왼쪽 SIDEOUT, 오른쪽 메뉴로 고정한다. 페이지 제목은 본문에 둔다. 메뉴는 하단 시트, PC는 사이드바를 유지한다. 하단 메뉴 버튼을 다시 추가하지 않는다.

## 일정 홈

- 모임 필터 → 주 이동·압축된 날짜 요약 → 날짜별 일정 순서. 헤더·필터·날짜는 고정하고 카드 목록만 내부 스크롤한다. 날짜는 카드 밖에서 같은 날짜의 운동을 묶는다.
- 주·필터 변경은 목록 맨 위, 상세 왕복은 회원·주·필터별 위치 복원, 자동 갱신은 현재 위치 유지가 원칙이다.
- 카드 순서: 상태/마감 → 모임/운동 공지 → 장소 → 입장·시작·종료 → 명단 확인/인원 바 → 신청·취소 또는 공개 팀 조회 → 운영진 일정 관리.
- 신청과 취소는 같은 위치. 공개 열람 권한이 있을 때 팀편성·경기 순서 조회를 제공한다. 권한 없는 미공개 정보를 예시 선수로 채우지 않는다.
- ‘명단 확인’은 공개 전후 동일한 문구다. 인원 바는 18/21/24/28 단계의 다음 기준까지 차오르며 단계 숫자를 장식으로 나열하지 않는다. 신청 정원과 권한은 서버 기준이다.

## 일정 등록·상세·수정

- 새 ‘모임 등록’과 ‘이어서 준비’ 모두 운동 상세부터 시작한다. 신규는 모임 기본 정보, 저장된 준비 일정은 저장값을 보여준다. 신규 화면 진입만으로 생성하지 않는다.
- 상세에 ‘모집 준비 중’과 회원 미공개 상태를 표시한다. 정보 확인 → 필요 시 수정/저장 → 상세에서 모집 시작 순서다.
- 조회와 수정은 장소·시간 / 신청 정보 / 운동 공지의 동일한 순서와 단일 카드 구조를 공유한다. 수정 진입은 카드의 버튼 하나다. 정보/공지 탭과 요약 변경 펼침은 사용하지 않는다.
- 일정 정보 수정 화면의 작업은 ‘저장’ 하나다. 저장은 기존 준비/모집 상태를 유지하고 편집 화면에 머문다. 모집 시작 버튼은 운동 상세에만 둔다.
- 모집 시작은 앱 확인창에서 제목 ‘모집을 시작할까요?’, 안내 ‘회원들에게 일정이 공개되며, 참석 신청을 받을 수 있습니다.’, 취소/확인 순서다. 확인 후에만 실행한다.
- 신청 마감은 정확한 한국 날짜·시각과 D-N/오늘 마감/신청 마감으로 표시한다. D-N은 한국 달력 날짜 기준. 팀 공개 시 접수 종료가 우선한다.
- 등록/일정 수정은 제목 고정과 내부 본문 스크롤을 사용한다. 날짜·시간 입력과 카드의 너비는 작은 화면 안에 수축할 수 있어야 한다.
- 일반 회원의 공개 팀 조회에는 필요한 장소·시간·공지를 표시하고 관리용 신청 설정은 생략한다.

## 명단·운동 공지

- 명단은 신청자·대기자 탭, 소속 회원·게스트 그룹과 기존 열람 권한을 유지한다. 취소 후에도 명단 창을 열어 두어 연속 처리한다.
- 홈의 운동 공지 모달은 저장된 자유 문장 공지만 표시한다. 상세에서는 같은 공지를 본문에 3줄로 표시하고 실제 넘침일 때만 펼친다. 없는 준비물/체육관 규칙을 생성하지 않는다.
- 공지가 없으면 일반 회원용 영역을 숨기고, 수정 권한이 있는 운영진은 추가/수정으로 들어간다. 공지 진입은 같은 일정 수정 폼의 공지 영역으로 연결한다.
- 명단·공지 모달은 모바일 높이를 활용하고 제목/하단 조작을 유지한 채 내용만 스크롤한다.

## 팀편성·경기 순서

- 코트/행이 같은 편집 원본과 선수 선택 다이얼로그를 공유한다. 별도 배정/미리보기 페이지는 사용하지 않는다. 보기 전환 시 맨 위로 이동한다.
- 코트는 팀별 카드와 추가 인원 영역, 행은 전체 팀·포지션 표다. 추가 선수 줄은 모든 팀에 함께 생성·삭제한다. 코트 팀 추가는 목록 끝에 둔다.
- 선수 선택/교체 후 모달을 닫고 최근 타일을 강조한다. 해제 후에는 선택 모달과 현재 선수 영역의 빈 타일을 유지한다. 후보가 모두 배정되면 신청자 탭의 완료 안내에서 미신청 목록으로 명시적으로 진입한다.
- 기본 포지션 우선 자동 배치, 남은 인원 추가 자리, 미배정 사유와 이유 보기 경고, 확인 후 배정 초기화를 유지한다. 자동 배치가 언제나 모든 인원을 배치한다는 표현은 하지 않는다.
- 저장 후 편집 유지. 공개 중 읽기 전용·빈자리 숨김, 수정은 공개 취소 후 가능하다. 공개·공개 취소·팀/추가 줄 삭제의 확인과 서버 권한을 유지한다.
- 팀 이름 수정은 현재 행 헤더에서 제공한다. 코트 이름 수정 진입과 팀 열 순서 DnD는 후속 검토이며 구현 완료로 표시하지 않는다.
- 경기 순서는 팀 목록 아래 이어지며 별도 바로가기 버튼을 두지 않는다. 경기 편집은 저장만 제공한다. 같은 팀 ID 구성일 때 공개된 경기 순서도 저장 즉시 갱신하는 서버 규칙을 유지한다.

## 하단 플로팅과 편집 보호

- 모바일은 목적지 복귀와 작업 버튼을 하단에 개별 둥근 버튼으로 모은다. PC는 기존 본문 복귀와 상단 작업 그룹이다. 모바일 버튼은 44px 높이, 13px/400 글자, 24px 모서리, 콘텐츠에 맞춘 폭이다.
- 일정/경기 수정: 돌아가기·저장. 팀 편집: 돌아가기·저장·공개/다시 공개. 공개 중: 돌아가기·공개 취소. 모집 준비 상세: 돌아가기·모집 시작.
- 불투명한 바탕 바 없이 본문 위에 띄운다. 공통 페이드는 배경색 0%→42%→82%이며 단독 ‘운동 일정으로’도 동일하다. 페이드는 터치를 가로채지 않고 PC에는 적용하지 않는다.
- 마지막 내용 가림 방지 여백은 스크롤 내용 끝에 둔다. 단순 입력 포커스가 아닌 실제 키보드 높이 변화에 따라 키보드 닫기·저장을 표시한다. 모달/경기 드래그 중 배경 버튼을 숨기고 저장 중 이동을 차단한다.
- 참석/대기 취소, 명단 삭제, 즐겨찾기 변경 폐기, 최신 정보 불러오기, 미저장 화면 이동은 앱 공통 다이얼로그를 사용한다. 취소는 작업하지 않고 기존 입력/부모 창을 유지한다. 중복 확인 요청과 계정 해제 후 지연 작업을 막는다.
- 모달의 키보드 트랩·Escape·초점 복귀를 유지한다. 브라우저 새로고침/탭 닫기 등 beforeunload 경고는 브라우저 통제이므로 데이터 보호를 위해 유지한다.
- 같은 문서의 해시 이동은 편집 이탈로 취급하지 않는다. 명단 복원 키는 화면별로 구분하고 동일 화면에 중복 명단 창을 만들지 않는다.

## 검증과 미완료의 경계

- 이전에 사용자가 확인한 내부 스크롤·선수 선택·경기 드래그·공개 취소/재공개는 인수 완료다.
- 최신 iPhone Safari 변경은 2026-10-12 사용자가 실기기 정상 동작을 확인하여 이번 단계 인수를 완료했다. 자동 WebKit 결과와 사용자 인수 근거를 구분한다. 전체 접근성/스크린리더까지 확인했다는 뜻은 아니다.
- 가입/승인·회원 포지션 입력 인수, 전체 접근성, 운영 DB 업그레이드/백업·복구, 로고/게시판/팀 순서 DnD는 별도 범위다.
- [현행 검증·통합 후보](../docs/reviews/main-preparation-20261012/REPORT.md), [공통 확인창](../docs/reviews/common-confirm-dialogs-20261012/REPORT.md), [수정 저장 전용](../docs/reviews/schedule-save-only-20261012/REPORT.md), [승인 홈 비교](../docs/design-review/schedule-home-concepts-20261009/IMPLEMENTATION.md).

## 1차 완료 기준점 — 2026-10-12

사용자 실기기 확인과 선택 커밋·최종 리뷰·메인 통합 승인에 따라 이번 단계의 기준점을 남긴다. 제품 전체의 디자인/기능 검토 종료를 뜻하지 않으며 이후 변경 요청을 계속 반영한다. 범위·리뷰·통합 결과는 [1차 완료 기록](../docs/reviews/first-completion-20261012/REPORT.md)을 따른다.
